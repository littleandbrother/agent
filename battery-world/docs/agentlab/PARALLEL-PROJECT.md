# 页面内三个任务共同完善基座

用户澄清后的目标是在现有任务页面同时运行三个 Pi 会话，并让任务暴露的实际问题推动公共平台改进。
不是由三个 Codex 子代理分别建立实验系统，也不是规划者、执行者、验收者三种角色。

| 页面任务 | 研究对象 | 首轮交付 |
| --- | --- | --- |
| A · 产品综合 | 采能机械故障诊断节点 | 场景与服务承诺、现有适用基准反馈、设计修改范围记录 |
| B · 判断协调 | 无电池太阳能桌面陪伴产品 | 计算基线、纯展示与服务条件变更、判断适用性记录 |
| C · 方法演化 | PV 物流记录器 | 有范围的候选规则程序、公开开发用例、保留与限域行为比较 |

上述交付是各任务的首轮工作委托；是否完成以实际会话、文件和核对回执为准。
它们不是三篇论文已完成的声明，也不将开发用例称为未来盲测或实物验收。

## 页面与共享范围

三条会话位于「BF-AIoT 三任务共建」文件夹。每条会话有独立 Pi 进程、工作区、方案、事件流、账本身份和执行时限。
切换页面会话不会停止其他任务；侧栏圆点和文件夹运行计数投影实际状态。
进入控制台后仍沿用所选会话，工具、Skills、MCP 事件继续进入现有 Trace。
全景可查看并发模块和实际代码变化，不将一次工作区改动自动归因给某个任务。

文件夹共享工具与 Harness 选择、公共提示词和版本化 Memory。
Memory 只保存跨任务可用的能力事实与待验证需求，不共享某个产品的默认工况。
写入使用 expected_revision：冲突写入被拒绝，任务必须重新读取并合并，不能静默覆盖其他任务笔记。
各会话另写 platform-needs.json，记录能力名称、观察证据、影响和建议。平台开发者复核这些缺口后修改共用代码。
参与任务的 Pi 保持原有工作区写权限，不直接修改生产平台、评估器或预算。

## 并发实现

此前所有会话竞争 pi-session.lock 的独占锁，导致后来的任务被拦截。
现在交互会话共享该锁，另外持有会话独占锁及最多三个进程槽位。原来的独占批量实验保持排他关系。
同一个会话不能重复启动；第四个会话保存消息并明确显示容量限制。当前不会在空闲后自动重发，需要用户继续操作。
Harness 冻结构建有独立文件锁，避免三个会话同时首次构建相同版本时读取到未完成的清单。
每条消息继续使用现有 600 秒时限。Provider 的预算预留仍在 SQLite BEGIN IMMEDIATE 事务中完成，三个任务共用同一总限额。

首轮使用既有总上限 USD 3.9279102、单次请求上限 USD 0.19。初始每条会话 USD 0.05 分配因保守请求预留过紧而暂停，核账后在原有总额度内重分配为三条合计最多 USD 0.45。最后分配 A/B/C 分别为 USD 0.15/0.18/0.12，均包含已有用量；B 最后的 USD 0.03 来自 C 未用分配。总上限、单次上限、累计 token 和用量记录均未重置。

## 验收

新增本地测试启动三个真实 Pi 进程，以无付费替代模型流同时阻塞/释放，核对进程重叠、消息分离、共享文件夹、流式事件和独立结束。
另核对同会话/第四槽/旧批次互斥、共享 Memory 版本冲突，以及三路模型请求竞争同一小额预算时只有额度允许的请求获得预留。
真实模型首轮的运行状态、产物、成本及后续问题在 PARALLEL-PROJECT.json 中记录。

本文不改变既有科学环境与 B2 gate。计算示例、程序行为测试、平台接口验证和实体产品验收分别记账。

## 由真实任务反馈完成的公共修复

1. 三条会话的旧全局独占锁改为共享批次锁、独立会话锁和三个槽位；同会话和批次实验仍互斥。
2. Harness 首次冻结/构建加锁，避免并发读取半写入产物。
3. C 的一次模型返回明确 usage，但 completion_tokens=4097 超过请求的4096。原实现先拒绝输出，再把已知用量误记 UNKNOWN，导致 B 被全局暂停。现在先记录准确计费，再保留输出错误；未知用量仍然停止后续请求，真实费用超过预留也仍全局停止。
4. C 历史这一笔仅根据已保存 SDK usage、请求时间/身份与本机映射代码核对为 SETTLED，保留原始错误与审计回执。没有重放请求，没有伪造缺失的原始 HTTP response hash。

负对照涵盖第四会话、同一会话重复启动、旧批次排他、共享 Memory 过期版本、三路预算竞争、已知超限输出与真正未知用量、费用超过预留后的停止。
本机 TLS 回归测试曾因3秒本地握手超时未收到 ClientHello，调整测试等待至10秒后仍严格检查握手记录和零应用写入；未改变生产传输超时。

## 第一轮研究任务的证据边界

- A 从一次 dev-01 过压 FAIL 出发，仅改 clamp_v=3.5，实际重跑 PASS 并提交绑定快照。它只证明固定 F1 条件下的局部修复，不证明实物、通用联合设计或新研究机制。
- B 生成自己的太阳能日预算与变更初筛。复核退回了“把纯展示误写成灯效耗能”“表格余量不一致”“串并联注释错误”“修稿引入储能窗口漂移”。最终程序和结果由独立临时目录重放核对。相机只是元数据控制，没有声称新 Blender/CAD 渲染；未计漏电、峰值、响应和实测。
- C 编写候选与固定对照，在公开开发用例上运行。复核纠正了固定对照永远 NO_EVENT、仅看 stage 却称来源校验，以及把既有 Harness 冻结机制误报不存在。最终5个开发用例、3个断言仍只是程序行为验证。输入缺失覆盖字段等进一步负例、独立未来任务和生产接入尚未通过，不采用该候选。

期间 A/B 曾输出“准备修改”后直接 stop，未实际执行工具。协调者根据文件证据追加指令后才继续。页面 IDLE 仅表示进程空闲，不能视为产品或研究完成。此处尚未加入自动追问/自动重试控制器；应先增加任务交付清单与产物新鲜度观察，再讨论控制策略。

## 共用基座下一批优先项

1. PV/超级电容日预算和时序供能能力：B、C 都缺适用的标准入口，先明确输入单位、初始条件、漏电与断电覆盖，不能套用旋转基准。
2. 产物完成与假设漂移检查：绑定任务要求、代码版本、输入假设、结果与最终答复；新增版本必须解释假设变化。保留当前任务页极简形式，将明细放控制台 Trace/验证。
3. 候选脚本到既有 Harness 冻结、回归和演化记录的接入：复用现有能力，先做观察与回放，不将开发用例结果自动晋升。
4. CAD/现场测量是单独的能力接入与物理证据工作，未安装或未测量时保持未验证状态。

三条页面任务会话、共享 Memory、独立工作区和 Trace 均持续保留，可在同一项目继续推进。完整账本、产物哈希、回放和状态见同目录 PARALLEL-PROJECT.json。
