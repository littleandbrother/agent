# BF 可执行无电池设备实验室：配置与 R0–R5 复核

本文件记录本次实际实现与检查。新 C 原生资格和公共环境发布已完成，原 Pi C 已完成本阶段交付，十篇论文正在沿原会话续跑。已有工程、十个原 Pi owner、全部旧费用与 UNKNOWN 保留；不把安装、文件完整、数字功能、硬件验证或方法改进合并为一个完成度。Git HEAD 为 `5e6e09f96c4fc47ca9dc6ab4c18a8e55ed8ffd6d`，本次实现包含尚未提交的工作树修改；各源码与回执摘要给出实际版本。

## 1. 实际运行结构

`battery-world` 是工程服务和独立检查器；`pi-bf-aiot` 是 BF/Pi 执行程序。结构、电路、固件、算法、硬件与场景由候选身份共同绑定。工具返回版本、文件、计算和检查事实，Pi 决定保留或修改设计、选择实验、处理反馈、采用和提交。Codex 本次修改公共实现、配置与检查器，没有改写十篇参与者工程。

源码：`packages/python/bfworld/src/bfworld/agentlab/design_lab/`。入口与重点函数：

| 模块 | 实际职责 |
|---|---|
| `builder.py: candidate/plan/verify_asset` | 七类输入身份、依赖传递、精确复用、单位/初态/适用域/校准状态与动作限制 |
| `coupled_c.py: environment/build/execute/evaluate` | C/H 与支持的 `device.json` 构建、实际程序—原生电源迭代、细步长复查、独立接收与结果绑定 |
| `native_solver.py: solve` | 隔离的新联合执行器；保留旧 D5 冻结实现与旧结果 |
| `native_witness.py: original/reuse/verify_archives` | 只在物理输入、求解内核和实际编译程序的完整电流/状态轨迹一致时复用原生证据 |
| `service.py: configure/task_version/run/adopt/submit` | 原 owner 的阶段恢复、旧任务归档、不可变操作、独立采用与同版本包 |
| `controller.py: start/freeze` | 当前 E/V 资格门、真实 Pi 运行、请求与版本记录 |
| `model_catalog.py: catalogue` | 现有 ROM、磁力资产及原厂模型来源清单；缺失模型明确列出 |
| `native_backends.py: inventory/probe_receipt` | 后端安装身份与独立 API 探测，不能据此授予产品资格 |

候选变更影响下游：程序或算法变化使目标构建、传感接口、联合执行、接收、验证和交付需复查；结构与物理绑定变化使机械、机电、电路和传感链失效。只更改报告不会自动触发原生整机求解。复用不仅比较名称或旧的 PASS，还核对实际输入与文件摘要。

真实主机程序对象与 ARM 对象分别检查外部符号；主机可执行文件由被检查的同一批对象链接，拒绝只在主机条件编译中加入的文件/进程访问。候选代码在独立沙箱进程中执行，不能加载到服务进程。编译器需要的精确栈保护辅助符号单独允许，未放宽参与者 I/O 权限。重复声明同一摘要的不同 RAW 文件也分别核对，不能通过首个文件掩盖第二个损坏文件。

主服务仍为 `http://127.0.0.1:8768/`；主 UI 风格保留。十篇在原论文运行数据库中，查询只读 `mode=ro`；不为审计另建 Workbench。新 C 阶段沿原 `pi-chat-3faf3eb798e76401`，旧门磁 owner 不恢复。
