## 3. 使用者角度：现在能获得什么

### 3.1 可用价值

用户可以在原工程页面接手一个有明确范围的任务，保留原 Pi 会话与产物；Pi 可读取合同和版本、调工具、观察失败、修改共享程序、选择检查、采用并提交。同版本的 C/A/B 阶段包有实际源文件、编译对象、执行轨迹、采用理由和检查回执，可交由另一人复核。

十篇也已经留下可读的阶段工程包，局部机械、固件、供能模型与资料不是空目录。可以用这些包接手下一阶段、核对事实、排除已关闭问题，避免从头复现。

原主 UI 已恢复并保持字节一致：对话/产品/交付与工程工作区/运行动画的结构沿用。此轮无需新控制台来展示能力；新资料用独立文档和压缩包提供。当前 HTTP 与 C 同版本包已读回，本轮未再次做全部鼠标交互回归。

### 3.2 使用体验的主要不足

**页面在线、会话 IDLE、模型进程 COMPLETED、文件包 PASS、功能 PASS 仍然容易被误解为同一状态。** 十论文的 stage 文件门都 PASS，但 39 个核心门未检查。用户实际需要知道的是：当前采用哪个 D、下一项受什么阻塞、哪份包可读、结论适用于什么范围。

C 已有主控持久状态；A/B 和方法比较仍主要通过实验 CLI 加封存记录完成。这些实际结果尚未统一进入主任务交付/恢复流。用户若手动重试通用 chat，可能进入错误控制器。21 个未派发占位本轮已经通过现有 recall API 撤回，但这个补救不能替代统一控制器。

产品页适合保留现有布局，增加精确的已通过范围、未关闭门、有效来源及交付入口。需要补的是数据绑定与状态语义，没有证据支持再次大幅改 UI。

## 4. 架构角度：各层的职责与实际状态

### 4.1 核心提示词

新 DesignLab/方法执行的核心较短：理解合同、按实际事实修订、保留边界、不能编辑 E/V/账本或自授通过。专业细节归工具合同和技能正文。

优点是减少“每次错误再加一段全局提示”。不足是旧论文流程、通用 chat、C 和实验方法执行器的入口还不完全一致；仅改某个提示词不等于所有运行使用该版本。

### 4.2 Skills 与插件

系统已有冻结目录、明确技能身份/版本/适配器和按需激活机制。新 C 使用两个服务器所有的技能：`bf-design-task-control-v1` 与 `bf-compiled-event-port-v1`；`resources.py:load()` 对错名明确报错，`bundle()` 提供适配器和资源 SHA。

实际源码：

```python
if skill_id not in SKILLS:
    raise ValueError('SKILL_NOT_FOUND; available='+','.join(SKILLS))
```

技能正文进入实际请求已经有证据；“安装”“可调用”“被本次读取”“产生正确动作”仍分别记录。R4 的 Pi 补丁实际写成 `SKILL.md` 并注入 system 指令，但未推广到全局目录，不能把它计作已发布产品插件。

旧架构文档中 21 项技能、4 个插件包是历史目录记录，不能仅凭数量证明质量或本次兼容性。新两项是 Codex 公共方法，R4 条件补丁才是 Pi 方法候选。两种来源要保留。

### 4.3 MCP、工具与实际能力

工具/插件是执行和资源组织方式，MCP 是传输/能力暴露层之一；不是额外的设计智能。实际工程路径还使用 typed CLI、HTTP、原生进程及文件回读。

有效接口应返回精确工程身份、输入哈希、实际作业状态、检查范围和分页位置。Skill 可以解释工作方法，科学执行工具应提供事实。不能用安装了 EasyEDA 接口代替实际原生项目、保存/重载/读回、连通性及 DRC 验收。

本轮 A 首次将源码放进 `candidate` 时被静默忽略，导致 11 个付费调用没有产生预期修订，直接说明参数合同比再增加提示词更重要。新有限执行器已拒绝错误/未知字段并明确列出参数，但其他旧工具仍需逐个合同回归，不能宣称全系统已无类似问题。

### 4.4 状态、记忆与上下文

任务状态、已采用工程、版本、作业和检查应由程序提供事实；模型的总结、`TASK.md/CHECKPOINT.md/analysis.json` 是辅助解释。过期文字不能覆盖已构建或已封存的源。

保存经验或激活 Skill 不更新模型权重。长期文件和会话恢复也不自动形成可迁移知识。有效经验要包含当时可见输入、动作、后果、范围及介入，再经新任务验证。

当前有 SDK 会话、任务数据库、公共轨迹、归档及请求投影等多份表示。它们能保留历史，但一致性与恢复成本也是问题；下一步宜统一任务主状态和按需引用，而非增加另一份总结作为事实源。

### 4.5 独立检查与采用

`DesignLab.adopt()` 通过 `BEGIN IMMEDIATE` 和 expected revision 校验采用，任务提交消费实际执行结果。方法候选由独立程序裁决。两者都避免“模型说成功即成功”。

这里的“独立”主要指独立于参与者生成与自我评价：评价器由公共工程实现，模型不能修改。它不等于已有外部实验室、第三方实物验证或完全独立研发团队审查。Codex 编写检查器也会出错，本轮多项 checker 错误已保留并撤回相应结论。

## 5. 任务恢复与上下文审查

### 5.1 已有真实恢复证据

### 5.2 尚缺的恢复资格

运行中的服务崩溃、供应商已扣费但本地未确认、原生作业未知、文件写到一半、提交后未收到确认等多种切点，需要故障注入和精确重放。本轮已有局部测试，尚未证明所有长时工程工具都能 exactly-once 恢复。

C 的主控制器和 A/B/方法 CLI 的双重入口仍不一致。21 个通用未派发占位被撤回，97 条新费用保持；这解决一个具体误重派风险。应将实际控制器身份持久化，恢复时按身份选择运行器，而不是只按 chat 状态猜。

### 5.3 生效授权和部署差异

用户已明确取消费用/token/请求/运行时间累计上限，不需要再次询问相同授权。主服务实际为 `bf-model-unbounded-policy-v2`、时间无上限；论文旧 runtime 的只读查询仍是 v1 owners 策略，缺 v2 时间授权字段。旧 10 月 9 日时间记录不能当成用户当前意愿，但新授权也不会仅因一句文字自动更新所有库。

这是发布/兼容性缺口。恢复十篇推理前应在其实际 runtime 上发布兼容政策并封存原值，读取实际 READY/资格哈希、owner、共享锁和队列。不能换 owner 绕过旧策略或清 UNKNOWN。此次十论文审查没有新派发，原十任务当前无原生作业运行；P01 会话历史为 FAILED，其余多为 IDLE。

### 5.5 合理的费用优化顺序

1. 先减少无结果的循环：严格参数、身份明确、读取一次完整有界失败、避免重包和重派。
2. 对每轮提供当前 D/E/V、有效未关闭问题、最近作业和下一决策需要的事实，完整历史按哈希回读。
3. 固定模型、thinking、工具、资料和评价，比较当前上下文与候选；统计成功、语义提示、所有请求、缓存、验证和获取成本。
4. 只有保存质量且实际总成本改善才发布；低源字节不是充分条件。R4 的反向追加结果正说明“提示更有帮助”的直觉需要检验。

P01–P05 以完整系统为目标，P06–P08 专业子系统，P09 替代无芯片架构，P10 接收侧无线供电。不能为了统一目录强加 MCU，也不能用五项专项当五件整机成功。

### 6.1 真正的工程瓶颈

**原生电子与跨专业接口是突出缺口。** 编译有了，但原理图器件身份/引脚、PCB 网络/DRC、真实尺寸与板固件接口尚未贯通。机械 STEP/实体存在不等于配合、装配和动力学；SPICE 波形存在不等于源域和任务预算有效。

**程序功耗与供电关系仍分层。** C 复用固定 D5 见证，改变负载使结果过期；A/B 将程序阶段反馈到储能，但用固定阶段电流和合成源。二者都不是已校准的目标固件—转换器联合执行。

**模型有效域比求解器是否返回成功更重要。** 当前部分论文只获得存储、静态几何、代理电路等局部模型，论文核心功能未建成。正确做法是扩大有证据的可执行域，而不是增加几次相同求解。

## 8. 研究者角度：现在实验装置是否可信

### 8.1 已增强的可研究性

设计 D、执行方法 H、环境 E、评价 V 分离；真实源变更、执行、采用与结果可定位；错误通过不会覆盖；UNKNOWN 不清除；独立采用可以 REJECT。既有无 Agent 正负参考，也有实际 Pi，而不是只有 mocked 模型代理。

本轮 20 个 R3 控制和 17 个针对测试补了真值泄漏、免费阶段电流、主机 I/O 与错数值回执问题。应用完整 932 tests 通过，目标工具链身份固定；这是有意义的工程基础。

### 8.2 尚限制因果解释的因素

1. A/B 源和阶段功耗为人给定；ngspice 数值积分复核重放同一净能量账，不能独立证明源/负载物理真实性。
2. 方法比较每项样本少，父子顺序/缓存/随机性未全部控制。首轮 5 对与追加 3 对全 PASS、正确性收益 0，不能证明能力提升。
3. 基础 API model 名、thinking 和实际请求被冻结，但商业 API 后台权重没有可验证 pin；不能宣称实验期间供应商内部权重恒定。
4. 评价器与公共参考主要由 Codex 建立。必须继续用负控、独立实现/资料和外部复核验证 evaluator，而不能仅由自己的测试证明自己的科学语义。
5. 改进对象目前是条件化 Skill/提示注入；没有真实自改 Harness 执行代码并通过发布/回滚的连续链。
6. 所有十篇已经进入开发与反馈过程，是开发/回归资产。后续用于独立泛化结论需要新论文/新任务；这些论文的新变体只证明变体迁移。
7. 比较费用未包含全部 Codex/人工、原生计算及物理成本；供应商账单未重新对账。本地登记与缓存估算须并列。

### 8.3 对 R4/R5 的正确解释

首轮限定变体结果符合预注册成本规则，记录保留。反转顺序后的新序列加入获取费仅降约 9.1%，未达 15%，故不扩大采用。这个结果证明候选评价流程能作出拒绝，不证明该 Skill 在所有情形无用，也不证明它已有稳定收益。

R5 的方法后代暂未运行，因缺少通过追加确认的父方法。物理也未运行，因设备和采集身份未明确。两者为不同前提，均不应标为已经测试失败。不能由版本号递增、五间动画或技能数量推导 RSI。

## 9. 论文角度：可支持什么主张

### 9.1 目前有证据的主张

- 实现并展示一个有限设计装置：Pi 的真实 C 修订进入编译、执行、独立检查与同版交付。
- 在声明合成域中，源/负载变化能改变程序与服务结果；版本错配、无数据类别、错误身份和未完成接收等负控被拒绝。
- 可保留真实失败、费用和外部介入，并在原 owner 恢复任务。
- 一个 Pi 方法候选经过实际加载、新变体配对和费用评价，追加确认没有满足推广规则；可以报告负结果。
- 多论文工程资料与阶段产物能按实际版本审查，文件门与核心功能门明确区分。

### 9.2 目前证据不支持的主张

- 十篇完整复现成功、80% 整机成功、原生 PCB/固件全部复原。
- 完整自主多专业产品设计、人类工程师替代、真实采能设备自主运行。
- 稳定减少费用、改善模型一般能力、独立跨论文迁移。
- 连续递归自改进、权重学习、每代都提高。
- 合成源或静态模型证明论文物理结论错误/正确。

是否构成论文新颖性，还需独立文献定位和足够实验；本次系统审查没有据实现存在就授予新颖性。较稳妥的当前定位是可执行工程 Agent 与版本/资格/验收边界的装置报告。若要主打学习或自主设计能力，需要相应新任务、对照、覆盖和物理/目标证据。

### 9.3 需要补的最小研究证据

固定一个有来源、可被反例推翻的任务环境；注册 H0 与一个小候选；进行多次配对、顺序平衡及无关负例；统计实际正确性、严重错误、完成声明、人工语义提示、全部成本。固定公共工具和资料，明确 API 模型 pin 的局限。

用未参与候选选择的新任务验证，再决定是否采用。若后代可继续提出更新，要保存实际父子补丁、加载、执行和独立裁决，不要求每一代成功。
