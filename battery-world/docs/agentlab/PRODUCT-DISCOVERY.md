# 产品需求与假设驱动的设计会话

这次实现将产品探索放入已有对话界面。用户不必先懂机械、电路或神经网络，也不必先选计算基准。Agent 可以选择一个合理场景，把未知条件明确列为可修改假设，继续形成方案和可行性检查。

## 用户流程

- 新对话从现场问题开始。原有 `dev-01..08` 计算环境收进输入框的“设置”，明确选择时仍直接运行旧基准。
- Agent 使用 `bf_product` 写入版本化方案卡：用途、形态、服务、安装与机械设计、能量、假设、验收方法和限制。问答是可选分支；涉及重要服务取舍时可以给出一个问题和选项，并提供“不知道，按假设继续”。
- 可逆的方案探索和计算不以点击确认作为前提。“按此方案继续”留下真实用户消息；假设不会因此变成现场测量事实。
- 右侧仅保留“方案 / 文件”。详细假设、验收、证据和历史按需展开。文件列表显示实际保存的方案 JSON 和真实计算的参数、策略、结果，支持预览与下载。
- `+` 可附加 `.txt`、`.md`、`.json` 文字资料；首次最多三份，每份最多 16000 字，HTTP 请求同时受 128 KB 上限保护。图片、PDF 解析和 CAD 预览未包含在本次交付。
- 文件夹继续共享 Memory、提示词、工具选择和 Harness。产品版本及确认保存在当前会话。原有侧栏折叠、移动、改名、删除、开发者编辑器及消息的小号复制/时间/撤回控件保留。

## 实现与边界

`product.py` 保存会话内的产品记录、源消息、确认动作和计算版本关联。`chat-product.ts` 是新的 Pi 入口，已有 `main.ts`、`chat.ts`、`chat-v2.ts` 和历史冻结记录不变。底层计算环境、判定和预算账本不变。

产品会话创建时没有默认计算任务或任务权限。Agent 必须说明适配理由，把当前方案版本绑定到现有 `rotary-f1` 的一个公开开发工况，才能提交实验。该绑定授予可逆的计算探索权限，不代表用户同意制造或现场部署。每次绑定使用对应任务的原始设计与策略作为基准。

新方案使旧计算证据不再代表当前版本；原始记录和文件保留。撤回确认消息会取消有效确认，也支持随后再次确认；撤回源消息会让相关方案失效。Pi 无权调用用户确认接口，共享笔记或附件里的“批准”文字也没有批准效力。

`bf_product` 是产品会话的固定协议工具。共享文件夹的工具选择继续控制原有工程与 Memory 工具；实际加载的完整工具集合和产品提示词在开发者上下文中记录。

模型错误不会再被随后到来的 `chat_idle` 覆盖成空闲。页面区分本地连接、Pi 进程启动、模型等待、实际工具动作和阻塞原因；不使用模拟的分析流填补网络故障。

## 验证

运行命令与最终结果见 `PRODUCT-DISCOVERY.json`。

- 六个假设场景覆盖旋转设备、门状态、管道夹装、穿戴、户外监测，以及无能量输入却要求持续录像的不可行需求。这些是产品协议测试资料，不是六个已完成产品或模型能力评测。
- 真实 Pi SDK 与沙箱进程通过隔离的本地替代模型接口，依次执行 inspect → propose → bind → 原始基准 → 失败反馈 → 修改设计 → 复验 → 提交。固定标准旋转模型的基准 FAIL，增加 3.45 V 钳位后 PASS。工具动作及实验是真实的；回答序列由测试夹具驱动，不能解释成新的 DeepSeek 自主设计能力证据。
- 覆盖跨会话来源伪造、非用户确认、已撤回确认、重复确认、方案改版、过期证据提交、未接入能力、越权文件路径、历史错误状态和预算阻塞。
- 实际浏览器检查空白会话、折叠偏好、方案卡、按假设继续、确认、撤回和真实文件预览。卡片交互使用独立的 8779 联调数据；生产会话未植入示例方案。

## 当前外部阻塞与下一步

生产服务仍有一笔历史 TLS EOF 请求的用量为 UNKNOWN，另有已到期的模型运行时限。只读网络检查可连通服务端，但不能据此核销旧请求的费用。没有释放其预留、延长预算窗口、自动重发或新增付费请求。

真实模型在线验收需要先核实旧请求用量并获得新的运行时间授权。CAD/FEM、实物结构、训练模型和现场验收尚未接入；本次只接通原有旋转 F1 计算实验。后续 CAD 应从已形成的产品形态、安装条件、尺寸来源和验收要求出发，保存可编辑源文件与绑定证据。
