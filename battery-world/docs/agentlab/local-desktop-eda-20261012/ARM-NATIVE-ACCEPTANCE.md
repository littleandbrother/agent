## 3. CLI 与 Gateway 的真实比较

早期 Run API Gateway 只读调用出现 12 秒、8 秒超时，另有一个旧连接错误。这些回执保留。
完整客户端重启后，Gateway 的只读调用恢复；首页窗口返回没有当前工程，测试项目窗口
返回正确 UUID，项目读取约 4 ms。

随后在同一测试 PCB 上，用**相同冻结 typed 提供程序、相同 action、相同输入**串行比较：

| 路径 | 一次板框读取 | 真实身份/尺寸 |
| --- | --- | --- |
| 厂商内置 CLI | 0.546 s | PASS |
| Run API Gateway | 0.133 s | PASS |

每条路径只取一个样本，不是完整性能基准。Gateway 有减少进程开销的潜力；本次没有通过
它执行工程写入，未检查其保存、恢复、超时/UNKNOWN 和交付资格。BF 继续使用本轮已经
完成 Pi 写入与重启验收的内置 CLI；不自动降级到 Gateway 或 Web。

本地文件 CLI 打开约 1.25–1.48 秒；两次文档重载分别约 28.47、32.29 秒。客户端层仍有
可见等待。ARM 二进制确认通过，不能把非受控的 ARM/x86 观察当作“卡顿全部解决”。

## 4. 归因、失败与费用

- **Pi**：生成参数，写入两版板框，显式保存，重载，读取原生几何，导出原生工程并写报告。
- **Codex**：修公共接口/本地路由/Skill；建立空测试容器，打开/恢复同一本地文件；提供
  接口和报告边界的公开反馈；独立检查与后台/客户端生命周期测试。
- Codex 对参与者设计源码写入为 **0**，对测试板框的直接几何编辑为 **0**。
- Pi 在测试窗口关闭后有一次阶段停止。重新打开同一文件后沿原 owner 继续，未重建工程。
  窗口关闭原因未证明，不归因于 Pi 或厂商。
- `project --help` 曾被过度拒绝，造成 Pi 错误推断没有导出通道。接口已修复并有回归负例；
  原推断及后续更正均保留。原生导出随后由 Pi 成功执行。
- Pi 报告曾把文档重载外推为整个客户端重开，也混淆 schematic/page UUID。已提供事实
  反馈并由 Pi 修正文档。独立客户端重启通过由另一份回执证明。
- 新 owner 共 **53** 条 SETTLED 请求，本地保守登记费用 **$0.5047314**。
  这是本地登记口径，不是供应商实付账单；全部预留、失败和 UNKNOWN 不重置。
- 因此本轮支持“Pi 可在已接通、已指定测试要求的本地工程中进行原生操作”，不证明完整
  电子产品自主设计、零教师帮助、整体效率收益或 RSI。

## 6. 如何使用

正常启动 ARM 桌面客户端，打开本地目标工程；后台自动启动。Pi 通过 `bf_eda inspect`
核对真实宿主、绑定 UUID 与唯一原生 session 后使用 typed 工具。无需改成 Web，也无需
为了本地流程每次登录。云端工程、在线库、备份与厂商授权仍按其服务条件处理；本轮
不能保证云端会话永久有效。

窗口关闭时先恢复同一个已有文件并确认 UUID，不让模型不断重试或创建替代工程。每个
检查点显式保存；写入 UNKNOWN 时停后续写入，重启后台不清账或清 UNKNOWN。

总回执：`native-closeout.json`。Pi 当前报告、参数、几何快照和原生工程包含在下载包中。
历史停止报告保持原样，最新独立检查优先于旧文字状态。
