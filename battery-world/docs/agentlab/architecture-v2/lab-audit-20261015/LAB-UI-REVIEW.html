Lab UI 审查与改版方案

审查日期：2026-10-15。对象：http://127.0.0.1:8768/lab 的六个页面、关键详情、工程预览和横向历史。检查窗口：1280×720、1024×768、1440×900。

主要问题：页面按照内部数据对象排版，缺少面向用户的阅读顺序。当前版本、实际问题和下一项工作，被哈希、重复记录及过密的卡片掩盖了。优先修正状态与统计，再整理导航、详情和布局。

本报告包含改版方案和验收条件；当前页面尚未修改。

1. 当前页面应该首先讲清的事实

用户要知道什么当前事实建议显示
正在看哪个设计当前提交 SC-e8f2f2e5…；当前采用 SC-4c0da605…第二轮供电／固件修订；旁边单列“稳定参考”
这一版如何核心检查 2 通过、2 未通过、4 缺少验证条件以这 8 项作为版本验收汇总
主要卡点供能与任务执行、PCB DRC；器件／接口／模型／装配资料缺口直接列问题名称和具体原因，点击看测量与证据
Agent 现在是否工作原 Lead、Power、Firmware 均已停止执行；另外两个未执行任务仍显示“已排队”当前无运行任务；历史及未启动任务收起
能看什么原理图、PCB、CAD 预览均可打开；同版审查包存在工程预览、检查结论、交付下载三个明确入口

版本名称是建议的显示别名，底层提交身份和账本保持原样。

2. 六个页面的审查结果

顺序／页面健康度实测问题改进后的首屏
1 系统设计需重排四列流程、四个专业、候选、六步验收同时争抢空间；专业卡只统计最后一次声明的 1 项变化，未体现整轮源码修改当前候选、相比上轮的实际变化、接口和验收摘要；底部横向版本历史
2 运行记录需重排操作回执直接称为 Decision Episodes；每条堆长理由、哈希和调用状态；详情展开后 Agent 名称被挤成多行按设计轮次与工程任务分组，显示谁、做什么、得到什么结果
3 验证优先修正8 项核心门与 4 条复查记录合计为 12 项，显示 4 通过／4 失败；同类契约重复出现当前 8 项有效结论；复查历史另开，不计入当前完成数
4 环境需修正三栏中的五列表格过窄，ARM_GCC 等名称断成多行；执行资格部分由前端固定规则推断按机械、EDA、SPICE、固件列能力，给出实际版本、最近调用、结果及阻塞
5 方法与技能需修正顶部只显示最后一个 H 哈希，底部实际存在不同 Agent 的不同 H；技能目录、加载和激活混在长列表按 Agent 查看实际方法与本轮技能；完整技能库单独展开
6 实验与改进应简化尚无注册实验，却占用多个空卡片；两个方法配置被画成谱系；开发活动计数放在 Findings 下实验准备状态、真实比较记录；方法配置和有亲缘依据的谱系分别显示

当前浅色风格、Studio／Lab 入口、矢量图标、原生工程查看器和横向历史可以继续使用。

3. 具体问题、原因和措施

P0：先修正用户会读错或点不动的地方

问题当前证据／原因具体改动验收条件
验收数量重复validationRecords() 将 8 个当前门和 4 条检查回执直接拼接；validationPage() 对整个集合计数当前资格按核心门汇总；接口检查按检查类型取当前有效记录；历史保留在历史区当前版本首屏显示 2／2／4；历史增加不改变完成数
契约列表与详情状态冲突列表读最新检查为“通过”；详情读契约本体 status，显示“未检查”契约详情同时表达“契约版本”与“本候选下的检查结果”，后者与列表使用同一来源同一对象在卡片、列表、详情显示相同检查状态与范围
失败详情没有原因供能门详情只展示 power_load_chain、摘要和绑定字符串，缺少实际结果默认显示结论、关键测量、条件、具体问题和报告链接；哈希移到来源区点“供能未通过”直接看到问题和本轮测量，继续一击打开完整证据
验收表格行点击无响应行含 data-kind，点击处理器只接受 button,[data-preview],[data-cad]；现场点行未打开详情表格内增加真正的详情按钮／链接，支持键盘鼠标和 Enter 都能打开对应检查
执行成功与工程结论混淆运行卡采用操作的 SUCCEEDED，实际检查结果可能是 FAIL分开显示“调用已完成”和“工程结果：未通过”，主要强调工程结果检查完成但失败的卡片不会只剩一个绿色成功标签
环境与方法状态靠固定文案exercised() 对 SPICE/CAD 返回“复用基线结果”；策略卡和加载卡包含固定 ACTIVE/PASS由对应能力回执、实际执行和所选 Agent 的加载记录产生状态；显示作用范围与时间目标构建、SPICE 本轮执行、基线复用、未开放写入能分别对上实际记录

P2：布局与交互整理

- 列宽随主工作区变化。 1024 窗口中运行正文为 11px，Agent 卡名称和请求数被反复断行。右侧详情默认抽屉打开；主区不足时覆盖显示，关闭后完全消失。

- 侧栏完全收起。 用顶部按钮重新展开，不留一排细栏。宽度偏好与详情状态按页面保存。

- 减少同级卡片和边框。 每页一块主要工作区域；辅助信息折叠。正文建议 14px，元信息 12px，标题 20–24px；英文技术名按单词断行。

- 图纸提供缩放和平移。 原理图适屏后器件文字太小；PCB 默认图也缺少局部定位。共用查看器增加适屏、100%、放大、缩小、拖动和器件／网络定位；CAD 沿用已有旋转缩放。

- 固定返回位置。 切页和展开详情引发布局重排，时间轴选中项会离开视野。页面、对象、候选、过滤器和滚动位置一起恢复；路由名与 select#system 的锚点重名一并处理。

- 明确更新时间。 “Synced”改成上次读取时间，同时显示最新工程事件时间；断流时保留最后视图和提示。

- 补键盘语义。 页面导航设置 aria-current；选项卡表达当前选中；弹窗关联标题；表格用可聚焦按钮。避免把整页重新渲染都放入实时播报区。

- 搜索给出范围与结果。 当前实现匹配 JSON.stringify，用户难以知道为何命中。优先检索名称、问题和文件，提供结果数、清空和无结果提示，ID 检索继续保留。

各页应展示什么

页面左侧对象主工作区详情与联动
系统设计当前系统、专业版本、接口；历史版本入口候选目的；相对父版本的真实差异；8 项验收；工程预览；交付点专业看源码／模型差异，点契约看对照，点失败看测量；横向历史保留

环境机械、EDA、SPICE、固件、数据接口软件版本、当前连接、权限、最近真实操作、当前阻塞完整配置、实际接口合同、原生回执、资源锁与故障信息
方法与技能Lead／Power／Firmware；技能库入口该 Agent 的模型、上下文、工具配置、本轮加载和使用的技能提示词、实际请求、版本差异、技能正文和使用片段
实验与改进协议、实验、方法候选未开始时给准备状态；已执行时给条件、样本和真实结果方法／环境／评价身份，原始运行与采用依据

三种典型操作

1. 看当前卡点： 系统设计 → “供能与任务执行未通过” → 测量／条件 → 本轮波形与负载 → 相关 Power／Firmware 修改。

2. 看版本如何改进： 横向历史 → 选择第二轮系统 → 相对第一轮的差异 → 新构建和计算 → 独立检查 → BF 的决定。

3. 研究 Agent 方法： 运行任务 → 当时实际方法／技能 → 对应配置 → 已注册比较；费用范围与任务范围一致。

任何跨页跳转都携带项目、候选和所选对象。返回时恢复原来的阅读位置。查看历史只切换观察对象。

5. 实施顺序与验收

工作包内容完成条件
A 状态与统计当前资格／历史拆分；契约状态统一；调用结果与工程结果分开；修表格入口同一候选、同一检查，在各处读到同一结论；重复回执不改变当前验收数
B 内容与导航语义标题、按页对象栏、类型化详情、按任务分组、费用范围能从当前候选经契约追到相关运行与工程证据，默认阅读不依赖 JSON
