# 运行中发现的问题

本文件记录离线审查，不向运行中的 Pi 注入提示。20 项试验保持同一份 H，结果汇总后决定默认配置。

| 位置 | 实际问题 | 后续改动 |
|---|---|---|
| 资料返回 | `files` 同时表示设计提议和资料结果；资料任务要求空对象，现有说明没有给出明确示例 | 为资料任务生成可校验的 `files:{}` 示例，并区分提议与引用 |
| 来源定位 | `WORK_SOURCE_POINTER`、`WORK_SOURCE_NOT_IN_BASE` 缺少具体失败字段和可用路径，Agent 连续猜测 | 返回出错事实、文件、定位器；提供冻结文件目录及结构化章节读取 |
| 工具参数 | 电容固定组两次调用 `read` 只传 `path`，后端返回裸 `'system_id'`；工具入口未在调用前指出必填身份 | 将动作参数要求并入同一 schema，返回缺失字段和可选候选身份 |
| 结果引用 | 零储能固定组的电源工作者能读取 `fine/program.csv`，但返回协议只接受父源树内文件，工作者把执行 ID 和波形来源塞进文字条件 | 为冻结任务及其执行产物提供统一、可校验的证据引用；保持候选与执行身份 |
| 完成判断 | S1 直接读取组提交被拒后，最终文本仍声称“已提交” | 结束条件读取已保存的 WR 回执；缺回执的试验记为未完成 |
| 工程报告 | 连续设计第一轮把正的 `unresolved_electrical_j` 解释为源端缺口；零储能通过组又把它称为结束储能 | 独立语义复核保留：该量为端口能量减储能增量与负载能量，应结合 PMIC／寄生损耗解释 |
| 任务定义 | T2公开任务给出8 ms有效期，却没有说明计龄起点；检查器从采样开始计龄，最短采样10 ms加发送4 ms已超限；通用目标仍要求实际修改 | 公开完整接收判据与时间起点；启动前检查固定下界，支持约束冲突出口 |
| 存储预检 | 联合迭代写入多份大波形，磁盘耗尽后外层执行未完成；已有调用未进入原统计 | 启动前按预计峰值预留空间；失败执行保存已发生的原生调用和输入身份；继续按完成回执复用 |
| 启动依赖 | Git元数据和Node依赖冷加载导致首个模型请求前退出 | 将本地文件读回、Git身份和实际SDK导入并入免费预检；零调用恢复保留原失败回执 |
| 操作身份 | T2-joint最终文本声称没有更换操作ID，轨迹实际尝试了新ID及错误候选ID | 报告中的操作与完成状态从事件回执生成；UNKNOWN先对账，再按原ID处理 |
| 结束对账 | T2-fixed达到80次共享请求时，控制器先退出，后台失败执行随后入库；原结束快照漏掉12次原生调用 | 结束采集等待在途操作结算；失败执行也从迭代回执计数。原快照保留，追加结算证明 |

T2 的固定判据从采样开始计算数据有效期。最短采样10 ms、发送4 ms，单状态程序不能重叠两者，有效期却为8 ms。公开任务只给出时长和概括性接收条件，缺少计龄起点，Pi多次按采样结束解释。该任务单列为定义缺陷结果，原始任务和判据保留；组织比较另列其余三个可行任务。证据：`results/t2-public-contract-audit.json`。
