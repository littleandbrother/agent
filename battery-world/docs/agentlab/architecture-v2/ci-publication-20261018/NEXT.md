# 下一步：让主设计者使用闭环完成连续修订

执行器已具备电压驱动的启动、掉电复位和程序负载反馈。预充参考接收5帧；零储能参考17.9385秒启动，在20秒内收到1帧，要求3帧。下一步围绕这一差距推进。

| 顺序 | 工作 | 结束条件 |
|---|---|---|
| 1 | 原V2压电任务显式切换到反馈配置，沿用主设计者、工程历史和账本 | 任务、修改范围、初态、服务判据、参考资格和费用时限均绑定；旧候选可查 |
| 2 | BF选择真实源码或设计参数修订，执行、独立检查、决定并交付；再基于新候选小修一次 | 两轮候选→执行→检查→决定→同版包；完整源树和作业对应，未变计算复用，中断可继续 |
| 3 | 只接入一种按需资料工作者，返回参数、单位、工况、来源和冲突 | 主设计者实际消费结果；与直接检索对照，统计全部调用、错误和返工，再决定保留 |
| 4 | 同任务、模型、工具、初态和评价比较单主设计者、临时委派、原固定工种和按证据扩大共同范围 | 统计有效服务、错误采用、返工、人工介入与总成本；验证集和最终测试分开 |

BF决定修改哪一侧；Codex处理执行器缺陷和版本问题。固定任务要求、设计变量及检查器版本，设计失败继续进入候选证据。下一轮先用已具资格的单主设计者路径，具体初态作为任务条件明确选择并冻结。

共同范围按实际问题调整：缺接口信息、共同上下文还是实验范围，分别处理，记录原因和代价。跨任务检验再形成可迁移规则；改进器比较在积累独立轨迹后开展。

目标MCU与电流测量作为模型校准增量接入。现有主机C和声明电流模型继续保留来源。其余九个原案例在连续修订稳定后，选一个有不同耦合特点的案例验证迁移。
