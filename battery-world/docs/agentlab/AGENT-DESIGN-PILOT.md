# 固定门磁器件家族的设计先导（BFA-031）

本轮回答一个有限问题：Pi 能否读取原生反馈、自主提出合法修改、执行、比较并提交？
这不是开放式架构综合、方法优越性比较、实物验证或 Harness RSI 成功实验。

## 固定任务与参与者边界

任务是一次既定开门动作、零初始储能、无诊断电源，在 4 秒内完成至少一个正确应用报文。
目前只评价“动作事件出现”，不评价开/关方向或跨掉电的严格一次性动作语义。
唯一任务源为 `configs/reference_cases/design-pilot/door-event-nominal-v1.json`；绑定后不可编辑。

| 内容 | 当前处理 |
|---|---|
| 间距 | 28–70 mm，进入 CAD 和力表；合法输入仍可能超出线性模型域 |
| 输入电容 | 10 / 22 / 47 / 100 / 220 μF，进入原生电路 |
| 输出电容 | 10 / 22 / 47 / 100 / 220 / 470 μF，进入原生电路 |
| 广播间隔 | 50 / 100 / 200 / 500 ms，重新编译共享 C 配置 |
| 动作、初始储能、诊断电源、链路 | 冻结 |
| 阻尼、剩磁、程序阶段时间和电流 | 冻结；没有器件/代码依据时不作为设计变量 |
| 数值设置、确认检查 | 冻结；不能关闭确认 |
| 展示参数 | 本轮不参与优化 |

标准电容值只代表当前名义电路的电容选项，不声称已经绑定具体供应商料号、偏压降额或温度公差。
工具不会返回自然语言“应该选哪个参数”。Pi 的公开说明保存在 Trace；物理效果由候选和产物核对。

任务绑定会限定 Pi 只使用 `bf_engineering`。没有通用文件写入、命令执行或其他求解入口。
新候选数量在数据库事务内检查；重复 operation_id 返回原任务，不额外消耗候选名额。
最终提交限定在同一 owner 的已结束任务；重新核对文件哈希并重算任务评价，封存选择和理由。

## 四层状态不能混用

1. **输入合法**：没有改变冻结条件。
2. **可以解释的名义预测**：原生求解完成，能量、插值、梁网格、程序负载固定点和时间步检查通过。
3. **名义任务是否满足**：在层 2 的前提下，供电达到启动条件且存在按时、载荷正确、来源属于完整 TX 的接收报文。
4. **物理设计排序资格**：还要求磁场网格、独立锚点和完整旋转轨迹确认。

当前完整旋转 FEM 覆盖尚未完成，磁场网格也有未通过项。因此本轮可能进行模型内预测比较，不能据此宣布物理设计排序已经成立。
`out_of_domain`、`numerical_fail`、`tool_fail` 与合法模型内的 `unsatisfied` 分别保留。
任一层都不会自动将 `product_verified` 或 `hardware_calibrated` 改为真。

## 原生摸底与冷缓存控制

`protocol.json` 预声明 12 个候选：基线、5 个间距、3 个输入电容、输出电容、广播间隔和一个组合。
额外两次基线使用各自空缓存，独立启动原生工具。首个基线和两个冷复算可以用于检查数值重复性；
其余候选共享一个仅属于本轮的摸底缓存。Pi 的每条轨迹另用独立缓存，不继承摸底热缓存。

这只是有边界的开发期取样，不能把未找到成功候选写成“整个设计空间不可行”。
本轮不使用外部电流正诊断作为自供能正例，不自动扩展任务条件来得到成功。

每个记录包含：冻结任务、实现与工具身份、候选、全部检查、结构化状态、阶段执行/缓存次数、
原生档案哈希和外层周转时间。外层计时包含归档和读回校验；内部求解耗时另列，不混用。
失败运行不会被覆盖；不自动重试并替换失败结果。

运行上限：12 个摸底 + 2 个冷复算、合计不超过 6 小时、单候选最多 1 小时。
磁场、梁和 PMIC 仍为已有模型，不在摸底途中改源码或降低阈值。
额外沿实际轨迹检查 0–65° 的解析磁力求积与插值误差，以及早期运动的磁力做功占比；
它是同一解析假设下的数值诊断，不等价于独立 FEM 确认。

## 真实 Pi 先导

预声明四条轨迹：基线失败两次、模型域边界起点两次；每条最多 3 个新候选。
初始资料只给该起点的原生反馈和注明降采样的波形预览，不给其他摸底候选答案。
模型内正例尚未建立，因此不伪造第三类“正例附近改进”任务。

Pi 使用当前同一服务和费用账本，每条轨迹独立 owner、候选缓存和最终提交。
请求的新增研究额度为 USD 2、12 小时，单轨迹 USD 0.5、单次请求低于 USD 0.20；
必须先取得明确额度回复。已有费用、未决记录和 token 上限均保留。
服务当前还有 30 分钟交互消息租约，可能比先导脚本的 45 分钟最大外层时间更早停止；
不会静默续租。费用、超时、上下文或等待失败均纳入轨迹记录。

本轮首先观察真实等待和恢复行为，不提前宣称完整崩溃恢复已经验证。
若需补发“继续”或修复运行环境，记录为人工介入，并保留修复前轨迹；正式方法对照另行冻结。

`bf_engineering artifact_view` 支持文本分页及 CSV 通道/时间窗/行分页。
读取始终经过 owner 与原始产物哈希检查，不需要将 GB 级原生档案塞进模型上下文。

## 后续条件

先根据失败区间、模型范围和实际 Pi 行为选择是否开放一个真实结构自由度。
若所有合法取样均未满足，先定位主要物理或模型限制；不要通过反复增加 Agent 调用来伪装设计进展。
