# 用户对话与开发者 Trace

用户页保留流式公开进展、模型回复、用户消息、必要的执行错误和产品交互。`read`、`write`、`bf_inspect_run` 等工具输入/返回卡片及 Pi 加载记录不再出现在对话流中。源日志仍完整保存，模型和 Harness 的执行行为没有改变；没有开启或展示模型内部推理原文。

## 使用入口

选中左侧会话，进入 **开发者 → Trace**。2026-09-18 更新为概览、时间线、对比与原始记录四个视图；工具、Skill 读取和 MCP 调用支持分类筛选。每条调用可展开输入、返回、原始行号、调用 ID 与时间。Tools 页负责能力/统计，并链接到 Trace；RSI 页也可回到当前会话的 Trace。最新入口和验证见 [TRACE-ENGINEERING.md](TRACE-ENGINEERING.md)。下文验证数字是原 BFA-007 交付快照。

“导出审查记录”下载 `bf-agent-trace-review-v1` JSON。它包含：精确原始日志字节（base64）、源 SHA-256、完整换行记录、异常解析/关联记录、运行回执及 Harness 身份、会话事件、模型账本与已有异常判定、实验结果引用。快照 ID 绑定整个导出载荷；原文件不被改写。开发者接口 `/api/developer/trace?session=<session-id>` 仅 operator 可访问。

代码中的 `TraceReview.snapshot` 只读取数据。模型账本/会话/实验在同一 SQLite 只读事务中观察；文件是单独捕获的字节快照，不声称文件和数据库存在全局原子快照。运行中的日志可能继续增长；不完整末行不参与解析，但原字节仍导出。完整行损坏不会悄悄丢弃，会标注行号和错误。32 MiB 以上的源文件需直接使用本地日志，本接口明确报错，不静默截断。

调用关联优先使用 tool call ID。旧日志没有 ID 时，只有唯一同名未完成调用才可按顺序关联，并保持该较弱关联标签；并发同名调用无法判断时记录为待核对。工具开始时间没记录就显示“未记录”，不拿进程启动或日志摄入时间冒充。模型请求只提供实际保存的哈希/usage，不重构并不存在的完整 HTTP 请求。

## 如何服务于 Harness 改进

Trace 可以帮助区分重复读取、工具误用、参数错误、上下文缺失、实验失败与模型连接失败，支持形成具体的修改假设。可从当前 Trace 打开现有 Harness 候选编辑器；打开编辑器不会保存、启用或运行候选。

后续闭环应逐项留证：Trace → 问题归因 → 候选修改 → 同任务/同环境对照与回归 → 后续任务验证 → 独立决定是否采用。无改动、失败和回退记录同样保留。工程设计失败并不自动说明 Harness 有错；工具输出是观测，不是新指令或已验证训练标签。本次只补齐展示、审查和导出，不实现自动优化，不宣称 Harness RSI 已成立。
