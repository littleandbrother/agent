## 三种模式

| 模式 | 用途 | 展示内容 |

| 任务 | 与 BF Agent 完成产品任务 | 原有会话、公开进展、回复、方案与文件 |

控制台明确当前信息属于选中会话、共享文件夹还是整个平台。
Memory 先展示摘要，原始记录折叠。Harness 分开显示本次加载版本、已保存候选与下次选择，避免把保存当成生效。
演化页区分平台代码快照与 Harness 候选谱系，保留已有 H0/H1、递归实验数据及其未通过状态。
验证页分开显示软件检查与选中会话的科学实验；成功执行与设计通过保持原来的区别。

## 全景的数据与交互

首版覆盖 10 个模块、89 份源文件：任务与工作台、会话与产品、Pi Agent、Harness、记忆与配置、工具与工程环境、受控执行与存储、科学计算环境、Trace、验证与演化。
12 条连线是带有来源说明的架构声明，不是静态分析生成的完整函数调用图，也不表示该调用当前正在执行。

- 当前架构：查找模块或文件，拖动节点、平移、缩放、全图和重置布局。
- 开发变化：按真实文件新增、修改、删除高亮模块，点击查看文件与差异。
- 版本对比：选择两个已观察到的快照。历史文件从对应内容存储读取，不读取当前文件代替。
- 右侧详情：模块职责、关联文件、声明关系、执行者归因、检查范围，以及控制台入口。

初始快照为施工过程中建立的观测基线，并非 Git 发布版本；已有工作区没有提交基线。
同样的内容复用同一快照。版本列表保留首次观察时间；重复观察时间单独显示。
所选快照默认与其上一份观测快照比较；要看更早的累计变化，请显式选择比较基线。
模块清单与连线也封存在快照中。

全景可见时每 8 秒扫描一次允许范围内的源码；关闭或隐藏全景后不会持续扫描。
它不是后台文件监听器，可能错过两次观察之间发生又被撤销的修改；扫描也不声称文件系统原子快照。
文件读取期间发生变化会跳过并记录。符号链接、范围外路径、非 UTF-8 和超过 2 MB 的文件不会进入快照。
新模块需要更新明确的模块清单，不会凭空从模型描述生成“已实现”状态。
