# B2-003：供负责人冻结的具体实验方案

2026-09-07 · **待审阅，不是运行授权。** 本文件没有修改正式任务、模型、费用上限、
评估阈值或执行窗口。`protocol-draft.json` 仍为 `draft-not-authorized`。

## 1. 本轮只回答一个问题

同一个 DeepSeek V4 Flash，接触相同历史、使用相同实验工具和预算时，经过独立检查的
可执行知识，是否能使一个没有原始会话的新 Agent 在未见任务上更少试错，并保持
证据准入正确？本阶段不声称长程能力、持续学习、硬件迁移或 RSI。

建议先做**一次迁移的可行性检验**，不要把剩余预算承诺成完整 B–C 论文实验。
即便成功，也只产生一个可复核案例；跨任务统计与多代学习另行预注册。

## 2. 一个刚得到的、会改变实验解释的开发发现

公开的 7 个 v2 条件、36 份已封存设计观测上，固定 C 升序基线需要 22 次策略探测；
两个不经过学习的简单排序——C 降序、ESR 升序——都只需 9 次。
q6/q7/q8 分别由 4/5/3 次降为 1/1/1 次；不可解的 tight-deadline 条件仍探测 3 次并弃权。

这里是**重放已有观测的确定性策略计数**，不是 13 次实际实验被节省，也不是 Agent
自主学到了程序。来源：`docs/b2-development/workflow-use-controls.json`。

直接后果：只战胜 C 升序或原始枚举，不能证明学到的世界模型具有额外价值。
建议把两个固定排序纳入不付费的经典控制，事前冻结，不按隐藏结果选择更好的那个。
正式新任务还应包含“大电容并非总更好”“ESR 相同但负载时序不同”和无需更新的情况。
这些是待批准的任务设计原则，不是已经生成或验证的隐藏任务。

## 3. 建议冻结的研究决策

| 项目 | 具体提案 | 尚需负责人决定的边界 |
| --- | --- | --- |
| 基础模型 | 原 `deepseek-v4-flash`；保持当前 temperature / thinking / max_tokens 参数，精确记录服务 fingerprint | 不用换模型追求更好结果；服务身份变化先停 |
| 历史 | 一份按 run hash 封存的 public-history；四个 Agent 条件完全相同 | 哪些开发运行进入历史，冻结前可审阅 |
| 语义候选 | 最多 G3、G4；每代语义提案 1 次，机械修复最多 2 次 | G4 只读取允许公开的失败反馈，不接触 regression/OOS/blind |
| 机械检查 | AST、安全、plan(ctx)、schema、有效输入、非法输入、域外弃权 | 不通过，不启动新的科学观测 |
| 世界检查 | explanation / deterministic use / regression / OOS 分别输出 | 建议 agreement ≥ 0.90、coverage ≥ 0.90、false-feasible = 0；这不是已批准阈值 |
| 工作流检查 | 独立 scope + routing + use + regression 回执，不依赖世界通过 | 建议 median probe reduction ≥ 1，false admission = 0，所有可解任务保留 |
| 回归 | 旧 q6、q7 保持可解且探测不超过 4、5；q8 不超过 1 | 原任务现在是公开回归，不是隐藏发现证据 |
| 域外 | 不支持的源、无效输入、超出声明版本等必须明确 abstain | 参数适用范围尚需在候选中显式表达，不能只靠源标签证明完整域外识别 |
| Agent 比较 | Raw / text / unqualified executable / qualified executable | 相同模型、历史、工具、任务和费用；Raw 也可写代码 |
| 非 Agent 控制 | exhaustive reference、C 降序、ESR 升序 | 单独报告，不冒充第五个同模型 Agent；其本地计算和实验成本仍计入 |
| 成功 | 正确诊断、按时交付、电气/资源可行、同任务同设计的合法证据 | 物理通过与合法提交分列；缺证据不算 VMS |
| 主效应 | 首次合法成功的实验数、token、模型费用和本地成本；失败与停止完整保留 | 小试验不做“统计显著提升”结论 |
| 统计单位 | 当前：一个独立任务对的描述性案例 | 正式论文：独立任务族或完整 learning campaign，不能把 turns 当独立样本 |

世界模型的解释 gate 与工作流排序的效率 gate 不是同一个分数。两者各自可以被拒绝，
也各自可以通过。只有二者实际被公平激活并交叉评估，才能讨论 joint benefit；当前
两个独立检查器并不等于已完成 2×2 因果实验。

## 4. 数据划分建议：先冻结生成规则，再封存具体任务

1. **Development**：已有公开 v2 条件与允许进入历史的失败/干预。旧最终结果不再隐藏。
2. **Q3 / Q4 qualification**：两批互不重复的新条件，分别用于候选选择。Q3 的反馈一旦
   交给 G4，就属于开发反馈，不能再作为 G4 的独立最终证据。
3. **Regression**：旧 q6/q7/q8、无需更新与已知失败边界。结果不能回流给提案 Agent。
4. **Out-of-scope**：冻结输入规范和域外测试；不支持的物理实现只检查弃权，不编造参考真值。
5. **Blind transfer + final confirmation**：一个新的设计任务和一个不公开的确认条件。
   同一候选设计目录，但不同物理条件；全部条件的提交封存后才开启 confirmation。

每条任务都要完整列出源、初始状态、负载时序、模型/标签、接收条件、deadline 和
候选设计，绑定 environment hash。不同名字、session 或顺序不算不同物理任务。
现有 exact-hash audit 不证明近重复独立性；负责人应在不知道 outcomes 的情况下
审阅生成规则、机制覆盖和近邻排除规则。**本文件没有替负责人生成隐藏集。**

建议有限目录包含 ≤ 4 个设计，每个 Agent 试验最多 6 回合、4 次实验；为代码使用与
提交留出回合。此设置只是初始可行性试验，不称为 long-horizon。若正式任务需要更多
设计或回合，应显式改协议与预算，不在运行中静默增大。

## 5. 费用与执行时长：现金不是当前唯一约束

原 SQLite 账本在本轮以只读方式核对：

| 资源 | 已使用 | 原工程上限 | 剩余 |
| --- | ---: | ---: | ---: |
| 模型调用 | 63 | 120 | 57 |
| tokens | 463,487 | 600,000 | 136,513 |
| 计费上界 | ¥1.463445 | ¥19 工程保护线 | ¥17.536555 |
| 未结算调用 | 0 | 不允许带未知结算继续 | 0 |

用户要求仍是每试验不超过 ¥2、全部费用严格低于 ¥20。上述价格数字来自原账本的
保守计价，不是本轮查到的实时价格或实际账单。原执行窗口已经结束；新窗口需要批准。

一个完整的候选→五条件→移除/移植小流程，模型调用的预留数量可达：

| 阶段 | 最坏调用数提案 |
| --- | ---: |
| G3/G4 语义提案，各加最多两次机械修复 | 6 |
| 四个模型条件 × 每条件 6 回合 | 24 |
| 额外 removal 与 fresh-session transplant，各 6 回合 | 12 |
| 合计（不含确定性 Oracle） | 42 |

42 小于剩余 57 calls，**但这不能证明 token 预算够用**。原 Provider 每次预留
`请求 UTF-8 字节数 + 2048 + 4096` tokens，仅固定部分乘以 42 已达 258,048，
高于现有 token 余量；历史平均调用也约为 7,357 tokens，不能据此保证未来均值。
实际结算会释放多余预留，所以这不是“必定耗尽”的证明，却足以说明无法事前保证
整个矩阵完成。单纯看到现金剩余很多就启动完整研究是不合理的。

**建议的批准方式**：

- 首选审阅并批准分阶段的可行性 pilot：保持原账本/现金/调用/token 上限，先 G3 与
  离线检查；检查实际请求大小和剩余额度后才决定矩阵是否能完整运行。预算不够就
  记录未完成，不能只报告先跑完的有利条件。各条件按冻结轮转顺序调度，需要相应
  campaign 层支持；当前单矩阵执行器仍按固定条件序列执行，不能假称轮转已实现。
- 如果要求一次性承诺完成全部配对条件，则需要负责人**显式批准新的 token/call
  工程额度和执行窗口**，仍保留原账本、每试验 ¥2、总费用 < ¥20。现有 guard 不会
  自动接受额度扩展，需要先修改协议兼容路径并验证。这不是重新开始计费。

没有对这两种方式作出选择前，不进行新的付费调用，也不读取密钥。

## 6. Removal 与 transplant 怎么定义才不是重复演示

- **Removal**：保持任务、公共历史、模型、预算与工具不变，只去除那一项程序及其
  自动执行结果；同等预算允许 Agent 自行写代码。若其行为已经与 Raw 完全相同，
  必须显式标记是已有对照的复用，不再把同一条记录伪装成独立重复。
- **Fresh-session transplant**：新 session 接收封装程序、适用范围和公开任务，不接收
  来源会话。与另一个不带程序的新 session 配对；不能拿“有历史的作者”当基线。
- 当前主矩阵已有相同历史的新 session 隔离，但它本身不证明“不带原始历史的知识
  移植”。后者需要上述额外配对和独立成本记录，尚未实现完整调度。
- 另一模型不是本轮必需条件，不在固定模型研究中偷偷换模型。

## 7. 正式执行前，负责人可逐项检查的一个样例

现有 `scripts/build_b2_provider_control.py` 会生成明确标注为**模拟传输**的完整链。
通过 `docs/b2-development/provider-trial-control.json` 定位，不要访问或展示 API key。

依次检查：task / prompt → 模型 action → experiment receipt → 原始 RunBundle →
下一轮 observation → submission 的 evidence_hash → learning-frozen 屏障 →
confirmation → admission → Studio 对应轨迹。再杀掉子进程检查同一结算是否被重用。

该样例是执行器教学和审计材料，不是待发表的 Agent 结果。正式批准后也应保留同样
可追溯链，同时加入实际 provider usage、候选生成来源、学习成本和资格成本。

## 8. 明确的 stop / claim boundary

重复候选、机械修复耗尽、模型身份变化、原账本未知结算、预算不足、隐藏泄漏、
不完整成本或独立科学检查失败，都停止相应阶段。不得修改阈值、重抽隐藏任务、
替换基线、把工程候选改名 G3/G4 来获得通过。

如果没有新任务收益，保留负结果；如果简单排序已解释收益，就把结论限制在排序，
而不是归因于物理知识增长。如果运行通过但没有独立信息源，只能谈当前计算参考
环境；实测电流、BLE 日志与充电轨迹来自不同 session，不能拼成一次硬件闭环。

负责人最终需冻结：**研究主张、具体数据划分、阈值、基线、统计单位、共享额度和
新执行窗口**。工程哈希在这些决定及最终实现稳定后生成。任何审批必须绑定完整
协议内容；本提案以及测试夹具中的 approval 字段都不能替代真实授权。
