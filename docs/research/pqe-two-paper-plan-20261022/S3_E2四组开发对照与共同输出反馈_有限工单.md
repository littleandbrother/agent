派发：`BF-PQE-S3-E2DEV-20261023-001`；总派发：`BF-PQE-20261022-001`。本包落实已批准方案 S3-01、S3-04/05 的开发比较部分，连同 S2 剩余真实行为问题继续评价。S0 统一安排 A/B。全仿真，自动化仍暂停，不 commit/push。

## 1. 审查结论与推进理由

M3 已审收口：局部 P 上界 1.794395V 小于 2.2V 启动门限；全合法几何乐观上界 1.925295V 大于最低门限 1.9V，完整可行性仍 UNKNOWN。generic 当前设计 FAIL 有据，全域排除未建立；full_h 完整响应 JSON 解析错误，没有候选消费和物理判定。两组均没有实际 P 修改。原始结果和费用保留，不补跑原 M3、改写它的输出或转移余量。

此前局部修复已能运行，P 编译入口已有软件证据。当前核心缺口是：同一公共输出协议下，四种完整方法究竟作出哪些动作、服务结果和范围判断。阶段二的 P 行为出口仍开放；推进可独立进行的阶段三对照，不等于宣称阶段二完成，也不要求先制造一个 P 正例。

这次使用既有开发案例是为了补齐首次四条件匹配比较，**不是未见迁移或原两组的救援**。旧协议数据不并入新主比较。无论结果为何，12 格后结束这个开发批次，不再用同题先导追正例。

**假设：**公共接口恢复后，四种决策策略可以在相同工程事实与权限下比较；full_h 是否改善完整服务、错误采用/范围判断或执行成本是待检验问题。

**反驳与负结果：**持平、基线更好、所提策略增加成本、仍被协议错误阻断或根本未采取范围动作均保留。语法反馈可用不等于方法贡献；不能把没有执行当物理失败。

## 2. S0/B：一次共同输出反馈修复，随后直接执行比较

现有 episode_methods 只反馈已解析 JSON 的字段合同错误；pilot 将 JSON 语法与传输异常合为 PARSE_OR_TRANSPORT_ERROR。仅修这个已定位的共同路径，适用于所有四组。

- 只对**完整正常 stop、身份确定、usage 已 SETTLED**的模型公开输出提供语法诊断（错误种类、行/列、公共返回合同）。同一次输出没有被接纳、没有物理执行，原文原样保存。
- 模型可在剩余共同预算内自行重新提交；语法和字段错误共用原“最多两次连续纠正机会”的上限，不能各增加一套。所有请求、时间、tokens 和费用照计；合法动作之后才按已有规则清零。
- 不修逗号、不抽取半截候选、不自动把 observe 改为 edit，不替模型补字段、选规则或增加预算。若模型继续停或错误，正常保留终态。
- 传输中断、缺用量、上下文/工具权限异常、非正常 stop 不进入语法恢复路径；遵守原停止规则，绝不扩大 R11 历史例外。
- 生成、选择以及 Update 若有可恢复输出错误，使用同一边界；科学执行完成后的 Update 重试不得重复执行刚才的工具。修复范围以实际调用路径为准。
- 共同 schema/合法示例保持方法中立，不加入 M3 修复参数或全域判断答案。记录新协议版本，旧 M3 不回写或重新消费。

一次离线定向验证覆盖：完整语法错误后的模型自行重提、字段错误共同计数、两次额度耗尽、usage/传输异常不恢复、Update 重提不双执行。可以用保存的错误形状作 fixture，但不能将旧错误文本改好后冒充实际 Agent 行为。最多两次有理由的实现修订，无单独付费格式探针，入口可用即进入下面批次。

## 3. B：冻结四种可执行条件

沿现有 H/episode 入口实现 P1-B0 强通用、P1-B1 固定顺序、P1-B2 同表示普通反馈、P1-B3 full_h。Task、Problem、事实、工具、全球合法动作、外部评价与预算共同。

- B0 可以主动观察、联合修改、解除暂固定选择；不人为削弱。
- B1 固定的是公开声明的决策顺序，须有实际调用/选择轨迹；不能只起一个 fixed_sequence 名字而没有规则，也不能删除合法动作伪造策略差异。顺序在任何本批输出前冻结。
- B2 使用相同表示和公共信息，普通反馈决定下一步；不额外输入所提因果程序或更多历史。
- B3 复用现有 Generate/Select/Update、解释/预测/P 策略，不注入开发者的 M3 纠错答案。
- 同模型、同推理/温度设定、共同基本指令与纠错合同；条件差异明确列出。若 B0/B2 在实现上实质相同，先准确说明并实现计划中的策略差别，不能用相同代码标签充当独立基线。

仅检查新增差异路径。已有装置、公共隔离、费用与缓存机制复用，避免重新全仓资格。审查表不取代真实执行。

## 4. A/S0：冻结三个既有 DOOR 开发问题

使用同一当前科学消费者版本，固定以下三题、初始 Design/P 和所有服务条件。每题四组看到相同资料和共同初态结果，任何旧候选答案、私有终评、其它组轨迹不进入参与者上下文。

| 问题 | 固定选择 | 要比较的实际判断 |
|---|---|---|
| M1 局部控制 | D15 已有 volatile 初态，原运动/服务不变 | 是否以局部持久状态修复保持完整服务，避免无依据重构；不把它称为全部 NVM 故障覆盖 |
| M2 供电—程序耦合 | D07 已有 TX 时重启初态，当前 DoorProgram 消费 | 是否查看突发/掉电与事件后果、选择相关动作；该题可能可局部解决，不预称必须联合改多个变量 |
| M3 范围控制 | 原 M3 已冻结半速 Task、Design、P、公开源端界原样 | 是否区分局部界/全局 UNKNOWN，实际解除相关选择，或作出有依据的停止 |

精确匹配当前科学输入的初态直接复用；旧消费者版本的结果不伪装为当前结果。最多三次新共同初态仅用于确有输入变化或缺失缓存的题，禁止重新扫参找更有利题。若某题输入不合法或机制不再出现，单列未执行原因，不偷偷换题补格，不阻塞独立题。三题都是已公开的开发材料，不是最终测试集。

同一 Task 的四条件顺序按一次事前确定的平衡顺序执行；不看前组结果改后组方法/提示/输入。可以共享科学精确输入缓存，但只有参与者自主提交该输入后才返回对应结果，不能把前组答案提前提供。保留每组独立决策成本、缓存命中与共同数值来源，不能把共享物理结果当独立重复。

## 6. 分工与并行

- **S0：**一次研究/资源声明、共同接口集成、三题四组冻结与实际执行；单写 execution-state，完成后通知审查。
- **A：**三个当前输入的机制与消费者对应、初态精确复用；按同一事前标准核对已执行候选的事件—供电—接收及解释范围。已有原始数据足够就离线复核，不另开数值资格轮次。
- **B：**共同输出反馈与四条件策略，入口冻结后整理实际方法差异、全部失败和两稿短结果。可随后在原授权范围内整理 G 的公开经历输入与实现设计；本包不另运行 H/G 形成或目标任务，不向方法形成开放未来迁移测试。

一名 owner 一次只负责一个实现包；跨 owner 独立工作可并行。没有必要新增会话或新的常驻角色。
