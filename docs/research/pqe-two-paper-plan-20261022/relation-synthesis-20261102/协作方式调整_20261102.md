# 协作方式调整与本轮真实卡点

本记录只整理协作方式和已保存结果，不授权新实验；原工单、科学条件和预算不变，旧任务及自动化保持暂停。

## 1. 最合适的工作方式

采用**完整工作块并行、固定接口汇合、总管连续执行、审查异步核证**。减少“审查→总管→执行者→总管→审查”的同步往返。

| 角色 | 独立完成的工作块 | 对外交付 |
|---|---|---|
| A 工程 | 共同执行接口、可信消费者、输入和服务事实、原始后果 | 可运行入口、版本、结构化结果及独立服务核对 |
| B 方法 | 完整的状态读取、候选生成、选择、结果更新流程 | 可运行控制器、直接路径证据、真实决策轨迹及方法核对 |
| S0 总管 | 任务/版本/预算冻结，接入共同运行器，连续运行，合并出口 | 一份权威执行状态、结果总表、费用和报告索引 |
| 审查会话 | 科学问题、比较公平性、核心机制和结论范围 | 里程碑审查；普通实现修订不逐项等审查批准 |

共享版本化文件作为事实来源。消息只通知交付可用、完成或唯一具体阻塞；不复制整段历史，不要求相互确认。一个人同一时刻只维护一个实现。结果前固定任务与算法；结果后如需改方法，另记版本，不能覆盖旧结果。

每个工作块从输入一路完成到可复验输出，避免只交一个函数后让总管补完全部集成。阶段性汇合只发生在真正的数据依赖处。A/B完成后可并行核对服务与方法/成本；总管不再逐份重写相同报告。

两篇论文共享执行和证据层。论文一的设计方法有效性、论文二的经验学习增量是有先后依赖的两个问题；第二篇不能仅靠另开一组会话与第一篇齐头堆实验。

## 2. 计算耗时不是本轮主要工作量

105个新完整单工况合计257.272837秒，即约4分17秒；四条模型轨迹共31次已结算请求。仿真本身很快。提速重点应是减少交接等待、重复接入与反复准备，同时让完整可运行工作块尽早进入真实执行。不能把其余全部耗时归因于消息：实现、模型读取推理、集成和审查也都占用时间，本轮没有逐项墙钟因果分解。

## 3. 本轮结果揭示的方法卡点

12条预定轨迹已全部执行。强通用Agent在两个门体、两个冷链轨迹中均首个新设计完整通过。普通联合搜索门体均首评通过、冷链均六评未过。关系方法门体均第四评通过、冷链均六评未过。当前没有关系方法评价效率优势。

关系方法在门体上的四步完全可读回：

| 次数 | 储能/阻抗 | 持久化 | 启动门限 | 三工况完整后果 |
|---|---|---|---|---|
| 1 | 100→257µF，5→0.1Ω | 关 | 2.2V | PASS / FAIL / FAIL |
| 2 | 回到原100µF、5Ω | 开 | 2.2V | PASS / PASS / FAIL |
| 3 | 保留原100µF、5Ω | 开 | 1.9V | PASS / PASS / FAIL |
| 4 | 再加回257µF、0.1Ω | 开 | 1.9V | PASS / PASS / PASS |

第2步重新从初态展开，丢掉第1步的供电修改；到第4步才把已发现的几项改动合在一起。公开事实确实改变了行动，但实际行为仍接近串行修补。一个intent内部的静态配套扩展，并不自动等于把多个尚未履行的运行服务合成为整体设计。

强通用Agent则首个设计就同时改变多项变量。在冷链两次成功设计中，共同改变面积25→50cm²、电容0.012→0.05F、ESR8→0.1Ω、启动2.5→2.3V、记录容量2048→4096和ACK/重试配置，保持原采样服务。只能说整套方案有效，不能据此说其中每一项都必要。

## 4. 核心机制与结论边界

新代码已经从实际组件事实检查出“启用保持器但无人读取”，再生成读取配套；这条静态调用链不是原来的固定整套补丁。但正式比较中，所有实际选中干预都没有引入新组件职责；门体最终成功设计全部holder off。LC尚无对应设计事实适配器，只执行当前诊断探针。因此，**静态配套合成已经实现，动态收益尚未被证明；本轮也没有证明强Agent会因半成品低分而放弃有效联合方向。**

这两类问题必须分开：协作效率通过减少串行往返改善；方法价值仍需实际比较回答。不能用更流畅的调度、更多日志或图表，替代算法增量。
