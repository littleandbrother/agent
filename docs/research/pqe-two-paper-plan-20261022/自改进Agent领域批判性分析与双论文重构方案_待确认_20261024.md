# 自改进 Agent 领域：真实进展、证据缺口与值得做的问题

## 外部文献批判性分析，以及两篇论文的重构建议

**版本：待用户确认，2026-10-24。所有工程、实验、调度和自动化保持暂停。本文只交付阅读判断与研究提案，不构成恢复执行的授权。**

本文主要审查别人已经公开的工作，不是核查我们自己的论文。范围是：Agent 工作流程优化、自动程序与算法搜索、经验学习、改进器学习，以及它们在科学和工程设计中的应用。覆盖正式发表论文和最新 arXiv 预印本，二者在文献表中区分。这里讨论的是这个交叉领域，不能用这个样本代表全部 AI 研究。

## 1. 我的总体判断

**这个领域已经实现了有价值的自动程序搜索、工作流程修复和有限经验迁移；“系统能够稳定地提高自身改进能力”的证据，明显落后于这个领域使用的语言。**

最常见的问题不是分数凭空捏造，而是把一项较窄的成功解释成更大一级的能力：

| 实际观察 | 可以支持的判断 | 还需要额外证明的判断 |
|---|---|---|
| 增加格式检查、提交提醒后，任务通过率提高 | 运行流程更可靠，原模型能力得到更充分发挥 | 系统学到了更强的领域推理能力 |
| 生成很多程序，挑出的程序更好 | 搜索找到了更好的程序 | 产生候选的机制本身学得更好了 |
| 用旧经历改写提示或代码，新题成绩提高 | 在该划分下，经验加工与复用有效 | 已学到跨机制通用的改进原则 |
| 后期版本比早期版本更好 | 累计开发产生了收益 | 每单位资源的改进能力持续提高 |
| 自动生成了若干代“改进器” | 存在程序修改的谱系 | 存在可靠的递归自改进 |

我不接受把这些层级直接连成一句“系统已经学会自己变聪明”。但也不接受反过来把所有成果都说成“套壳”：**一个简单的搜索流程如果产生了以前没有的、可独立验证的算法，它的研究价值可能高于一个概念非常复杂、却没有排除简单解释的 Agent 系统。**

真正需要批评的是三种情况：

1. **贡献对象错位。**主要成果是补齐执行流程，论文却把重点放在通用认知、自主科学或递归能力。
2. **比较对象错位。**新方法得到了更多调用、额外反馈、参考结构或更易改造的起点，却把差异全部归因于所提机制。
3. **评价对象错位。**评价的是最终分数、分类准确率或候选中的最好值，却声称证明了原因判断、行动选择或自我改进效率。

这三类问题比“用了大模型 API，所以没有创新”更值得认真追究。调用 API 是实现手段，不能直接决定学术质量；**有没有回答一个此前不清楚的问题，实验能否把竞争解释分开，才是关键。**

## 2. 先把几个被混用的概念拆开

### 2.1 “自改进”至少包含四种不同事情

**第一种：修理执行流程。**例如避免空补丁、在超时前提交、修复输出解析。它能显著提高可用性，但往往是在释放基础模型原本已经有的能力。

**第二种：改进任务程序。**例如找到更好的矩阵乘法、控制器或搜索启发式。这可以产生真正的新知识，即使负责搜索的程序始终不变。

**第三种：从经历中学习以后的决策方式。**例如学到在什么条件下应该扩大设计范围、什么时候应该保留原方案。这要在未用于形成或选择的方法评价任务上体现出来。

**第四种：提高“产生好方法”的能力。**即新改进器在相同起点、相同历史和资源下，比旧改进器更容易形成有效方法。它比“后代程序分数更高”多了一层需要证明的东西。

记忆、代码、提示、模型权重都可能改变一个系统的行为。**不能规定只有改权重才算学习，也不能规定改过代码就一定比更新记忆更高级。**应当追问：哪些条件下，系统的选择改变了；这种改变是否带来了可重复的收益。

### 2.2 “递归”有程序结构含义，也有能力含义

程序允许修改负责修改自己的代码，这是结构性质。修改后，产生有效后代的能力提高了，这是经验结果。进一步证明这种提高能跨起点、跨任务、在计入全部成本后持续出现，是更强的研究结论。

很多论文把第一个性质作为系统设计，把第二个性质作为愿景，再用任务分数上涨连接二者。连接可以是有希望的，但不能省略实验。

### 2.3 这不是从零出现的研究方向

“提出程序—执行检查—根据反例再修改”有明确的程序综合传统；“维护候选群体、保留优良个体”有程序进化传统。LLM 带来的重要变化，是候选生成器具有很强的代码和语言先验，能够接收复杂反馈，而不是反馈循环第一次被发明。可参照 Solar-Lezama 的 [CEGIS 讲义与历史说明](https://people.csail.mit.edu/asolar/SynthesisCourse2020/Lecture10.htm)。

区别也要说清：形式化综合中的反例，可能在声明的逻辑范围内排除一类程序；一次自然语言批评一般没有这种保证。把二者都画成反馈箭头，不会让后者自动获得前者的正确性。

因此，一篇新论文至少应明确：它改进了**搜索空间、候选生成、反馈利用、选择规则、适用域判断或成本分配**中的哪一项，以及这个改进怎样超出了已有方法的重新组合。

### 2.4 把 Agent 热词拿掉，很多问题已经研究了几十年

| 今天常见的说法 | 已有研究脉络 | 对新论文的实际要求 |
|---|---|---|
| 根据任务选择最合适的策略 | Rice 的算法选择问题，1976 年已有明确表述 | 说明选择对象、输入特征与学习机制的新部分，而不能只把算法改名为 Agent |
| 学会选择或产生启发式 | 超启发式研究区分启发式选择与生成 | 与同资源的策略组合、自动配置和生成方法比较 |
| 决定要不要再思考、再试一次 | 理性元推理按对下一步决策的预期价值分配计算 | 检查额外思考是否真的改变有价值的行动 |
| 学会改进学习方法 | Learning to Optimize 等工作学习优化器，并研究对新任务的泛化 | 区分记住好的答案、好的起点和真正更好的优化过程 |

这些对应关系可从 [Rice 原始论文](https://www.sciencedirect.com/science/article/pii/S0065245808605203)、[Burke 等超启发式研究综述](https://people.cs.nott.ac.uk/pszrq/files/HHSurveyJORS2013.pdf)、[Russell 本人的研究说明](https://aima.eecs.berkeley.edu/~russell/research-bo.html)和 [Li 与 Malik 的 Learning to Optimize](https://arxiv.org/abs/1606.01885)核对。

甚至“用学到的优化器训练新的优化器”，2020 年已有具体实验。那篇工作把它谨慎类比为编译器能够编译自己，并没有因为完成自举，就证明无止境能力加速。[Metz 等，§4.6](https://arxiv.org/html/2009.11243v1)

**当代 LLM 的真实新条件，是它能够以自然语言和代码处理更广泛的候选与反馈。**这改变了工程可行性和搜索先验，但不会使算法选择、元学习、反例综合的历史消失。

所以，本报告后面提出的“条件化干预”“修改范围选择”，也不能仅凭名称自称全新理论。真正可争取的新颖性应来自：间歇供能的事件与服务耦合带来了什么旧方法没有处理好的决策结构；我们怎样具体利用它；收益能否超过传统选择器和普通模型搜索。若这三点没有成立，换一套词汇也救不了论文。

## 3. 逐篇看：哪些进展成立，哪些叙事走得太远

以下判断针对所列版本和实验，不是对作者或整个研究团队作评价。每个条目都保留值得借鉴的部分，也指出最有辨别力的补充对照。

### 3.1 ADAS：代码空间确实更灵活，但“可表示”不能推出“能学会”

**论文实际贡献。**ADAS 用元 Agent 编写新的 Agent 程序，并借助历史候选与评价继续搜索；论文有跨任务、跨模型的转移实验，不能简单说只是同一题上调提示。[正文 §3—4；ICLR 2025 发表记录](https://proceedings.iclr.cc/paper_files/paper/2025/hash/36b7acf6f6010652b3f2a433774a66fe-Abstract-Conference.html)

**最需要警惕的推论。**其摘要与引言用编程语言的图灵完备性，说明代码搜索原则上覆盖任意 Agent 系统。[审读版本 §1](https://arxiv.org/html/2408.08435v2)

我的判断是：这说明**表示语言宽**，并没有说明有限预算下的搜索概率、可发现性和评价能力。一个空间能够容纳好算法，并不意味着现有提案器有合理概率找到它。事实上，空间越开放，可靠搜索和验证可能越困难。

**保留的价值：**让自动优化越过固定提示模板，修改真实控制流程。**尚未解决的问题：**与成熟人工流程、同成本普通代码搜索相比，哪些结构性变化可迁移，哪些只是更多调用或更好的提示。

最有价值的补充不是再列几个新 Agent 名字，而是把发现的流程放到更强、更完整的公共起点上，测其独立增量。

### 3.2 TextGrad 与 GEPA：文本反馈优化是真进展，“梯度”与“超过 RL”都有条件

TextGrad 把自然语言反馈沿系统组件传播，再据此修改提示、程序或其他变量。它提供了一套有用的优化接口；这里的文本“梯度”是引导修改的反馈，不具备通常数值梯度的全部数学性质。[TextGrad 方法 §2](https://arxiv.org/html/2406.07496v1)；[Nature 发表页面](https://www.nature.com/articles/s41586-025-08661-4)。

这类接口的研究价值在于：**把跨组件的反馈组织成可执行优化过程**。但“看起来像反向传播”不能替代信用分配的正确性证明。同一句批评传到多个模块，仍可能把问题归错位置；效果应由干预后的表现确认。

GEPA 进一步把执行轨迹、反思修改与候选保留结合起来。其报告包含与 GRPO 等方法的比较，以及明显更少的 rollout 消耗；主表也存在 AIME 这样的例外。部分任务反馈含相关文档等丰富信号。[GEPA，Table 1、方法与任务反馈附录](https://arxiv.org/pdf/2507.19457v2)

我的判断：这是值得认真比较的优化方法，不应被轻视为“只是提示词”。但**少用完整任务运行，不等于全部训练、反思和部署成本同比减少**；固定模型和反馈条件下优于某种 RL 配置，也不能推出文本优化普遍取代权重学习。

需要分开比较三件事：同样反馈下谁更会优化；同样总资源下谁更有效；形成后在新任务上谁更可靠。对这三件事回答不同，完全可能同时成立。

### 3.3 DGM：有真实可迁移改进，但最终分数不能单独证明改进机制更高效

DGM 修改 Agent 的代码与运行组织。论文报告：SWE-bench 中一个完整搜索运行估计约 22,000 美元，两项消融各约 10,000 美元；作者明确承认这个差异。它也有有意义的跨基准证据：SWE-bench 上形成的 Agent 转到 Polyglot，报告成绩从初始 14.2% 到 28.9%。[§4.4、附录 E.1](https://arxiv.org/html/2505.22954v3)

**我的判断：**转移结果足以反对“全是记住原题”的简单否定；代码与工具组织确实可以形成可复用改进。

但资源不相同的最终分数，无法独立回答：如果让固定改进器也多搜索同样的成本，它是否同样能达到该水平？也无法仅据任务能力提高，就推出产生改进的能力提高。一个更擅长完成修复任务的程序，未必更擅长选择下一种有用的自我修改。

**最关键补充：**在固定起点和总成本下，对比固定提案器、可变提案器及普通多候选搜索，画出达到共同目标所需的完整成本，而不是只比较各自预算末尾的最佳值。

这里不是说 DGM 的收益已经被“多花钱”解释完了，而是这项竞争解释仍需更直接的控制。

### 3.4 HyperAgents：比只展示世代曲线更进一步，但迁移实验仍混有起点差异

HyperAgents 在目标域中固定一个改进器，让它生成最多 50 个任务程序，再以验证结果选择后代、查看测试收益。这比“第十代比第一代高”更接近改进能力测量。不过 §5.2 写明，迁移时带过去的是**整个实现，包括改进器和任务程序**；初始目标域零分还涉及输出格式问题。[§5.2 与附录 D.3—D.4](https://arxiv.org/html/2603.19461v1)

**关键逻辑：固定改进器在一次运行中不再变化，并不等于比较时被改进的程序起点相同。**两个起点都得零分，也可能一个只差解析器、另一个需要重建控制流程。相同初始分数不能保证相同改进难度。

因此，这项证据支持“迁移后的整套系统更善于形成有效程序”，对“改进器本身学到了多少独立能力”的归因还不够干净。

**最有辨别力的补充是交叉交换：**旧/新改进器分别作用于旧/新任务程序，统一历史、允许编辑范围与总资源。若新改进器在两个共同起点都更有效，元层能力的证据才明显加强。

另一个问题是成熟起点：应检查收益能否在已经处理好格式、日志和基础工具的任务程序上继续存在。自动补齐这些能力有价值，但它与新的领域推理能力需要分开计量。

### 3.5 RSIFlow：必须区分论文设想、公开版本和真正改变的行为

RSIFlow 研究任务系统与元层经历的联合更新。公开仓库明确说明：当前发布的是技能记忆版本，Meta 的可执行程序保持固定；代码包含记忆检索与维护入口。论文也报告了元层不同阶段从共同任务模型起点进行改进的结果。[论文](https://arxiv.org/html/2610.21791v1)；[作者仓库 README](https://github.com/1HUAN1/RSI-Flow)；[技能记忆实现](https://raw.githubusercontent.com/1HUAN1/RSI-Flow/main/RSIFlow/skill_memory.py)。

这并不能直接证明论文没有自改进：**同一程序读到不同记忆，完全可能执行不同改进策略。**程序不变不等于政策不变。

真正的缺口在于：经验内容增加、检索改善、策略改变，分别贡献多少？公开版本又能复现论文中哪些机制与结果？如果只展示后期 Meta 更有效，但后期 Meta 同时拥有更丰富的任务经验，就还没有把“更会改进”与“掌握了更多答案线索”分开。

需要给旧改进器同一份新历史，再与新改进器比较；还应把条件规则、检索记忆和真实运行行为接起来，检查规则在不适用任务上能否正确不触发。

**我的结论：**该工作有可研究的经验复用设计；当前公开代码不能被笼统描述成“已公开元程序不断改写自身的完整实现”。同时，也不能仅凭代码固定就判它的经验学习无效。

### 3.6 Self-HPO：很多“能力增长”首先来自工作流程不再丢失已有能力

Self-HPO 交替优化运行流程和模型策略；主结果报告组合优化优于分别只优化其中一项。其公开案例中的流程改变包括超时前提交、避免空补丁、检查接口和提交回退。[方法、主结果与 Figure 5/附录 E](https://arxiv.org/html/2610.22791v1)

这些修复非常实用。一个已经会写正确代码的模型，如果经常没把代码交出去，补齐提交流程会显著提高分数。

但这也提出一个必须回答的问题：**新方法究竟增加了多少新的求解能力，又恢复了多少原来被执行缺陷浪费的能力？**二者都值得做，却对应不同的论文贡献。

最有价值的对照，是先为所有组补齐通用提交、解析和超时处理，然后比较联合优化的剩余收益；另外比较把同样总资源全部分给策略训练、全部分给流程搜索、交替分配的结果。

不能反过来断言这篇论文所有收益都是格式修复：它实际还训练了模型。这里指出的是归因要拆开，而不是预先否定联合优化。

### 3.7 MetaShare：并行更快可以成立，省计算与机制归因则需要另看

MetaShare 报告用更少代数达到各自最佳程序，但每代使用三个并行提案，作者明确说约需三倍自修改 token；部分领域的基线分数直接取自旧论文，没有在相同准入流程下重跑。[§4—5、Table 1、局限](https://arxiv.org/html/2610.21887v1)

**我的判断：**更少同步轮次是有用的工程结果，但不能自动写成搜索更省资源；“到达各自最好值”也不是“到达同一个质量目标”。历史基线可作背景，不能代替全部机制受控的比较。

这篇也做了值得保留的对照：把失败描述与对应后果打乱，检查配对语义是否有用。这样的实验比“删除整个记忆模块后下降”更有辨别力。

还有一个容易被忽略的边界：通过删除任务名称、语言后缀等文本，不能在逻辑上保证剩余代码语义不透露任务。所谓“对任务不知情”的审计器，最好有实际可辨识性检验。这里是对独立性保证的质疑，不是已经发现测试答案泄漏。

### 3.8 AdaMAST：它最有启发的结果，是诊断结构不总是收益来源

AdaMAST 学习故障分类，并用于搜索、运行检查和候选选择。附录 D.4 的等长度比较中，分类文本和普通摘要均为 72.3%，原始片段在部分长度下更高；附录 E 中，强制逐项检查故障会使 TheoremQA 平衡准确率降低 0.13—0.24。作者对这些现象有明确讨论。[Table 19、附录 E](https://arxiv.org/html/2607.16387v2)

**这是本次阅读最重要的启发之一：发现真实的过程缺陷，也可能作出错误的最终判断。**一个过程可以绕远路、犯过错、又成功恢复；批评这些缺陷没有错，把它们直接当成“任务失败”就错了。

因此，准确分类、压缩历史、预测最终成功、决定是否干预，是四个不同目标。一个表示可以适合前两个，却伤害后两个。

我认可它在表示压缩、跨使用方式评价和负对照方面的工作。不能据这个表否定它在其他用途中的收益；同样，也不能把总体系统收益全部归给分类名称本身。

**真正值得跟进的是：故障信息应在什么决策位置、以多大权重、触发哪种行动。**再丰富分类表，不一定继续推进这个问题。

### 3.9 “自演化很脆弱”的论文，也必须接受同样审查

《On the Fragility of Self-Improving Agents》对完整学习过程重复运行，报告任务顺序和随机性会放大部分记忆系统的性能波动。这是比只重复测试一个已选版本更有价值的检查，但研究范围主要是所测试的记忆系统，不能覆盖全部代码演化方法。[实验与讨论](https://arxiv.org/html/2608.18066v2)

《Rethinking Self-Evolving Agent Skills》有一个重要对比：SearchQA 中演化结果与并行 oracle 很接近，而 Spreadsheet 中演化优势明显更大。其并行 oracle 使用“多个尝试中只要有一个成功”的理想选择，不是可直接部署的单次系统。[结果与 oracle 定义](https://arxiv.org/html/2608.02636v1)

我的判断：这两类工作帮助拆除“学习一定比多尝试好”的假设；但不能把一个理想上界当成现实方法，再宣布学习无用。合理结论是：**有些任务的收益主要可由采样覆盖解释，另一些任务确有可复用流程的价值；选择器能否找到那个好结果，是独立瓶颈。**

批判性论文也可能因标题锋利而被过度传播。我们应接受其受控实验，拒绝把局部负结果扩大成整个方向的死刑。

### 3.10 SEAL：确实改变了权重，但一次适应成功不等于持续学习成立

SEAL 让模型产生训练数据或更新指令，再以更新后模型的任务表现训练这种生成能力。它包含真实权重更新。论文也明确报告：连续更新会损害此前任务表现，而且当前训练依赖与输入配套的下游评价任务。[方法 §3、局限 §5](https://arxiv.org/html/2506.10943v2)

这是不能被“都是外部套壳”概括的路线。它把“怎样组织新信息，才能让参数更新更有效”变成了可学习对象。

但一次新知识吸收成功，只解决了局部适应。持续学习还要考虑旧知识保持、无法立即取得标准答案的输入、更新成本和错误积累。把局部适应称为无限持续自学习，会跳过这些问题；作者的局限部分实际上比这种传播叙事谨慎。

**更深的困难是评价来源：**如果未来让模型同时生成训练材料与自己的考题，需要防止它只学会通过自己擅长出的题。评判机制的独立性不会因改了权重而自动成立。这个困难与代码演化中的自评循环相通。

### 3.11 SEVerA：形式保证可以完全正确，同时任务答案仍然大量错误

SEVerA 用形式化约束保护程序，并在无法得到合格生成时回退。GSM-Symbolic 的实例保证输出可解析；回退可返回表达式“0”。该任务表中，带参数优化的版本报告约束违反率 0、答案准确率 66%。[§5.4、Table 4、附录 L](https://arxiv.org/html/2603.25111v3)

这两个数字没有矛盾：**“保证满足约束”所保证的内容，是写进约束的性质，不是全部任务成功。**形式化保护有真实价值，但不能把“Verified Agent”理解成所有推理或工程结论都得到证明。

论文另以排除回退触发样本后的收益，说明收益并非只靠回退。这能排除一部分解释；但单独依靠它，还不足以把剩余收益全部归给专门程序结构，因为拒绝后重试、反馈和模型优化也可能起作用。[§6.4—6.6](https://arxiv.org/html/2603.25111v3)

值得借鉴的是它把约束满足与任务回报分开；需要继续审查的是保证范围、用户提供公理的可靠性，以及机制归因的对照。**不能因为有定理就不读定理前提，也不能因为保证范围有限就说形式化方法没有用。**

## 4. 工程与科学 Agent：结果是否真正在对象上成立

### 4.1 FunSearch / AlphaEvolve：系统外壳可以简单，发现本身仍然很有价值

FunSearch 的核心是程序生成、执行评价和候选保留，产物包括新的数学构造与算法。[Nature 原文](https://www.nature.com/articles/s41586-023-06924-6)

AlphaEvolve 将程序搜索扩展到更复杂的代码修改和多目标评价。一个需准确表述的结果是 4×4 矩阵乘法的复数乘法次数从 49 到 48；不能省略计算域，改写成对所有实现都同样节省实数运算。[AlphaEvolve，矩阵乘法结果与 Table 3](https://arxiv.org/html/2506.13131v1)

**我把这类成果看作领域中较扎实的进展。**原因不是用了最宏大的自主叙事，而是产物能在问题本身上核验：算法是否正确，目标是否真的更好。

但这种成功依赖人给出问题、程序表示与评价器。它证明了自动搜索能产出有价值的答案，不直接证明系统能自主选择重要科学问题，更不证明负责搜索的算法已经递归改善。

这里存在两条独立价值线：**发现的算法是否新而有用；发现过程是否比已有搜索更好。**前一条成立时，即便后一条归因还不完整，也可以是好研究。反过来，一个复杂 Agent 框架不能因为“自主程度高”就免除产物质量要求。

### 4.2 EvE：确有动态仿真中的控制设计，迁移与“物理解释”仍需准确命名

EvE 用可执行控制程序参与流体仿真，报告多次运行、对照与扰动测试。其 3D 任务使用保留的 2D 控制器继续优化，并非零反馈直接迁移；三维流体中的机体运动仍限制为前进、侧移和偏航。[结果与 3D 扩展](https://arxiv.org/html/2606.08405v4)

这类结果比只让模型写一份设计说明更有实质：候选实际改变了动力学后果。应承认这一点。

我不把“输出程序可阅读”自动当成“因果机制已解释”。一段代码可能包含有用规律，也可能混合了补偿项、冗余项和特定工况技巧。要证明哪个机制导致收益，需要有针对性的删项、替换和扰动，而不是仅给出听起来合理的解释。

评价迁移也应区分：旧程序直接使用；旧程序作为新搜索的起点；从旧任务学到更好的搜索方法。三者都是有意义的研究，但难度和结论不同。

### 4.3 RocketAgent：完成复杂工程流程，与证明 Agent 方法优势是两件事

RocketAgent 展示跨工程模块的执行与依赖管理。一个案例中，原最高比冲工作点的冷却候选没有可行项，沿事先允许的富燃方向调整后找到了可行候选；另一些受控测试在求解器启动前检查过期状态能否被阻断。[案例与受控测试](https://arxiv.org/html/2610.06044v2)

**我的判断：**这是实际工程整合能力，不能因为用到了成熟优化器就说没有贡献。授权内改变工作点也是合法设计行为。

但前者回答的是“在允许的设计取舍下能否找到方案”，后者回答的是“系统能否避免使用过期输入”。二者都不单独回答：这个 Agent 为什么比同工具的强通用方法、传统联合优化或工程师规则更好。

也不能把一个工作点失败说成整个任务无解。大规模补充仿真可以加强某些工程量的可靠性，却不会自动补齐方法层的因果对照。**工程有效性和控制策略优越性，要各自有证据。**

### 4.4 TopoSizing：问题范围较窄，反而更容易看清真正的方法贡献

TopoSizing 结合电路结构分析与搜索范围调整，在四个固定拓扑电路上与优化方法比较，每电路报告十次独立运行，并做模块消融。[方法与实验](https://arxiv.org/html/2509.14169v1)

这支持一个具体贡献：结构先验可能帮助尺寸搜索更快达到目标。它不等于自动发明了新拓扑，也不需要声称完成整个电路工程流程才能有价值。

最值得继续追问的是：相同的结构信息若由简单规则提供，是否已经取得大部分收益？LLM 是必要的推理部件，还是便利的先验提取器？两种答案都可以有工程价值，但创新点的表述会不同。

这个例子提醒我们：**研究问题清楚、对照扎实的窄方法，可能比“全自动工程科学家”式的大系统论文更值得借鉴。**

### 4.5 Long-Horizon Analog Design Bench：最有帮助的“经验”，可能已经是结构答案

该基准区分了多种经验条件。其中 Skill 8 提供与任务对应的参考电路拓扑，保留连接与层次，数值留待调整。对一个较强模型，在六小时条件下这项辅助的增益很小；对另一个模型仍明显。[技能定义与预算实验](https://arxiv.org/html/2609.33356v1)

这不是作者隐瞒泄漏：参考结构是被明确研究的实验条件。它揭示了一个重要事实：**经验可能通过直接消除搜索维度帮助系统，而不需要系统学到更好的搜索原则。**

参考电路复用在工业中很正常，完全可以很有用。但“借到正确拓扑后能调好参数”和“从经验中学会何时改变拓扑”是不同能力。

强模型、长预算下增益缩小，还提示我们：一种辅助方法的价值取决于基础系统本来有多强、时间有多充裕。不能拿弱起点上的巨大增益，直接预测成熟工程 Agent 上的长期价值。

## 5. 这个领域的八个深层矛盾

以下是基于上述证据形成的分析，不是作者原文结论。它们不是纯粹的文字游戏，而是会直接改变实验应该怎样做。

### 5.1 起点越差，“自改进”看起来越惊人

如果起点缺提交、解析、日志和正确停止机制，自动修复这些问题很容易获得大幅提升。这个结果是真的，但它可能意味着自动化了常规工程维护。

随着公共运行环境成熟，这部分提升空间会减少。于是，同一种方法在一个脆弱起点上很亮眼，在一个已经正常工作的起点上却没有增量。

**洞见：评价自改进能力时，需要把“补齐基本能力”的收益与“超过成熟起点”的收益分开。**不应故意削弱起点制造增长，也不应因为修的是基础问题就否认自动修复的价值。关键是准确命名，并检查收益是否能延续。

### 5.2 最佳结果一直上涨，可能完全不需要学习

只要不断产生候选，并保留历次最好的那个，记录中的最佳值天然不会下降。即使每次都是同一个固定生成器独立抽样，这条曲线也会呈现“不断进步”。

因此，世代曲线不能单独回答学习是否发生。需要比较：使用经历后的生成器，是否在新的相同难度起点上，以更少资源产生更好的候选；以及系统能否自行选到那个好候选。

**洞见：应把“积累了好程序”“更会产生好程序”“更会选中好程序”分别测量。**选最好不是错误，错误是把这三个效果都算给学习机制。

### 5.3 诊断越认真，行动可能越差

过程中的问题不都需要被修掉。有些错误已被恢复，有些绕路是探索成本，有些不完美与任务成功无关。过度强调这些问题，会让系统反复重构、丢弃有效方案或拒绝正确结果。

AdaMAST 的检查清单结果说明这种风险在实际实验中能够出现。更一般地，故障识别的目标与行动选择的目标不同：前者问“哪里不理想”，后者问“现在改这里，是否值得”。

**洞见：有价值的经验不是一份越来越长的错误目录，而是关于干预价值的条件判断。**它至少应包含什么时候适用、什么时候不适用、预期改变什么、什么结果会反驳它。

### 5.4 轨迹解释得再细，也不能凭空产生反事实证据

假设一次发送时电压掉了，导致记录未到达。储能不足、内阻过大、过早发送，都可能产生相似轨迹。仅凭同一条轨迹写十遍归因，并不能知道增大电容、降低内阻、延迟发送哪个真正有效。

这属于信息不足，不一定是模型不够会思考。要区分原因，需要能区分它们的观察、受控干预，或在适用范围内成立的必要条件。

**洞见：解释的质量取决于它能否改变下一项有辨别力的行动。**评价一个归因系统，不应主要看解释是否流畅、与专家标签是否一致，而要看它是否减少了错误干预，或以更低成本取得了区分原因的证据。

这里也不要求每条经验都升级为严格因果定理。对证据强弱分层，比把观察关联一律称为因果更实用。

### 5.5 验证器越强，成果越可信；但不一定更能证明自主智能

精确验证器能淘汰大量错误程序，使随机性很强的候选生成器也产生可靠成果。AlphaEvolve/FunSearch 的价值恰恰包含这种组合。

这说明成功可能主要来自“强先验生成器＋可靠筛选＋足够搜索”。它既不能证明生成器理解了发现，也不影响发现本身的正确性。

反过来，如果验证器只覆盖局部指标，Agent 可以持续提高这些指标而遗漏整体服务；如果验证器跟候选一起被修改，外部标准不固定，还会产生循环自证。

**洞见：产物正确性、搜索有效性、解释正确性、评价标准完整性，是四条独立证据链。**其中一条非常强，不能为另外三条代签。

### 5.6 经验迁移可能传过去的是答案、工具，或更容易修的起点

把一个好拓扑放进提示、把成熟解析器迁入新任务、把源任务程序作为目标起点，都可能明显帮助目标任务。这些都是合法的知识复用。

但要证明学到了通用改进方法，需要进一步控制：新旧改进器看到相同历史和工具，作用于同一个起点，还能表现不同。HyperAgents 的整套实现迁移与模拟电路参考拓扑条件，分别说明了这个问题的不同形式。

**洞见：迁移实验要说明究竟迁移了什么。**不能只因任务名字变了，就把所有收益解释成一般推理规则的迁移；也不能把有用的知识复用全部视为作弊。

### 5.7 “便宜”取决于分母，“更快”取决于终点

一次迭代可以包含一个提案，也可以包含多个模型、多个训练过程和大量候选。完成自己最好的结果，也不同于达到一个共同质量门槛。

应至少同时看：完整评价次数、模型输入输出、墙钟时间、离线形成成本和部署成本。不同资源不能在未说明价格与目标时强行压成一个数字。

**洞见：论文中的效率应表现为质量—资源之间的关系。**如果方法只是在更多并行资源下更快得到结果，就准确报告并行延迟优势。若要说长期节省成本，要说明需要部署多少次才能摊平前期学习投入。

### 5.8 能改代码，不等于知道应该改什么；能生成后代，不等于知道应该采用谁

代码编辑能力只是必要接口。系统可能总修改容易看见的短函数，回避真正决定行动的长函数；也可能产生有效候选，却因评价噪声或错误选择而丢掉它。

方法越自由，可改变的地方越多，归因与选择就越难。“允许修改整个代码库”扩大了空间，同时增加了无效修改和回归机会。

**洞见：开放空间的研究核心是如何形成有根据的干预与选择，而不是开放程度本身。**同样，递归深度增加只有在每一级确实改善了下一层的改进质量时才有科学含义。

## 6. 哪些是真进展，哪些还主要停在包装层

### 6.1 我认为已经比较扎实的进展

1. **程序生成与执行筛选的结合，确实能产生有用的新程序。**这是能力进展，不需要把底层模型也说成自我改造了。
2. **真实执行反馈通常比只有最终分数更有用，但使用方式决定收益。**GEPA、AdaMAST 等工作的价值在于具体优化和消费设计，而不是“反思”这个词。
3. **部分程序与流程改进能迁移。**DGM 的跨基准结果值得承认；迁移范围仍要按实验描述。
4. **完整工程对象上的闭环执行正在变得可行。**控制、模拟电路、复杂设计流程中已经有候选改变实际求解输入的工作。
5. **研究开始测量失败、退化、选择器和成本。**这比只给最佳截图更重要，哪怕它使结论变得不那么宏大。

### 6.2 我暂不接受的强结论

| 强结论 | 当前常见证据缺口 | 能让我改变判断的证据 |
|---|---|---|
| 自改进方法普遍优于更多采样 | 缺同成本固定搜索和真实选择器 | 在多个成熟起点上，以同资源稳定占优 |
| 已获得通用因果归因能力 | 主要验证标签或解释，没有干预区分 | 预先判断相反作用条件，实际干预后仍成立 |
| 改进器的能力已经独立提高 | 同时更换任务程序、经验和工具 | 共同起点交叉交换，新改进器仍有收益 |
| 经验是跨域通用规则 | 经验内含目标结构、目标反馈或同机制答案 | 形成过程未见目标机制，且有正确不适用样例 |
| 自改进正在稳定递归加速 | 只有谱系、最佳值和若干代数 | 多次独立形成后，单位完整成本的改进能力持续提高 |
| 系统会自主做科学 | 问题、表示、验证器仍由人给定 | 自主提出可检验且重要的问题，并获得独立验证的新知识 |

这些不是要求一篇论文解决所有问题。论文只需证明它真正声称的那一层。问题在于把低层证据拿来支撑高层宣传。

### 6.3 怎样判断“套壳”而不流于情绪

我建议把“包装大于实际”具体化为以下判断：

- 去掉 Agent/递归/元认知等名称后，是否还剩一个可准确描述的算法差异？
- 让强基线拿到同样工具、事实、候选数和时间，这个差异是否仍有效？
- 收益能否用成熟执行流程、参考答案式先验或更多采样解释大半？
- 论文有没有证明它最强调的机制，而不只是最终系统分数？
- 关键负结果、未执行格、无效候选和形成成本是否进入结论？

如果前两项没有清晰答案，后三项又没有控制，我会把它视为**科学贡献尚未分离出来的系统整合**，不会按通用方法突破来评价。

但这与断言作者“为了占坑”不同。公开材料可以证明推论不足、比较不充分或实现范围较窄，通常不能证明作者的动机。把批评落在可检查的问题上，才更有力量。

### 6.4 三个真正值得推进的研究洞见

**洞见一：从“识别错误”转向“预测干预价值”。**

新的研究对象应是：在当前条件下，改这个地方能不能提高完整任务结果，代价是什么，哪种结果意味着这条经验不适用。这样才把经验从描述变成了决策能力。

**洞见二：从“更多自由修改”转向“有根据地改变修改范围”。**

局部搜索与整体重构各有价值。关键问题是：什么时候局部修改已足够；什么时候当前范围无望；什么时候只是信息不足、应先试一个能分辨原因的动作。这个问题同时涉及工程约束和决策成本，不能靠“多想一步”解决。

**洞见三：从“后代最好分数”转向“能被可靠选用的改进”。**

学习过程要同时产出有效候选、正确适用范围和可靠采用决定。一个偶尔产生优秀程序、却经常错误采用退化版本的改进器，部署价值可能很低。应直接测错误采用、漏掉好改进以及最终保留方案的表现。

这三点都不是仅靠命名就成立的新颖性。已有工作涉及其中一部分。研究价值取决于能否给出具体方法和辨别性实验，并证明它超过同信息、同预算的普通程序搜索。

### 6.5 最容易被忽略的机会：把“反对意见”变成可操作的分辨实验

“可能只是更多采样”“可能只是起点更好”不能永远停留在质疑。好的研究应该把它们转换成几组能区分原因的操作：

| 尚未排除的解释 | 最直接的区分方式 | 不足以回答的替代品 |
|---|---|---|
| 更多候选带来最好成绩 | 固定生成器获得同样总资源，再用同一个真实选择器选结果 | 只报本方法最佳候选与基线一次输出 |
| 更好的被修改程序带来收益 | 旧/新改进器 × 旧/新程序交叉交换 | 两个初始程序分数一样就视为相同起点 |
| 经验直接给了结构答案 | 同历史普通检索、固定策略组合与所提学习比较；另留机制改变任务 | 改任务名称、改几个数值就称跨域 |
| 故障解释只是听起来合理 | 预先选择可区分原因的干预，检查相反条件中的结果 | 解释与专家措辞相似、模型自评更有信心 |
| 收益只来自常规运行修复 | 所有组先共享成熟运行能力，再比较剩余增量 | 用缺提交/解析能力的起点证明普遍智能提升 |
| 学习过程只是偶然选中一个好后代 | 独立重复形成，并评价实际采用结果及全成本 | 对同一幸运后代重复运行很多次 |

这些实验不必全部在一篇论文里做。应挑与核心主张直接相关的两三项。**与其增加十个指标，不如增加一个能推翻自己解释的对照。**

## 7. 两篇论文怎样据此重新定位

这一部分是从领域分析导出的待确认提案，不是对已有实验的重新包装。两篇分别回答“当前设计怎么修”与“以后怎样更会修”。第二篇不能只把第一篇换个学习名称。

### 7.1 第一篇：在耦合系统里，何时应该改变设计范围

**建议工作题目：**《何时扩大设计修改范围：间歇供能系统中的完整服务修复》。

**核心问题，用普通话说：**一个设备失败后，Agent 怎样判断应该改参数、改程序，还是同时改变采能与供电方案？怎样避免一个指标变好、整个服务却仍然失败？

**对象：**门体动能事件记录器是主案例；光供能状态标签提供第二种能量与信息关系。所有结论限声明的仿真模型。漏水案例当前不作为必须完成的主结果；是否保留为后续工作，需用户确认。

**拟研究的方法，而不是已有贡献声明：**

1. 从完整事件后果中找出阻断服务的关系，例如发送欠压、保存成功但交付迟到、暗区失去采样或时间语义。
2. 把修改范围作为实际决策变量：参数局部、程序局部、源—储能—程序联合配置；范围内调用共同搜索器。
3. 只有适用的必要条件才能排除一个范围；单个失败不能排除整类设计。证据不足时，选择能区分解释的有限干预。
4. 直接用完整动态执行评价新候选，先看全部服务，再比较成本。便宜计算只用于明确适用的界或筛选，不再另造一套不完整的队列模拟器。

**创新候选相对已有工作的区别：**

| 最接近的已有工作 | 已经解决的部分 | 我们需要额外证明的部分 |
|---|---|---|
| RocketAgent 一类工程整合 | 跨模块执行、依赖管理与工程优化 | 依据失败关系选择修改范围，是否真的优于同工具普通循环 |
| TopoSizing 一类结构先验优化 | 固定结构内，先验帮助参数搜索 | 在程序与物理设计耦合时，何时扩大范围，何时保持局部 |
| GEPA/一般程序搜索 | 用反馈改善候选程序 | 服务约束与干预范围的特殊结构，是否产生额外效率或正确性 |
| 传统混合变量优化 | 在既定空间内找高质量解 | 在线决定搜哪个范围、还缺什么证据，是否更值得；若没有，则承认传统优化更合适 |
| 算法选择与超启发式 | 依据状态选择搜索方法，组合或生成启发式 | 特殊的动态服务耦合是否要求新的状态与范围选择方式；不能把“会选策略”本身当首创 |

**不能当创新点的内容：**搭建平台、建立日志、给流程改名、使用独立检查、把几个工具接起来、生成可读解释。这些是完成可信研究的条件。

**第一篇的决定性实验：**

| 实验 | 真正要区分什么 | 对照与读数 |
|---|---|---|
| P1-A 完整服务与局部指标的分歧 | 方法会不会把“电压正常/接收数增加”误当任务完成 | 全服务通过、错误通过判断、修改后的新失效；所有组同样获得原始事实 |
| P1-B 修改范围选择 | 有依据的扩大范围，是否比固定局部或一开始全空间搜索更值得 | 强通用 Agent、普通反馈循环、固定局部流程、适用的混合变量搜索、所提方法；共同资源曲线 |
| P1-C 同表象、不同原因 | 方法是否真的使用了辨别证据 | 发送失败分别来自供电与时序等不同合法机制；测首个有效干预和浪费成本，不能把正确行动写在任务名里 |
| P1-D 反向条件与回归 | 有用修复能否在不适用条件下被拒绝 | 应保持原方案、局部足够、需要联合修改三类；测错误重构和原通过服务的退化 |

实验按问题组组织，避免每改一个参数就开新包。先执行最能否定核心假设的小规模比较；没有行动或服务差异时，不扩大相同矩阵。

**第一篇何时算有贡献：**不要求所有方法都赢，但至少应得到一个可复用的工程判断或范围选择机制，且在强基线、普通优化和相同信息下有清楚增量；或者得到证据充分、解释明确的适用边界。如果传统优化同样好或更好，就应把论文调整为具体工程算法/问题分析，而不是坚持通用 Agent 优势。

### 7.2 第二篇：从成败经历中学会“何时改、改什么、何时别改”

**建议工作题目：**《从设计经历学习条件化干预：工程 Agent 的方法改进与可靠采用》。

**核心问题：**同样看过成败历史，自动学到的方法能否比原来的强方法更会选择下一步？这种变化能否在新的机制条件下有效，并在不适用时停止使用？

先研究可用的经验学习，再讨论改进器本身的改进。**递归自改进不作为必须兑现的标题承诺。**是否降低这个原目标，需用户确认。

**H 的三个实际部分：**

- **Generate，提出行动：**根据当前服务失败和允许范围，提出具体可执行设计或辨别性实验，给出预期后果与可能受损的服务。
- **Select，选择行动：**在同一预算中选择最有希望修复、或最能区分原因的行动；不能因某个中间裕量提高，就选择已经预计没有有效交付的候选。
- **Update，吸收结果：**把预测与完整后果的差异更新为后续实际读取的状态；明确支持、反驳、无法区分、执行未完成。更新字段但不影响下一步，不算学到了有效行动方法。

**拟学习的最小内容：**条件、证据、动作、预期效果、不适用条件和停止规则之间的关系。可以体现为代码修改，也可以体现为由实际程序消费的规则；两种表示应按行为效果比较，不能先认定代码天然更高级。

**相对已有工作的创新候选：**

| 已有路线 | 我们不能再重复声称的内容 | 可能有价值的新增问题 |
|---|---|---|
| ADAS/DGM/GEPA | 自动改提示或程序并提高分数 | 同历史下，是否学到可转移的干预条件，而非通用流程修复 |
| AdaMAST/失败分类 | 从轨迹总结失败类型 | 正确诊断怎样转化为有收益的行动，何时应忽略无害缺陷 |
| MetaShare/经验库 | 保留成功与失败供以后检索 | 方法是否学到作用条件与反例，超过普通检索和原样经历 |
| HyperAgents/RSIFlow | 让改进层也使用历史或接受修改 | 在相同被改进程序和历史下，能否独立测出改进器能力；该问题先作为后续门槛 |

**第二篇的关键实验：**

1. **同经历比较。**固定强父方法；依次比较无额外历史、相同原始历史、普通反思/通用程序改进、所提条件化改进。另设简洁的参考方案检索/固定搜索基线，检查收益是否只是借到了结构答案。参与者工具、合法动作与总成本一致。
2. **形成后冻结，再评价。**训练、版本选择和最终评价任务分开。形成时允许完整执行和模型自主修订；最终任务结果不得回流修方法。形成失败、无更新和无合法后代照留。
3. **机制反转。**构造表面相似但同一动作效果相反的合法条件，同时保留无需修改的成功控制。评价是否正确触发、是否改变真实行动、是否保持原服务。
4. **作用位置检验。**在有实际后代后，用共同起点检查 Generate、Select、Update 的关键变化。联合修改可能有交互作用，先比较整方法，再做有意义的局部交换，避免机械拆碎或破坏程序合同。
5. **采用与总成本。**分别报告候选中的最好成绩、系统实际选中的成绩、错误采用与退化、形成/筛选/测试成本。不能用事后 oracle 成绩冒充部署表现。

**若要进一步做 G：**固定被改进的 H、公共历史、目标任务和完整资源；旧/新 G 交叉作用于相同 H。需要多次独立形成 G，而不只是同一个 G 生成多个 H。只有形成有效方法的质量和成本确有改进，才讨论更深递归。

**第二篇的否定结果同样有价值，但必须精确：**接口失败说明实验没完成；合法修改运行后无收益才是该修改的负结果；一个方法失败不能推出经验学习整体无效。若同历史强父已经解释全部收益，论文应报告这一边界，而不是继续换题寻找正结果。

## 8. 统一实验原则：少而有判别力，不再用庞大矩阵代替问题

### 8.1 先确定要排除的解释，再确定组数

每个实验只保留能回答当前问题的组。例如只问归因信息有没有帮助，就不必同时加五种模型和三个框架；但必须让普通历史组得到相同事实和资源。

按以下顺序展开：**实际行动是否不同 → 完整服务是否不同 → 更简单解释能否排除 → 是否在冻结新条件上重复 → 总成本是否值得。**前一步没有成立，不自动扩展后一步。

### 8.2 学习成本必须与部署成本分开列

最少记录：形成模型调用、开发任务执行、筛选失败、采用验证、最终求解。用两种视角报告：一次新任务的成本，以及多次部署时摊销后的成本。若前期成本很高，明确需要多少使用次数才可能有经济收益。

完整仿真就计作完整仿真；缓存复用单列；预转发工具错误与真实发出后用量未知分开。现存历史费用和 UNKNOWN 不改写。

### 8.3 评价的独立性不是多加一个叫“评审 Agent”的角色

关键是候选生成者不能控制最终服务定义，不能得到私有测试答案，不能通过修改评价语义来获胜。全仿真中可以使用事件重建、守恒检查、解析界或独立计算，但按当前争议选择必要项，不每轮做全套仪式。

### 8.4 重复实验要重复真正的不确定来源

只重复同一后代的测试，不能估计“自动形成好方法”的成功概率。正式方法结论应重复完整形成过程，并区分任务差异、模型采样和形成随机性。

具体数量在最小先导完成、看到波动量级后预先固定；不在显著性刚好出现时停止，也不把一个任务一次运行包装成普遍优势。资源有限时，缩小主张比虚构统计确定性更好。

### 8.5 跨案例迁移要改变真正影响选择的关系

门体动作既是事件又提供能量；光供能标签的供能与需要记录的温度历史可以错开。这个差别会改变启动、保存、暗期覆盖与恢复的判断，适合检验方法适用性。

如果 LC 任务已经参加训练，后续 LC 新工况应叫跨条件适应；若要声称门体经验向 LC 的零目标反馈迁移，就必须单独留出不含 LC 形成反馈的条件。不能靠更换名字实现数据隔离。

## 9. 总管 / A / B 的分工与四个大阶段

**本节只是待确认的安排，没有向任何 session 发送任务。**用户确认后，才由总管安排 A/B；当前所有执行继续暂停。

| 阶段 | 总管 S0 | A：工程与独立后果 | B：方法与论文 | 阶段交付及出口 |
|---|---|---|---|---|
| 一：锁定问题与最小证据设计 | 固定两篇各一个核心问题、共同资源、任务划分和停止条件；处理恢复前真实阻断 | 选少量有机制差别的合法任务；复用现有有效模型；说明哪些动作已能真实执行 | 写最接近已有工作与差异；固定强父方法和对照；完成两篇论证骨架 | 一份可直接执行的协议；任务、方法、指标对应。无新平台、无“先把所有东西整理完”的前置工程 |
| 二：完成第一篇关键工程比较 | 按完整方案推进，统一安排，出口一次独立读回；不逐参数等审批 | 执行整套源—供电—程序设计，重建记录交付；检查有域排除关系 | 实现修改范围选择，与强通用和传统优化比较；从实际差异写论文一完整初稿 | 行动/完整服务/成本对照表，一组解释清楚的成功与反例，论文一可通读稿；无增量则明确收缩贡献 |
| 三：完成第二篇学习与冻结评价 | 隔离形成与测试；让实际训练反馈连续返回；不在接口修正后停等新工单 | 支持同输入执行与必要独立评价；准备适用/不适用和保留父方案控制 | 自动形成真正被消费的方法；比较同历史、普通改进和条件化改进；分析采用错误 | 自动修改→实际行动→服务后果的完整证据；包括无更新/拒绝/负结果的论文二完整稿 |
| 四：有针对性的验证与交付 | 根据已经得到的结论确定还缺哪项反证；统一版本与复验入口 | 只对支撑主张的关键边界补必要验证，不重跑全部历史 | 完成相关工作、方法、结果、局限与图表；仅在门槛成立后提出独立 G 比较 | 两篇完整论文、同版代码与数据索引、复验说明；所有未成立主张明列。递归与漏水不自动扩展 |

**总管的重点：**判断当前实验是否还在回答核心问题，处理唯一直接阻断，避免同一实现反复修补却不执行。不能用管理文件数量代替研究进度。

**A 的重点：**让真实候选进入原动态消费者，说明服务为什么成功或失败；不给方法组偷偷提供修复答案，不为每个未知任务先求私有最优解。

**B 的重点：**把“提出—选择—吸收结果”落实为有行为差异的方法，诚实比较；写清楚普通方法已经能做到什么，所提方法额外做到了什么。先形成完整论证，再决定是否需要新增实验。

**本审查会话的重点：**检查关键主张与证据是否相称，并依据结果决定后续范围。当前只交付文档，不恢复监督或派发。

## 10. 需要用户确认的方向，不是执行中的默认改变

1. **论文一以具体耦合设计与修改范围选择为中心。**减少“通用自主工程平台”的主张，允许最终贡献落在有效工程算法而不是 Agent 必胜。
2. **论文二以条件化干预学习与可靠采用为中心。**把 G 的独立改进和深递归设为证据成立后的扩展，不再把 RSI 当必达标题。
3. **保留门体与光供能两个主案例。**漏水案例先作为资格依赖的候选，不阻塞已有主线；若用户仍要求其为主结果，应另设明确范围和资源。
4. **采用按研究问题组织的大阶段。**在一次冻结预算内连续完成实现、实际比较和出口分析，减少逐参数微工单；发现负结果后允许收缩或改变路线，不无限追正结果。

确认研究方向与批准恢复执行是两个动作。本文件送审时，仍然保持暂停。

## 12. 最终建议

值得押注的方向，不是继续提高“自改进”的命名层级，而是把一个此前说不清的决策问题真正解决：**面对相似失败，系统能否判断应该怎样干预，以及何时不应该干预；从经历中形成的这个能力，是否超过同历史、同工具、同成本的强方法。**

如果做到了，哪怕只覆盖门体与光供能两个模型明确的工程案例，也可能比一个没有干净对照的“通用递归科学家”更有研究价值。如果没有做到，就应把已有工程成果准确交付，并据证据调整论文，而不是靠增加流程、谱系和术语延长故事。
