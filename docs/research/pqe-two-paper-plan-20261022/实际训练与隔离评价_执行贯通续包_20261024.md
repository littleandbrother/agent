## 2. S0/B：一次修正两处直接阻断，检查实际嵌套链

### 预算从总额分配到子求解

形成 episode 的 262144 输出总额不是单个训练 solve 的上限。每个子求解同时受求解器原有上限与形成 episode 剩余资源约束：输出最多 min(131072, 形成剩余输出)，请求/工具/费用/时间同理，单次模型输出不超过共同后端上限及剩额。子求解消费回写同一形成预算；不得在每个子求解重置 USD、请求、工具或计时，不通过提高求解器冻结上限解决映射错误。至少保留一次反馈返回与自主修订的机会，由形成过程在共同预算内分配，未发生修订如实记录。

只修 token 不够：当前入口还把形成 USD10 传给上限 USD5 的子 solve，同样会拒绝。所有资源维度统一分配。形成实例也须显式得到已声明的 24请求/48工具/1800秒；仅修改 MAX_LIMITS 不会把默认 12/24/900 改成形成预算。继续使用同一 owner、真实账本和绝对截止时间，不把新上限误当新余额。对应原直接位置为 `lc-service-learning/s0/run_lc_learning.py` 的 `solve_program` 和形成实例配置。

### 公共视图既可发送，又可还原完整依据

保留父代码、六位点合同、合法 incident/source 对应、完整服务结果、失败/未知、必要证据索引和字段覆盖语义。大对象采用既有按需分页并保持原始引用可达；不按某组需要删公共事实，不用摘要替模型推荐答案，不扩大 broker/worker 原上限。同 result 身份的不同视图不能无声替换。实际投影失败时明确本地预转发错误；已发出的新请求若缺 usage，仍停止依赖调用。

### 形成前只做一次针对真实故障的贯通验证

用已保存 H2 原提案、H4 失败载荷及已有开发结果走实际入口：materialize/screen → 训练子求解额度准入 → 原结果返回 → Update → 下一 Generate/Select → 形成反馈/修订请求构造。科学结果只读精确旧缓存，模型用明确的离线替身，不产生新模型或科学输入，也不把软件路径通过算成方法收益。
