# E2 门体主比较与 LC-PV 并行推进

派发：`BF-PQE-S3-E2MAIN-20261023-001`。总计划 `BF-PQE-20261022-001`，阶段三主比较；阶段四仅前移 LC-PV 仿真资格。总管 S0 统一安排 A/B，沿用现有工作区。全仿真。定时任务继续暂停。

## 1. 为什么执行这一包

E2-DEV 已真实完成 3 题×4 条件：D15、D07 均四组通过，M3 四组都改变活动设计范围但仍未完成服务。没有建立 full_h 优势。F1-FIRST 已完成自动形成、选择与确认；H2/H4 均保留父方法，十次确认的初态本来通过、没有设计动作。这两包封存，不能继续把接口修复或已通过初态的停止当作修复研究进展。

下一项问题是：在事前固定、机制不同的门体任务上，四种设计过程是否产生不同的有效设计、完整服务、首次可行成本及错误停止？零差异和基线更好同样形成有效结果。

本包复用 E2-DEV 报告已提出的 **4 个任务×4 方法×2 个独立参与者上下文，最多 32 次求解**。这是限定任务集的主比较，不声称 4 个任务足以代表所有 BF 系统。不得执行后追加重复来追求显著性。

## 3. 门体任务与准入

任务来自批准方案的四种用户问题，事前确定具体实例和生成依据：

1. **D04：门抖动时重复记录，但真实的再次开关不能被去抖吞掉。** 检验程序局部修复及误删真实事件。公开硬件和合法动作，不能给出正确去抖值。
2. **D05：连续开关时漏记或迟到。** 检验事件保持、排队、发送与能量之间的关系。使用现有消费者真正支持的状态，不虚构不存在的缓存/脉冲捕获硬件。
3. **D10：增大储能后报告反而变慢。** 检验积能启动、运行能量、期限与合法活动范围的取舍。不是再次平移旧网关窗口或复跑旧半速 M3，不预先宣布必须联合或结构重构。
4. **D16：当前设备已满足要求，是否需要再改。** 明确作为不应无端修改的控制题；结果单列，不能计作失败修复或迁移成功。

四题的实际输入和完整服务必须来自现有 DOOR 模型与动作空间；以动作/事件历史和程序机制区分任务，不靠改 ID 宣称新机制。已见开发题、旧选择题和已暴露确认输入不得重新标为未见测试。

每题最多一次新的共同初态仿真。前三题的“失败修复”标签以真实初态为依据；若初态通过，保留并明确其控制/设计任务身份，不在看到方法结果后换题。若输入无效或模型不能表达机制，记录具体能力缺口，该题不运行模型也不换相邻参数题凑数；其他合格任务继续。未知解无需开发者先求出完整正例或全域无解证明。

至少区分用户设计入口、工况改变入口与固定失败入口，分别统计；所有方法在同一题上看到相同信息。私有初态诊断、参考推导和最终评价不作为模型答案。任务语义与生成规则在任何本包参与者运行前冻结。

## 4. 四条件与公平性

- B0 强通用工具 Agent；B1 固定顺序；B2 普通反馈；B3 完整 BF 方法。复用已经实际运行的实现，不能只改标签。
- 同一模型配置、任务、初态、共同开发资料、动作权限、工具和事实、评价与操作预算。强基线也能修改 Task 已授权的活动范围，不能人为禁止其联合设计。
- 两次重复是独立参与者上下文，不是新的物理场景。执行顺序在结果前按平衡循环固定；缓存只有在参与者独立提交相同输入后返回，不能提前暴露别组答案。
- 记录 B3 是否真正提出竞争解释、事前预测、选择观察、修改活动范围或根据结果更新；未使用不写作机制已起效。提示进入请求、函数调用、决策变化、服务收益分别记录。
- 原最终评价器对四组共同执行；工具错误、模型域不足、服务 FAIL、主动停止分列。一个候选失败不能推出整个拓扑或任务无解。
- 本包不改科学模型、外部服务或正式验收语义来适配某组。需要这样的变化时停止受影响部分并说明，其他独立工作继续。

## 5. 事前分析与否证

主要比较是每任务每条件的完整服务、错误采用和首次可行资源。报告每个任务两次结果及全部成本，不把精确缓存当独立数值重复。

沿用开发报告提出的实用差异：在相同上限下至少额外完成一个任务，或服务不降且每任务平均少一个新的科学输入，同时不增加错误采用/无依据的全域排除。候选评价次数（含缓存）、真实计算成本、模型成本另列，避免缓存执行顺序制造优势。形成方法的成本不混入本包固定 H 求解费用。

四任务的有限配对结果是主要估计对象；两次重复仅观察参与者变化。显示逐题差异和不确定性，不用运行数冒充任务数或保证统计功效。D16 单列控制结果，不掩盖前三题未修复。

若 B3 无额外成功、没有降低资源或更多错误，明确保留无增益/退化结果。若成功依赖扩大范围，当前只能报告实际路径；**重构后范围匹配、机制消融 E3 与传统参数优化参照仍是独立待办**，不得从本包相关性直接归因给某机制。B 可整理下一最有辨识力的有限对照，未经本包审查不自动增加模型运行。

## 6. LC-PV 的并行实际交付

A 沿批准方案 S4-01–04，复用已有 PV/电源/程序模块，形成最小可执行：声明光输入与安装条件→受载 PV→储能/启动→指定温度测点及传感响应→程序采样/保存→暗区和断联→恢复上传与新样。

必须区分缺样、未知区间、存量记录完整、FIFO/去重、记录时间及及时接收，不能把“没有收到异常”解释为全程正常。改变程序必须重新影响负载和供电。不能 lux 直接替换功率，也不把旧 A/R 通过结论直接移植。

本包最多 4 个新的 LC-PV 无 Agent 输入：一条完整服务参考，以及按现有具体机制事前选择的能量不足、状态/记录丢失、恢复时效反例。若缺模型或消费者能力，交付最小实现缺口与已经得到的事实，不强行凑四条、不新建平台或等待实物。模型/解析证据均标明范围。

LC-PV 私有资格输入和结果只由 A/S0 持有，不送给后续 H/G 形成或选择。B 只得到公开模型契约及完成/缺口状态。此包没有 LC-PV 付费 Agent、没有 F2 迁移成绩。
