# 双论文核心方法：算法、实质区别与决定性实验

**状态：待确认；全部实验、S0/A/B 派发与定时任务继续暂停。**  
**日期：2026-10-24。** 本文提出新的研究路线，不是已完成实验的结果报告，也不自动替换当前冻结工单。

> 这次只押两个具体想法。第一篇把“一个设计失败了”转换成“哪些参数组合不可能成功、怎样联合改变才能重新出现可行解”；第二篇主动寻找“同一种改法从有利变成有害”的分界，用这些成对实验学习实际选择行动的程序。每篇先验证最关键的一步，成立以后才补论文所需的覆盖。

## 1. 先改变做研究的方式

此前的问题不只是推进慢，还在于把三件事混在一起：工程功能越多、评价越完整、研究机制越新。它们没有必然关系。

现在采取以下取舍：

| 必须弄清楚 | 可以暂时不完美 |
|---|---|
| 新方法究竟多做了哪一步计算，改变了哪个真实设计动作 | 支持所有设计类型、所有工具与所有程序修改方式 |
| 最接近的现有方法是否已经能做这一步 | 将整个领域所有论文全部复现 |
| 同信息、同资源时，这一步是否带来实际服务收益或搜索节省 | 多个基础模型、大规模案例、完整产品化 |
| 拿掉核心步骤，收益是否消失；何种结果会推翻解释 | 深层递归、改进器自改进、漏水案例、硬件验证 |
| 单次任务仍按原完整服务判定，不能用局部指标替换成功 | 要求算法在所有任务都成功、所有指标都领先 |

**论文不需要证明算法永不失败。** 可以存在失败任务、作用范围有限和偶发退化。需要报告这些结果，让核心主张与证据相符。算法整体平均收益与单项设备服务是否通过，是两个不同的问题。

本文不把“每个新方法必须在所有测试任务全过”当作研究成立的条件。那是较强的部署采用要求。可以先证明一个方法在明确问题族内更有效，同时保留尚不适合部署的结论。这个研究口径建议等待用户确认，不回写旧实验。

## 2. 文献碰撞后，哪些想法不再当创新

新的检索进一步缩小了可做的范围。

- **“发现局部修复的副作用，改为联合修复”已经有人做。** VIGOR 使用局部投影与联合冲突图修复；更早的图模型修复也分析修复规则之间的冲突及循环。仅画一张冲突图不构成我们的新方法。[VIGOR，§3.4](https://arxiv.org/html/2610.13145v1)、[图模型修复，§7–8](https://link.springer.com/article/10.1007/s11334-024-00587-w)
- **“储能、阻抗、任务调度必须联合考虑”也不是新发现。** CO2CoDe 已具体分析电容与 ESR 如何影响间歇执行和调度。[CO2CoDe](https://hotcarbon.org/assets/2024/pdf/hotcarbon24-final69.pdf)
- **“电容大有利于执行、却拖慢充电启动”本身也已经是明确的设计知识。** 2025 年的任务感知可调门限 PMC 论文直接讨论这一矛盾；更早的无电池 LoRaWAN 工作联合分析电容、启动电压、业务与供能条件。我们不能把这条物理常识包装成发现。[任务感知 PMC](https://globals.ieice.org/en_publications/elex/10.1587/elex.22.20250395/_f)、[无电池 LoRaWAN，期刊版 2021／arXiv 公开版 2024](https://arxiv.org/abs/2402.07528)
- **“能量与截止时间一起考虑”已有很长的研究历史。** 采能通信中的能量到达、数据到达和完成时间约束已有明确优化方法。[Yang 与 Ulukus](https://arxiv.org/abs/1010.1295)
- **“用实验验证经验、发现反例后缩小适用范围”也已有直接工作。** EvoBelief 维护可检验的环境规则，并用观察和实验更新其可信范围。[EvoBelief，§3](https://arxiv.org/html/2610.12789v1)
- **“从同一上下文分叉执行，给行动分配贡献”不是我们的首创。** C3 和 BranPO 已分别研究局部反事实执行与共享前缀下的对比分支。[C3 v1，§3](https://arxiv.org/html/2603.06859v1)、[BranPO，§4](https://arxiv.org/html/2602.03719v1)
- **“找候选有分歧的样本，再学习程序”也不是新原则。** EQUI-VOCAL 已用分歧驱动的主动学习帮助程序合成。[EQUI-VOCAL](https://vldb.org/pvldb/vol16/p2714-zhang.pdf)

因此，下面不再把“联合”“条件化”“因果”“自改进”等词本身当贡献。**真正的创新候选必须落在新增计算步骤上，并与最接近的传统方法正面比较。** 新的组合仍可能只是合理工程整合；决定它能否成为方法论文的是下面的实验，而不是标题。

## 3. 论文一：把启动—运行冲突反演成联合设计

### 3.1 建议题目与唯一核心主张

**工作题目：**《从启动—运行冲突反求联合设计：间歇供能系统的可行窗口修复》

**核心问题：**当增大储能能避免发送掉电，却使设备来不及启动时，继续试电容数值可能没有意义。能否从当前程序和供能模型计算出相互冲突的参数范围，直接找到能够解除冲突的采能—储能—程序联合修改？

**待验证的主张：**

> 对具有相反启动与运行约束的问题，把设计搜索从“逐个试参数点”变成“先计算是否存在可行参数区间，再搜索能够打开区间的联合修改”，可以减少无效完整仿真，并在相同预算下更经常找到完整服务方案。

这篇的中心是一个具体的设计求解方法。LLM 可以帮助提出程序方案或解释结果，但不是贡献成立的必要条件。若一个确定性求解器就能实现核心机制，我们应该使用它。

### 3.2 为什么这是一个值得抓住的结构

储能容量 C 在同一个设备里有相反作用：

1. 容量太小，启动后不足以完成保存、发送与确认。
2. 容量太大，在有限供能脉冲里充不到启动门限。
3. 改程序会改变运行所需能量，也会改变采能期间的负载。
4. 改机构、源阻抗、启动门限会改变充电过程，并可能触及力、空间或模型边界。

因此，某个程序下可能根本不存在合适的 C。此时应该改变形成上下界的因素，而不是继续在 C 上搜索。

这与“选一个更大的电容”不同，也比“考虑全系统”更具体：**算法要计算并使用这个不存在的区间。**

### 3.3 一个能完整算清楚的例子

以下数字仅用于说明算法，不是项目新实验，也不是现有门体器件参数。

假设一个简化的两阶段模型：

- 从零电压充电，到 2 V 启动；必须在 3 s 内启动。
- 启动后输入停止，电压低于 1 V 就无法继续。
- 当前程序完成原定保存、发送、确认需要 3 mJ。
- 启动前可用恒定净功率为 0.5 mW；暂不计 ESR、漏电和启动能量。

启动要求给出容量上界：

\[
C\leq U=\frac{2P T_{\mathrm{boot}}}{V_{\mathrm{on}}^2}=0.75\ \mathrm{mF}.
\]

运行要求给出容量下界：

\[
C\geq L=\frac{2E_{\mathrm{run}}}{V_{\mathrm{on}}^2-V_{\mathrm{off}}^2}=2\ \mathrm{mF}.
\]

**下界大于上界，任何 C 都不能同时满足这两条要求。**

现在有两个允许的设计修改，均不减少应交付的数据：

| 修改 | 启动上界 U | 运行下界 L | 是否重新出现区间 |
|---|---:|---:|---|
| 原方案 | 0.75 mF | 2 mF | 否 |
| 只把净采能功率提高至 1 mW | 1.5 mF | 2 mF | 否 |
| 只通过程序实现把完成同一服务所需能量降至 2 mJ | 0.75 mF | 1.333 mF | 否 |
| 两项同时改 | 1.5 mF | 1.333 mF | 是 |

联合修改后，取 C = 1.4 mF：充电至 2 V 需 2.8 s；从 2 V 降到 1 V 可提供 2.1 mJ，满足简化模型中的两条要求。

这个例子的关键不是数字，而是：**两个单独看都没有修复成功的改动，合起来能使可行区间从空变为非空。** 按单个改动的最终 PASS/FAIL 排序容易丢掉它们；只调整 C 则永远找不到解。

这些公式本身是基础物理，不应被写成创新。创新候选是：在真实执行中自动识别适用的冲突，反求联合修改，并证明这种计算比普通搜索有价值。

### 3.4 具体算法：输入、计算与输出

令 z 表示暂时固定的非储能设计：机构/采能参数、阻抗、门限及程序策略；C 是首版要消去的一个连续变量。

算法只实现一个窄而完整的能力，不做万能设计编译器。

**输入：**任务服务要求、当前设计、实际完整执行轨迹、现有组件方程、合法修改范围、剩余仿真预算。

**输出：**一个实际可执行的联合设计，或者当前修改范围内的有依据排除，或者证据不足。

步骤如下：

1. **定位一条未完成的服务义务。** 例如某条记录启动太晚、TX 中断，或恢复后仍未及时交付。使用真实记录身份和事件时序，不使用“接收数少”代替具体义务。
2. **绑定少量已知物理关系。** 首版只绑定充电时间、一次必要程序段的能量、瞬时压降三类。记录中哪些量来自实际执行、哪些来自方程、哪些只是估计。
3. **反求 C 的必要范围。** 在适用条件 G 内，形成 `G ⇒ C∈W(z)`；最简单时 W(z)=[L(z),U(z)]。只能得到局部或多段范围时，照实保留，不能为了方便强行做成一个连续区间。
4. **若范围为空，找造成冲突的两侧关系。** 决定哪些合法变量能移动 L、哪些能移动 U。这里输出的是可影响关系的变量集合，不是“应该用某个固定成功参数”的答案。
5. **在小范围内求联合修改。** 先枚举至多两类修改的组合，例如源参数与程序策略；对每个组合重新计算范围。区间仍空且条件有效的组合不进入昂贵完整评价。区间重叠者生成真实设计候选。
6. **用原完整仿真执行候选。** 所有供电、程序负载、重试、队列、记录与接收重新相互作用。完整判据决定最终成功；区间重叠仅表示没有被这些必要条件排除。
7. **将新的实际后果送回下一轮。** 新程序若改变阶段顺序或源负载，旧条件 G 不再成立就重建该关系；不沿用已经失效的界。

示意伪代码：

```python
trace = full_execute_or_exact_cache(current_design, task)
if complete_service_pass(trace):
    return current_design
while budget_left():
    obligation = first_unmet_service(trace)
    window, scope, dependencies = invert_bounds(obligation, current_design, trace)

    if window.is_empty() and scope.is_valid():
        edits = combinations_that_can_move_conflicting_bounds(dependencies, max_families=2)
    else:
        edits = ordinary_candidate_generator(current_design, trace)

    proposals = []
    for edit in edits:
        candidate_family = apply_edit(current_design, edit)
        new_window = recompute_bounds(candidate_family, task)
        if new_window.provably_empty:
            continue
        proposals.append(realize_candidate(candidate_family, new_window))

    candidate = common_selector(proposals)
    if candidate is None:
        return scoped_stop_or_unknown()
    trace = full_execute(candidate, task)
    if complete_service_pass(trace):
        return candidate
    current_design = candidate
```

这段代码表达新策略，不表示这些函数已经实现。`invert_bounds` 和 `recompute_bounds` 才是第一篇真正要做、真正要被检验的算法内容；其他部分复用现有工具。

### 3.5 最关键的技术难点：不能把旧轨迹当新设计的物理界

当前门体模型的源电流与母线电压相互影响，形式上包含：

\[
I_h(t)=\max\{(|e(t)|-V_{\mathrm{bus}}(t)-V_{\mathrm{rect}})/R,0\}.
\]

因此，改 C 或程序负载后，实际采到的能量也可能变化。旧设计的总采能不能直接作为新设计的供能上限。这不是额外追求完美，而是区间排除能否成立的核心。

首版采取一个明确做法：

- 用当前方程和声明变量范围推得的**乐观供能上界**与**必要消耗下界**，推导可排除区域。
- 实际仿真轨迹用于找到相关阶段与失效条件，不能单独证明整个参数区域无解。
- 若只能得到过松的界，接受它筛不掉候选，交给原完整仿真；不另建队列/重试近似器来强行提高筛选率。
- 必要条件允许放过最终失败的候选，但不能把实际可行候选排除。对所有被宣称排除的区域，必须说明适用域与依据。

在简化模型中可以证明区间判别的正确性；完整模型中首版只为能明确推导的分支提供排除。**不要求为整套仿真做形式验证。**

**第一版怎样实现 `invert_bounds`，而不是把难点藏在函数名里：**

令固定非储能设计 z 下的整流后开路电压为 u(t;z)≥0，源阻抗 R(z)>0。对现有规定运动、准静态源模型，在任一非负母线电压 V 下，输入储能端的瞬时功率满足：

\[
V\max\{(u-V)/R,0\}\leq u^2/(4R).
\]

所以，从零电压开始、必须在 T 内达到启动电压时，可以计算一个不依赖旧负载轨迹的乐观上界：

\[
\overline E_h(z,T)=\int_0^T\frac{u(t;z)^2}{4R(z)}\,dt,
\qquad C\leq U(z)=\frac{2\overline E_h(z,T)}{V_{\rm on}(z)^2}.
\]

计算积分上界时使用可包住输入变化的分段上界；不能把未经误差处理的采样积分当严格排除依据。忽略损耗只会放宽 U，不能凭空提高真实设计的成功判定。

对于由任务与模型共同保证的一个无输入执行段，若开始电压最多为 V̄_s，完成规定记录服务至少需要 E_min，且不得低于 V_off，则必要条件是：

\[
C\geq L(z)=\frac{2E_{\min}(z)}{\overline V_s(z)^2-V_{\rm off}(z)^2}.
\]

E_min 从该段必须完成的采样、保存、至少一次有效发送及确认等基本事件的能量下界组成；不把当前失败轨迹里所有无效重试都当作不可避免的能耗。若该段仍可能采能，要扣除有依据的供能上界，或不用这条下界。若“无输入”只在旧轨迹出现而非新设计仍满足的条件，也不能使用它排除新设计。

在这个基础上实现有限的区间分支搜索：

1. 将共同合法程序选项作为离散分支，源参数按原合法范围组成小的参数块 Z；每个程序选项保持相同服务。
2. 对每块算出 **L 的下界**与 **U 的上界**。若 `lower(L,Z) > upper(U,Z)`，整个参数块与任意 C 的组合都可排除。
3. 未被排除的块按固定规则细分，或选取代表 z。对该点重新计算 L(z)、U(z)，再生成区间内的 C；不把不同 z 的最好上下界拼成一个虚假可行点。
4. 优先执行具有区间重叠且修改成本小的候选。没有可证明区间时保留普通探索，不编造无解结论。

**真正要验证的是这种“先消去 C，再搜索能打开范围的 z”的降维是否有效。** 单条轨迹只负责指出该绑定哪段服务关系；整个区域的排除必须来自模型关系和适用条件。可先只实现上面这对关系，ESR 的瞬时约束作为原消费者的最终检查，不必首轮就做所有关系的反演。


### 3.6 相对最近工作的实质区别

| 最近工作 | 已有机制 | 本方案新增的具体计算 | 什么情况说明区别不够 |
|---|---|---|---|
| 任务感知 PMC / LoRaWAN 配置分析 | 已分析储能、门限、充电时间与任务负载取舍 | 从失败义务构造可排除的联合参数区域，并重新求具体设计 | 仅重新推导充放电公式，或只展示另一个更好电容点 |
| 无电池能量感知 MILP 调度 | 将任务安排与采能、电压约束写入优化问题 | 首版同时变更源/储能/程序，并用局部必要关系消去参数维度 | 给传统求解器同一信息后，转换与搜索并无新增作用 |
| CO2CoDe | 电容、ESR 与间歇任务调度的联合考虑 | 从当前失败反求相反服务约束的参数范围，再自动生成能够使范围重叠的联合改动 | 只复述“储能和调度有关”，或人工替系统填好新设计 |
| TopoSizing | 电路层级理解帮助 BO 初始采样与停滞时调整搜索范围 | 将一个参数维度反演成随程序/源设计变化的必要区间，用冲突指导离散程序与连续设计的联合修改 | 只是给 BO 换一组上下限，没有执行证据到区间的计算链 |
| VIGOR | 静态几何约束的局部投影与联合修复 | 处理修改会改变能量轨迹、程序事件及服务时序的动态关系；重新计算必要范围 | 只有冲突图与“联合改”标签 |
| CEGIS / CPS 参数合成 | 给定形式模型与约束后，以反例求参数或程序 | 从现有动态执行和有限物理关系中提取可复用的有域约束，避免先完整形式化全系统 | 把完整约束人工写好后调用求解器，并把求解器换名当新方法 |
| 普通混合变量优化 | 同时搜索参数和程序选择 | 利用可排除区间，避免在当前程序下不存在解的连续参数区域消耗预算 | 同预算优化器已经同样高效，或优势只来自本方法独享物理事实 |

出处：[能量感知调度的优化模型](https://arxiv.org/html/2402.05319v1)、[TopoSizing §III-D](https://arxiv.org/html/2509.14169v1)、[CPS 参数合成](https://easychair.org/publications/paper/1fL)。其他出处见第 2 节。

**我的新颖性判断：**这是一项有明确算法对象的工程方法提案，不能声称发明了约束传播、联合优化或反例引导合成。它的价值取决于“动态失败→有域区间→联合动作”的自动转换是否确实省掉大量无效搜索。这个风险应在首轮暴露，而不是靠更大的 Agent 叙事掩盖。

### 3.7 第一篇最先做的决定性实验

**只问一个问题：在单参数范围为空、联合修改能打开范围的任务里，区间反演是否真的帮助找到解？**

首轮使用同一个门体完整消费者，保留原服务与空间/力边界；选三类预先定义的问题结构，每类少量实例：

1. **单项可修：**存在 C 的有效区间。检验方法不会无故扩大修改。
2. **联合才可修：**两个单项修改仍无区间，联合修改才出现区间。它是核心机制例。
3. **界的条件不成立：**输入时序或程序阶段变化，使旧区间不可沿用。检验方法是否错误排除。

解析例提供机制真值，完整门体仿真提供工程结果；不能用解析例替代真实消费者。

**最小对照：**

- 所提方法。
- 同一合法修改算子库与选择规则，但移除区间反演与区域排除：采用逐点候选搜索。联合动作同样开放，不能把基线限制为单参数修改。
- 一个正常配置的约束/混合变量求解基线，拿到相同合法动作、原始事实、组件方程与预算。先用该小问题可支持的标准约束传播或区间搜索实现，不以弱黑箱随机搜索代替最接近对手。

另做一个便宜的归因检查：把本方法提取的约束交给标准求解器。如果它能得到同样结果，贡献必须落在自动提取与更新约束，而非宣称发明了求解算法；若提取本身也只是手工写死公式，这条路线就更适合系统应用论文，不能冒充通用 Agent 推理突破。

强通用 LLM 可以作为论文补充对照，但**没有它也必须能说清这项算法有没有价值**。不能只赢一个弱 LLM 就宣称设计求解更强。

**核心读数：**完整服务成功率—完整仿真次数曲线；首次完整成功需要几次执行；被排除区域是否包含实际可行点；真正生成了哪组联合修改。建界计算与模型调用也列成本，避免把额外求解藏掉。

**推翻主张的结果：**

- 删掉区间机制，行动与完整服务结果基本不变。
- 同信息普通优化器同预算同样好，而本方法增加明显建界开销。
- 只有人工指定应改的两个变量时才有效。
- 声称必要的界排除了有效解，且无法在声明适用域内修正。
- 只提高电压或接收数，原完整服务没有改善。

**首轮建议规模：**三类各 2 个实例、每算法每实例最多 8 个完整候选。共最多 144 次候选执行，解析计算和已有精确缓存另列；这是待确认的先导规模，不是承诺统计显著性。首轮没看到机制差异就停下来改 idea，不自动扩大数量。

### 3.8 第一篇允许不做什么

先不做任意拓扑生成、任意固件合成、所有参数的形式界、第二套近似仿真、物理校准和全生命周期产品资格。主结果先放门体；LC 可以用来检验同样的区间反演是否跨到暗期存活，但不应成为第一篇起步前的必备模块。

如果只有门体某个子问题成立，就写清这个子问题。若最终算法不需要 LLM，按工程设计算法写，不硬把 LLM 放在中心。

## 4. 论文二：通过收益翻转实验学习选择动作的程序

### 4.1 建议题目与唯一核心主张

**工作题目：**《主动寻找收益翻转点：从成对设计实验学习行动选择》

**核心问题：**一种修复在任务 A 有用、在任务 B 有害时，学习器怎样主动找到两者的分界，并把它变成真正执行的选择规则？

**待验证的主张：**

> 在相同训练仿真预算下，主动收集“同一对设计动作在相近合法条件下优劣互换”的成对结果，比随机收集经历或只找预测不确定的样本，更有效地学会在新条件下选择正确动作。

这篇的新增部分是**训练实验的选择算法**，以及它产生的行动监督。不是“我们也让模型改代码”。

首版有意只学习 **Select：从候选里选下一项行动**。Generate 的候选生成器与 Update 的事实更新保持固定且共同可用。不要同时开放六个位点，让核心结果再次淹没在“代码改了但行动没改”的问题里。

### 4.2 为什么要找“好坏翻转”，而不是再多收集几次失败

假设某个修复动作是减少频繁重试：

- 网关长时间不可用时，它可能节省能量，让设备有能力完成后续有效发送。
- 有效接收窗口很短时，相同改法可能错过窗口，使记录超时。

“减少重试有用”“减少重试有害”都太粗。即使学习器读到了两个结论，也可能只记住更显眼的案例。

更有学习价值的是一组受控比较：**在两个接近的条件里，比较同一对行动，找到其优劣确实交换的位置。** 这迫使学习器识别决定选择的条件。

这里不预设减少重试一定有用，也不把已见的某个 retry 数字写成正确答案。上述关系只是需要真实执行检验的动机。

### 4.3 先把学习对象限制到可测量的范围

共有的候选生成器，对当前设计提出少量实际设计候选，例如：

- 局部储能/门限调整。
- 保持原数据服务的程序时序调整。
- 采能—储能—程序联合修改。
- 有充分依据时保留当前设计或停止。

这些是操作类型，不是固定的成功配置。所有对照组都能提出和使用它们，参数由当前任务与当前状态生成。不得给本方法专享正确答案候选。

每个决策状态 s 包含当前公开历史、设计、服务要求和预算。学习器能使用的特征 φ(s,a) 必须在行动 a 执行前就可取得，例如：

- 启动裕量、已知储能余量及其估计是否适用。
- 已保存但未完成交付的记录及年龄。
- 过去实际 ACK / 重试后果。
- 提议动作影响哪些合法字段。

不使用任务名字来查答案，不把仿真后的真实结果当输入特征。设计 Agent 可读任务公开条件；最终设备程序仍只使用原有传感、时钟、ACK 等观察能力。

### 4.4 具体算法：先做同状态对照，再找相反条件

**第一步：形成一个真正有分歧的动作对。**

在同一公开状态 s，选出两个不同的可执行行动 a、b。来自共同生成器或共同冻结的策略候选，不要求其中任何一个正确。两动作相同时不花预算“证明方法有差异”。

**第二步：把两条分支都真实执行。**

对相同任务、初态与设计历史分别执行 a、b。首轮只比较该完整候选能否完成服务，不加入额外的多步设计续行，以便一次行动对应一次完整评价。后续若研究多步设计，才加入相同的冻结续行策略，并把全部续行执行计入训练成本。

这里复用的是设计决策历史。**每个新设计的源—供电—程序后果仍从其正确初态重新执行，不能将旧电压轨迹移植给新程序。**

定义结果比较：

- a 完整 PASS、b FAIL：a 优于 b。
- b 完整 PASS、a FAIL：b 优于 a。
- 两者都 PASS：首轮记作服务收益相同，成本另报；不靠微小费用差异制造核心翻转。
- 两者都 FAIL：首版记作无法用完整成功区分，不按“少失败一门”制造赢家。
- 工具未完成：不产生工程优劣标签。

令 `V(s,a)=1` 表示完整服务 PASS，`V(s,a)=0` 表示有效评价的 FAIL；工具错误和证据不足不赋值。定义 `Δ(s;a,b)=V(s,a)−V(s,b)`。首轮只有 +1 与 −1 的交换才算核心收益翻转；两者同成败是平局，保留记录但不产生优劣标签。它只表示这个动作对的相对结果，不是全局最优动作的证明。

**第三步：主动寻找优劣可能相反的合法条件。**

在预先定义的训练工况范围中改变输入条件，例如供能脉冲持续时间、事件间隔、断联持续时间。服务判据、动作范围与设备观察能力保持不变。

不是“随便生成更多难题”，而是优先寻找：

- 动作对 a、b 在两个条件里仍有相同操作含义：操作定义、参数生成规则和共同起点设计在比较前固定，不能见到后果再换成不同的“同名动作”。
- 当前预测认为两者优劣可能交换。
- 两种选择的后果差异值得花执行预算确认。

使用一个小型预测器估计动作对的差异即可；首版采用由已有成对结果训练的浅层树集合，不训练大型世界模型。实际标签只来自完整执行。

查询器也需要具体到能够直接实现。用当前成对数据自助采样，拟合一组小型结果预测树。对每个候选条件 q，得到各树预测的 Δ_m(q)。对一对条件 Q=(q1,q2)，计算：

- p_flip：预测 `Δ_m(q1)Δ_m(q2)<0` 的树所占比例。
- H_flip：对这个比例计算二元熵，衡量目前是否还不能确定这里存在翻转。
- D(q)：各树对 a 胜、b 胜、平局三种结果的投票熵，衡量该点的行动结论是否有分歧。

首版查询分数固定为：

\[
\mathrm{score}(Q)=
\frac{H_{\rm flip}(Q)\,[D(q_1)+D(q_2)]}
{\sum_{i\in\{1,2\},\,a'\in\{a,b\}}\widehat{\mathrm{cost}}(q_i,a')}.
\]

q1、q2 只允许相差一个事前声明的工况因素，其余条件保持相同，并限制该因素的变化距离。这样查询的是哪个可观察因素改变了动作排序，不是任意挑两个完全不同的任务。每个 Q 最多产生四个完整执行；已存在的精确结果直接复用，查询预算按新增实际执行扣减。

**这里特意不采用“翻转概率越高越好”。** 如果两侧优劣已经确定，再确认一次往往学不到东西。上述目标优先选择“是否翻转尚不确定，而且这个不确定会影响动作选择”的区域。分数是一个可被实验淘汰的具体假设，不是理论上最优的查询器。

全部方法使用同一小份初始成对数据；其执行成本计入各自预算。没有这些数据时，先按共同冻结顺序做少量均匀查询，不能让本方法额外看一圈答案。另固定一部分后续额度做均匀探索，防止预测器从未发现某一侧；比例和选点规则形成前固定，不能看测试结果再调。

**第四步：把真正的翻转证据编成选择程序。**

收集的对象是：

```text
条件 q1、行动前状态 s1：a 优于 b；两条完整执行证据
条件 q2、行动前状态 s2：b 优于 a；两条完整执行证据
q1 与 q2 哪些公开条件不同
```

在同一有限程序语言中拟合一个小型选择器：例如最多 3 个内部判断节点的决策树。阈值和分支由数据学习，不由开发者手填。

学习目标是减少“选错行动导致的损失”，而不只是复述故障标签。对一条有可比结果的样本：

\[
\ell(s)=\max\{V(s,a),V(s,b)\}-V(s,\pi(s)),
\]

其中 V 使用上面明确定义的完整服务 0/1 结果；两者同成败不产生动作偏好，错误或未知不进入损失。首轮学习器只在共同动作对中选择；多动作扩展可以之后再做。程序长度作为固定的小惩罚，避免为每个任务写一个分支。

**第五步：在新条件中执行这个选择器。**

最终 H 的变化落在 Select 中：相同候选、相同公开输入，选择次序发生改变。执行后，固定 Update 更新当前事实，再由新 Select 作下一次选择。不是只在离线表格里预测一个标签。

```python
# 以下是结构示意，阈值 theta 由训练结果学出，并非开发者答案。
def select(state, candidates):
    features = public_pre_action_features(state, candidates)
    action_class = learned_small_program(features)
    return choose_candidate_of_class(candidates, action_class)
```

首版先证明一个可执行选择函数能学好。无需生成任意 Python、不必修改底层模型、不必让 G 修改自己，也无需自动改变全部 Generate/Select/Update。

### 4.5 这篇究竟“新”在哪里

**不是**决策树新、主动学习新、反事实比较新，甚至“按情况使用补丁”也不新。

具体的新颖性候选是：**把设计方法的适用范围学习，转化成同一行动对的收益翻转实验选择；通过主动构造成对训练条件，学习会实际改变后续设计选择的小程序。**

它和普通不确定性采样的区别是：一个样本很难预测，不意味着它能改变选择；一种故障反复出现，也不意味着不同修复的优劣会变化。所提查询要优先区分两种相反的行动结论。

| 最近工作 | 已有内容 | 本方案要增加的东西 | 必须正面面对的比较 |
|---|---|---|---|
| GEPA | 从执行轨迹反思、更新提示并筛选 | 由成对完整执行主动定位行动优劣翻转，训练实际 Select 程序 | 同训练预算的反思更新，不能只比固定弱父 |
| ADAS / 程序搜索 | 自动生成、执行、选择 Agent 程序 | 改变学习数据的取得方式，明确学习“何时选哪一个动作” | 相同父、相同候选能力、相同完整执行费用 |
| EvoBelief | 试验环境规律并维护适用范围 | 学习对象是动作的相对收益边界与选择函数，而非环境转移规则 | 给普通方法相同完整结果，避免把额外证据量当算法优势 |
| C3 / BranPO | 共享上下文下的分支结果帮助贡献分配 | 从一次局部比较继续寻找跨条件的符号翻转，并把边界编成可执行选择器 | 普通分支采样或相同数据上的普通学习 |
| 主动学习 / 主动算法选择 | 挑信息量大的样本，学习预测或算法选择 | 专门挑同一行动对的相反收益条件，并控制两侧试验成本 | **同一个学习器配随机采样、普通不确定性采样**；这是最危险、最重要的对照 |

[GEPA](https://arxiv.org/abs/2507.19457)、[ADAS](https://arxiv.org/abs/2408.08435)。其他出处见第 2 节。

**我的新颖性判断：**它比“让模型写经验规则”具体得多，但和主动算法选择很接近。若普通主动学习在相同预算下已经一样好，我们就没有理由把这套机制宣传为新的方法突破。必须通过查询策略的直接对照来决定，而不是只展示学出来的规则很好看。

### 4.6 第二篇最先做的决定性实验

**只问：主动找优劣翻转，是否比普通采样更快学会在相反条件下作相反选择？**

先使用一个真正存在两侧效果的任务族。它可以是门体中的供能—交付时序，也可以是 LC 中启动—暗区服务取舍；由已有模型确认机制可表达，不根据所提方法成绩挑题。

首轮只做三个条件：

1. 相同学习器 + 随机选择训练条件。
2. 相同学习器 + 单点行动分歧采样：使用相同树集合，按 D(q)/执行成本选点。这是一个直接的主动学习强对照，不另换弱预测器。
3. 相同学习器 + 所提收益翻转成对采样。

三个条件使用相同父、候选生成器、特征、选择程序容量、训练执行预算和停止标准。固定父本身作为零训练参考，不必为此另起一套方法开发。

**关键测试不是“换个名字的新任务”：**保留训练中未用过的条件，包含翻转两侧与接近边界的位置；测试标签由独立完整执行获得。各方法测试时先作选择，不能查询测试反事实结果后再训练。

**核心读数：**

- 在相同完整执行预算下，学到的选择器在未见条件中的行动选择损失。
- 实际完整服务成功率，而非故障分类准确率。
- 相反条件中是否真的选择不同设计，是否付出了新的服务退化。
- 训练全部成本与之后节省的执行成本，分开报告。

**一个必要的反向检查：**用相同训练结果但打乱“条件—优劣”的对应关系再拟合选择器。它不需要新训练仿真。若仍有同等收益，方法可能只学到了一个全局较好动作，收益翻转这一核心解释不成立。

**推翻主张的结果：**

- 随机或普通不确定性采样同预算同样有效。
- 新代码主要改变日志/解释，实际选择没变。
- 学到的分支靠任务 ID 或测试后果作判断。
- 边界分类很好，但执行后完整服务没有收益。
- 总体结果只靠某一个全局更强动作，根本不需要学习条件。
- 翻转只存在于无法从公开输入区分的隐藏状态中，当前可观察特征无法支持选择。

最后一种结果应改变问题定义或说明可识别性限制，不能让学习器靠隐藏信息解决。

**首轮建议规模：**一个任务族、3 种查询策略，每种最多 32 次完整训练执行。其中共同的 4 个初始条件×2 个行动占 8 次；后续 24 次额度，可用于 6 组翻转查询（每组两条件×两行动），或其他策略的 12 个单点比较。共同初始结果物理上可复用，但在各方法的训练预算中都计入，不能成为免费额外数据。保留 8 个测试条件，两行动的完整结果用于事后独立计分，不交回训练。实际选择还必须通过新 Select 接入原执行入口读回；精确输入结果允许复用。先验证行为分歧与边界是否出现。看到了核心信号后，再做独立训练重复，并扩到第二类机制；首轮小样本不写普遍优势。

正式成稿前，补一次同预算 GEPA/普通反思对照即可，不必把所有 Agent 框架完整搬进仓库。若要作跨案例声明，应明确训练是否已经使用 LC：用过 LC 就叫跨条件适应；真正 DOOR→LC 零反馈迁移是另一项更强实验，不混在首版核心里。

### 4.7 为什么不立即继续“让模型自由改六个函数”

目前想证明的是“经验怎样改变选择”，不是“代码编辑接口足够自由”。首版固定 Generate/Update、只学习 Select，能够直接分清：

- 是训练实验选得好，还是只是给了更多结果。
- 是学到了选择边界，还是碰巧发现一个固定成功方案。
- 是选择真的改善了服务，还是文字解释更合理。

若这一步成立，再开放 Generate 的联合候选构造作为扩展。若不成立，开放更多代码位点只会增加不确定来源。**暂不把递归自改进写入这篇的中心主张。**

## 5. 两篇之间的关系：共享工程，分别证明

| 维度 | 论文一 | 论文二 |
|---|---|---|
| 被改变的对象 | 当前设备设计 | 以后选择设计动作的方法 |
| 核心计算 | 反演必要参数区间，解除两侧冲突 | 主动寻找行动收益翻转，拟合选择程序 |
| 必须出现的行为变化 | 从无效单参数搜索转到有效联合修改 | 同候选条件下，在不同工况选择不同动作 |
| 最关键对照 | 去掉区间机制的同一算法 + 普通优化器 | 同学习器、同预算，替换训练查询方式 |
| 可以没有的东西 | 自动学习、多个 LLM、G | 完整代码自演化、权重训练、G 的自改进 |
| 主要风险 | 约束很松或不成立，传统求解已经足够 | 普通主动学习已经足够，反转边界不可观察 |

第二篇可以使用第一篇产生的候选，但不能只在“第一篇算法独享”的条件下获胜。两篇共用完整仿真与服务判定，分别承担自己的核心证据。

**不预设两篇都必须按当前标题成功。** 第一篇若只是一般约束求解的直接应用，贡献应定位为具体系统设计方法；第二篇若没有超过普通主动学习，就不以“自改进”改名挽救。我们应尽早知道这一点。

## 6. S0 / A / B 分工：按两个研究问题推进，不按微工单推进

以下都是确认后的拟议任务，当前不派发。

| 阶段 | S0 总管 | A 工程 | B 方法与论文 | 交付与结束条件 |
|---|---|---|---|---|
| 1. 做出两个最小机制 | 固定任务、共同信息和有限资源；避免重新建平台 | 为论文一推导可用上下界与适用分支；为论文二提供合法成对工况和真实执行入口 | 实现区间反演到联合候选；实现翻转查询与小型 Select 学习器 | 两个能改变实际输入的最小算法，不以文档/接口准备作为结束 |

A 不替 B 写学到的阈值或给测试答案；B 不为了形成正结果改服务判据；S0 不再把每个参数和修订拆成“等下一轮审查”的独立终点。

## 7. 最小论文骨架：每篇围绕一张主图与一张主表

### 论文一

- **图 1：**容量下界与启动上界不相交；两个单项修改分别仍无解；联合修改使区间打开。图中的实际数据来自完整模型，解析示意另标。
- **方法：**如何由事件与方程反求范围、如何判断界失效、如何生成真实联合候选。
- **主表：**同预算完整服务成功与首次成功执行数，列核心机制去除和普通优化器。
- **必要反例：**界适用性改变后，算法不能继续错误排除。
- **结论边界：**哪些冲突类型有效，哪些问题仍要普通搜索。

### 论文二

- **图 1：**同一行动在两个条件下效果相反，主动查询找到分界，学出的代码改变了选择。
- **方法：**行动对执行、翻转查询目标、选择程序学习。
- **主图：**训练完整执行次数与未见条件上的行动选择损失/完整服务成功率。
- **主表：**随机、不确定性、翻转查询使用同一个学习器；补普通反思结果。
- **必要反例：**两侧条件不可观察或根本不存在真正的优劣翻转时，方法不应被包装成通用改进。

没有必要把“平台、审计、可靠采用、跨案例、深递归”都塞进贡献列表。它们可以作为实现条件、附录或后续工作。

## 8. 我的最终取舍

我建议先批准的不是“继续现有自改进流水线”，而是下面两个明确研究承诺：

1. **论文一必须交付一个会计算冲突、会反求联合设计的算法。** 如果只剩自然语言建议或人工成功方案，就没有完成核心方法。
2. **论文二必须交付一个由成对真实后果学出来、实际改变选择的函数。** 如果只是改代码、写经验、增加调用，而未学会相反条件下作相反选择，就没有完成核心方法。

第一篇更接近可立即落地的工程算法；第二篇的研究风险更高，尤其要击败普通主动学习。两篇都不需要先成为完美系统。

**当前建议优先顺序：先用论文一的窄机制检验反演是否有价值，同时准备论文二最小成对实验；核心信号成立再补有限覆盖。本文等待确认，暂停状态保持。**
