## 1. 最终目标与两篇论文

### 1.1 一套 BF 环境、三个研究对象

目标是使 BF Design 能够理解无电池设备的服务要求，联合设计机械、采能、电源、电路、程序和数据交付；失败后识别原因、选择行动、修订设计问题；再从这些经历中改进设计程序及产生这些改进的程序。

| 对象 | 实际改变什么 | 怎样评价 |
| --- | --- | --- |
| D：设备设计 | 几何、连接、器件、参数、程序、状态保存和通信策略 | 当前任务是否在声明模型、输入和初态下完成完整服务 |
| H：设计方法 | 候选生成、行动选择、证据更新、工作分组、重构与停止策略 | 从新任务入口重新设计，比较服务、错误采用与完整成本 |
| G：改进器 | 经历提取、缺陷归因、H 补丁生成、试验资源分配；以及自身的这些程序 | 相同父 H、历史与总预算下，能否产生更有效、可迁移的 H 后代 |

设备通过、H 改善、G 改善分别报告。一次设备修复不能同时充当三种结论。

### 1.2 论文一：BF 跨域设计与问题重构

**工作题目：** *Evidence-Driven Cross-Domain Design and Problem Reconfiguration for Battery-Free Systems*。

**主案例：门体动能事件记录器。**固定 H，研究任务内的设计 D 和问题表述 P 如何根据证据改变。主要科学问题是：在机械动作同时决定能量和事件的情况下，Agent 能否区分局部参数问题、跨域耦合问题和当前局部结构的不可行性，并选择值得执行的观察、修改或重构？

拟检验的贡献包括：BF 组件—系统—服务的可执行定义；基于竞争解释和预测分支的问题重构方法；相同权限与预算下的有效性、成本和失败边界。定义是基础，主要方法结论须来自实际行为与对照。

反证包括：强通用方法同样有效；收益来自额外信息/预算/权限；P 只改变文字；不必要重构增加成本；修好局部指标却破坏完整服务。局部必要界和候选集内分歧上界用于解释算法性质，不单独作为主要创新。

### 1.3 论文二：BF 方法学习与递归自改进

**工作题目：** *Learning to Improve the BF Designer: Experience-Driven Program Evolution and Recursive Self-Improvement*。标题中的正向结论强度在实验后确定。

**学习经历主要来自门体案例；主要迁移对象为光供能冷链状态标签；候选异机制迁移对象为漏水事件记录器。**研究 H 的程序变化能否超越相同历史和通用反思，并进一步研究 G 的自修改是否改善产生 H 后代的能力。

正式路径包括 F1 方法学习、F2 跨案例迁移、F3 改进器独立比较。F4 更深递归只在 F3 的收益与可靠性达到事前条件后启动。F3 不能长期留到“未来工作”；F4 不因版本代数增加而自动启动。

### 1.4 三个案例为什么互补

| 案例 ID | 能量—信息关系 | 主要责任 | 不应混同的结论 |
| --- | --- | --- | --- |
| DOOR：门体动能事件记录器 | 一次动作同时带来机械能和待报告事件；能量/事件的先后可能冲突 | 论文一旗舰、论文二主要经历源 | 有电压脉冲不等于有效能量足够；发包不等于网关收到 |

## 4. 案例一：门体动能事件记录器 DOOR

### 4.1 产品与服务

**用户描述：**“给这个柜门做一个不用电池的记录器，每次有效开门、关门都要能记录，并及时让网关收到。”

模拟一扇具有确定转轴、开合范围和安装区域的柜门。门体/门框之间的拨片、凸轮或其他合法机构驱动采能器；感知、事件保持和通信共用由该动作获得的能量。门磁/触点是可选感知实现，产品统一称 DOOR，避免把普通磁性传感器本身当作能源来源。

因果链：

> θ(t)、角速度与接触 → 机构位移/作用力 → 受载换能 → 整流与储能 → 电源门限/复位 → 事件识别与保持 → 发送/确认 → 独立网关记录。

### 4.2 服务合同：阶段一填写并冻结

| 字段 | 候选定义或数值 | 冻结前要解决的问题 |
| --- | --- | --- |
| 事件真值 | 开/关状态跨阈值并满足稳定时间；保留方向与序号 | 半开、反弹、轻触和重复动作如何定义，不能按设备输出倒推真值 |
| 动作域 | 慢/常速/快开合、不同有效行程、突发与长空闲 | 轨迹及其合法范围来自什么机构和模型；不同速度不是不同机制 |
| 任务窗口 | 可用 24 h 仿真场景作为候选 | 它是场景时长，不是保证 24 h 持续带电或实测寿命 |
| 接收截止 | 候选：有效事件发生后 2 s 内 | 起点为独立事件真值；允许网络条件和重试策略要明确 |
| 漏事件 | 候选：声明分布下不高于 1% | 需要独立样本/相关性和置信区间设计；少量无丢失不能证明此比例 |
| 附加阻力 | 候选：指定把手位置不高于 0.5 N | 位置、峰值/平均值、开关方向与安装传动比必须明确 |
| 初态 | 冷启动空储能；长空闲后按同一泄漏模型演化 | 弹簧、磁性机构和电荷的初始储能也须记账 |
| 数据 | 事件 ID、方向、顺序、有效接收与重复去重 | 设备没有供电时如何保持事件；时钟失效后的时间精度 |
| 空间 | 柜门/门框允许安装区、运动间隙、包络 | 由统一参数化几何表达，不能为通过静默增大机构 |
| 用户硬约束 | 无电池、合法动作、接收服务与机械边界 | 原任务冻结后保持；新规格另建版本 |

上述 24 h / 2 s / 1% / 0.5 N 来自新增材料中的候选规格。确认总计划不等于这些值已被证明可行；A/S0 应在正式比较前给出依据并冻结。执行后不得因为方法失败而回头改阈值。

### 4.3 工程变量、模型和交付

| 子系统 | 可编辑设计 | 输入/状态/输出 | A 的具体交付 |
| --- | --- | --- | --- |
| 机械与安装 | 触发位置、行程、传动比、弹簧预紧、间隙、外壳 | 门角/速度、接触状态、作用力、机构位移、机械储能 | 参数化几何、安装/运动视图、机械输入与反力计算 |
| 换能 | 有依据的器件/模型、受载工作点、机械或电磁参数 | 运动和负载共同决定电压、电流与反作用 | 至少一个可受载执行的源模型和适用域 |
| 电路 | 整流、储能、开关、启动/掉电门限、供电分支 | VIN/Vcap/Vout、启动、掉电、复位和损耗 | 可追查连接的原生或结构化源工程；同一参数生成求解输入 |
| 程序 | 去抖、事件保持、写入、队列、发送/重传/恢复 | OFF/BOOT/CAPTURE/SAVE/TX/WAIT/RECOVER 及实际负载 | 可执行状态/程序、事件时序、能耗与时间依据 |
| 接收 | 帧、序号、确认、重传和去重 | 网络可用性、发送记录、接收记录、事件匹配 | 独立接收器/评价器，不读取设备内部“成功”标志作真值 |

机械输入功、储能变化、损耗与电能输出应闭合。给定门角轨迹时，修改机构必须重新计算反力和受载输出；不得对所有机构沿用同一固定能量脉冲。若研究采用规定运动输入，应同时核对实现该输入所需的附加力，而非忽略驱动代价。

官方 ECO 200 可作为“线性运动驱动采能”的资料锚点；当前厂商页标注不建议新设计使用，因此本轮不把它锁定为采购或产品答案，只抽取有条件的模型依据。[EnOcean 官方资料入口](https://www.enocean.com/en/product/eco-200/)

### 4.4 三类核心机制与两类控制

- **M1 局部修复：**当前结构允许可行解，某参数或局部程序不合适。检验能否保持简单。
- **M2 联合修复：**动作能量、启动、突发负载、事件保持/发送共同影响结果。检验是否选对联合变量和观察。
- **M3 问题重构：**当前暂固定程序/结构的必要条件冲突。检验能否说明局部边界并在授权域内重构，而非无限调参。
- **M4 信息或模型不足：**相同表面失败对应不同原因；需要观察或精化后再判断。
- **M5 不应重构/应停止控制：**当前方案已足够、某规则不适用、关键要求缺失或证据不足。

M3 的必要界属于私有资格证据或公共可查询的推导入口，按协议提供给所有组；不能只把正确结论提示给所提方法。未知新任务允许有限探索，不要求开发者先解出每一道题。

### 4.5 关键独立评价

评价器逐事件核对：有效事件是否被采到、是否保持、是否在截止前接收、是否重复、方向/次序是否正确；同时核对机械力、空间、模型适用域和能源约束。一个完整 PASS 要满足所有适用条件。

没有持续供电的时钟就不能免费使用仿真绝对时间作为设备时间戳。可以设计相对计时、重启时间不确定区间或合法同步，但相应误差必须接受原服务评价。

## 5. 案例二：光供能冷链状态标签 LC-PV

### 5.1 产品与独立任务身份

**用户描述：**“给循环使用的冷链箱贴一个不用换电池的标签，记录温度；暗处和断网时别把历史弄丢，恢复后把有效记录交给网关。”

首版选定“**箱内空气中一个指定测点的温度**”作为建议研究对象；安装位置和传感器热路径进入模型。若实际任务改为箱外环境或表面测点，应另作任务定义，不能把其中任一种自动解释为内容物中心温度。

供能是光伏；信息是长期温度历史。两者不必同相。LC-PV 的新任务书引用可复用的 A/R 程序/模型部件，但不继承 A/R 的通过资格，也不覆盖旧失败。

### 5.2 服务状态与候选合同

| 状态 | 应评价的服务 | 明确不允许的推断 |
| --- | --- | --- |
| 有光、有网 | 按要求采样并及时接收，值与时间正确 | 一次广播完成等于接收完成 |
| 有能量、无网 | 继续取得真实样本并按规则存储 | 接收缺失等于没有异常 |
| 暗区、储能足够 | 完成合同规定的采样和保持 | 暗区长度仅由平均功率判断 |
| 能量不足 | 记录已知数据与可知的缺失区间 | 缺失区间标记可以替代严格连续采样要求 |
| 光/网恢复 | 按原顺序、去重、时限恢复历史与当前服务 | 只报最新值就等于历史完整 |

候选场景为一个 24 h 行程，含光照变化、遮挡、暗区、断联与恢复。若采用旧 A/R 风格的 30 min 冷启动、12 h 暗区、60 s 最大采样间隔、120 s 恢复、10 s 新样交付，应在 LC-PV 独立合同中明确验证其适用性；这些数值目前是**拟议继承条件**，不是新案例的既成要求或已证明可行域。温度误差与时间戳误差在传感/时钟模型选定后冻结。

严格连续服务与“允许缺失但如实报告”的宽松服务是两种不同任务，必须分别命名和评价；不能执行失败后切换。

### 5.3 设计范围与可执行模型

| 子系统 | 具体变量 | 必须进入仿真的关系 |
| --- | --- | --- |
| 光与安装 | PV 有效面积、窗口、朝向、遮挡、堆叠 | 光谱/辐照条件、温度与受载 I–V；遮挡不能只改标签而不改输入 |
| 几何与温度 | 传感位置、外壳/窗口、厚度、热接触 | 指定测点真值→热路径→传感响应→采样值 |
| 电源 | PV/PMIC、单/分离储能、门限、漏电、转换效率 | 冷启动、长暗区、恢复及活动峰值的动态供能 |
| 程序与数据 | 采样、事件判定、NVM、时间戳/计龄、FIFO、重传 | 真实采样时间、写入成本、复位丢失、队列顺序及去重 |
| 通信 | 天线位置的声明模型、遮挡、链路/网关条件 | 成功接收、延迟和重复；不承诺未建模的射频资格 |

照度 lux 不能在没有光谱或器件对应条件时直接当作电功率。温度“真值”、传感器响应和程序实际读到的值分开，避免设备获得理想即时温度。

### 5.4 迁移要检验什么

从 DOOR 形成的方法遇到 LC-PV 时，应能识别：供能不再只来自一次事件；保存一次事件的策略不足以保证长期记录；门体的立即发送规则不一定适合积累/暗区；没有必要的结构重构应避免；必要时需要新的温度/时间/队列观察。

首轮 F2 冻结 DOOR 形成的 H 后在 LC-PV 运行，**不使用 LC-PV 结果继续选 H 再称零反馈迁移**。允许的任务内观察和设计仍由当前 H 自主进行。若研究允许目标案例适应，另列 adaptation 条件和预算，再用另一份未接触任务评价。

## 6. 案例三：漏水事件记录器 LEAK

### 6.1 服务与资格边界

**用户描述：**“这个位置出现规定范围的漏水后，记录首次有效事件并在规定时间内报告；凝露或残留水不要反复误报。”

必须固定液体、温度、电导率、接触/流动条件、安装朝向、事件阈值、真值、允许延迟、误报/漏报、网络和初态。不能笼统假定“有水就有足够能量”。

### 6.2 首选研究切面与备选处理

先评估**有明确液滴运动条件的非电池式水滴采能＋事件记录**，作为窄范围候选；滴落、静态浸湿、凝露分开。已有水滴发电研究可以提供受载和动态过程的资料入口，但其特定装置及液滴条件不能直接证明任意小漏水可供能。[原始研究：水滴发电器](https://www.nature.com/articles/s41586-020-1985-6)

若选水激活电化学方案，必须说明电极/材料消耗与化学储能。水触发一个化学电源不等于从水中无限采能；若它属于任务禁止的电池式储能，则排除该方案，不能通过名称规避“无电池”。若改成独立 PV 供能的湿度传感器，它可以作控制题，但不能替代“事件改变可用能量”的异机制案例。

### 6.3 模型资格的具体工作

| 内容 | 需要建立的输入/关系 | 资格依据 |
| --- | --- | --- |
| 事件真值 | 液体何时在规定区域达到事件条件 | 独立液体轨迹/接触模型，真值不依赖设备电压阈值 |
| 感知 | 接触、导电、阈值、迟滞、污染/残留 | 来源明确的模型或明确标注的构造模型及适用域 |
| 能量 | 液滴运动/接触与受载电输出，初始表面电荷/预处理状态 | 输入功、初态、负载和输出能量闭合；峰值电压不代替可用能量 |
| 状态 | 初次/持续/重复湿润、干燥恢复、一次性或可复用 | 状态转移实际进入后续输出，不能每滴免费重置为最佳状态 |
| 服务 | 检测—启动—保持—报告、误报/漏报和截止 | 独立事件匹配与接收记录 |

材料及机理资料不足时，可保留“构造模型研究”或资格不足结论，不能进入物理机理已验证的泛化统计。全仿真资格依靠来源、方程、适用域及独立计算，不要求采购或实物校准。

### 6.4 对方法的判别力

LEAK 应检验 H 是否会区分“等待有助于积能”与“事件消失后不再有能量”、“增大储能有帮助”与“使启动更迟”、“阈值可优化”与“传感/采能模型本身未定”。任何一种动作都不预设为正确答案。

## 8. H：可编辑、可替换、可测试的设计方法

### 8.1 Generate

**输入：**Task、有效 Design/Problem、当前可见证据、可用动作、模型域和剩余预算。

**输出：**有限候选列表。每项包括 `target`、`problem_change`、`operation`、`expected_state_change`、`prediction_or_unknown`、`observation_branches`、`affected_constraints`、`cost_bound`、`validity_conditions`。

候选要包含可执行请求或修改，不能只有“进一步优化”。例如 DOOR 丢事件时可以生成读取发送期间电压、检查复位后的队列、改变发送或保持策略、观察慢速动作等候选；这些是允许提出的方向，不是每次都正确的答案。

**具体检查：**请求能否被消费者执行；同一候选是否只是重述已排除动作；是否包含有区分力的实验；低成本局部解仍可能成立时是否保留它；UNKNOWN 预测是否被诚实保留。

### 8.2 Select

**输入：**合法候选、当前约束、预测/不确定性、成本、失败风险与已有证据。

**输出：**`selected_id`、`selection_basis`、`expected_discrimination_or_gain`、`resource_reservation`。依据必须可追查，但事后解释不能替代实际选择记录。

首版可将确定性检查/排序与 LLM 解释性判断组合。硬权限和预算检查属于公共执行基础；诊断优先级、修复排序、是否重构属于可替换的 Select。

测试五项行为：优先取得会改变行动的信息；避免重复已排除的等价动作；计入实验成本与失败风险；局部修复足够时保持简单；局部必要条件冲突时不无限调同一参数族。未知全域不能因有限搜索失败被判不可行。

选择器消融可用同候选池的轮转、成本排序、通用 LLM 判断与完整选择规则，另做端到端比较。候选池来源和生成成本单独报告，不能将预先给定好候选的优势当作完整 Agent 能力。

### 8.3 Update

**输入：**原预测/适用域、实际消费输入、执行结果、误差说明、独立验收及原设计状态。

**输出：**更新后的 Design/Problem/解释集、受影响预测失效列表、下一步候选方向与依据；最终行动仍经下一轮 Generate/Select 或明确的协议规则产生。

| 情况 | 更新 | 不允许的更新 |
| --- | --- | --- |
| 观测与有依据预测相容 | 标为 SUPPORTED/CONSISTENT，并保留适用条件 | 宣称唯一原因已证明 |
| 观测排除预测 | 标为 REFUTED，失效相关预测/局部策略 | 自动排除完整合法设计域 |
| 多个解释仍相容 | UNRESOLVED，保留差异和下一项判别需要 | UNKNOWN 自动变 FAIL |
| 执行未完成/工具错误 | 保存执行错误与成本，保留工程判断待定 | 将网络/格式错误写成物理失败 |
| 模型域外或误差不足以判别 | DOMAIN_UNKNOWN 或相应未知状态 | 用最后一条曲线强行判 PASS |

### 8.4 六类可编辑位点

| 位点 | 实际实现 | 可观察的行为检查 | 负控制 |
| --- | --- | --- | --- |
| H-GEN | 候选生成提示/代码/配置 | 输出新的合法候选或不同候选集合 | 相同问题不强制扩大候选数 |
| H-RANK | 设计/行动排序 | 同候选池选项改变且依据可核对 | 成本相等、证据不足时不虚构优势 |
| H-EXP | 实验生成/选择 | 选择能改变判断的观察 | 不确定性不影响行动时不额外实验 |
| H-UPDATE | 证据和状态更新 | 复位、未完成、反驳被正确处理 | 工具错误不污染物理结论 |
| H-REFORM | 工作分组、活动变量、暂固定选择 | 实际编辑/求解范围改变 | 局部修复可行题不无故重构 |
| H-STOP | 适用域检查、停止和父方案保留 | 条件成立时停止或拒绝超范围使用 | 单点失败不推广为整族无解 |

六类位点可分属三函数，不要求再建立六个 Agent。首版允许受限策略/函数修改，不要求任意修改全部仓库代码。

### 8.5 最小执行协议

```text
candidates = H.generate(state, quota)
checked = common_contract_check(candidates)
decision = H.select(state, checked)
result = environment.execute(decision.actual_input)
state = H.update(state, decision, result, independent_assessment)
```

保留实际加载版本、分支是否触发、返回的操作和后果。文字引用 H、规则绑定、实际行为变化是不同证据。仅看到绑定不能证明认知因果；既未加载也未改变行为不能称有效方法补丁。

每个函数至少有一个应触发、一个不应触发、一个信息不足和一个工具错误输入。测试围绕行为语义，不为低影响格式变更编写镜像测试。

## 9. G：从经历生成 H，并改进自身

### 9.1 四个函数与返回对象

| 函数 | 输入 | 输出 | 必须实现的行为 |
| --- | --- | --- | --- |
| Extract | 允许的成功/失败历史、未选候选、预算 | 有限 decision incidents：时点、当时可见证据、动作、结果、学习价值 | 同时选择成功、正确停止和失败；不只学习扩大搜索 |
| Attribute | incident、父 H、真实候选/预测/工具轨迹 | 竞争性缺陷解释、支持/反驳、待判别内容、目标位点 | 区分 Generate/Select/Update 缺陷、执行器能力缺口、任务欠定义和工程不可行 |
| Propose | 归因结果、允许编辑位点、父程序 | 可执行补丁、适用/不适用条件、副作用、预期行为、反证和测试 | 不用任务 ID、隐藏答案或具体电容记忆替代一般条件 |
| Allocate | 补丁队列、局部/完整结果、剩余预算 | 下一次筛选/评价及停止/保留父版本决定 | 把所有提案、拒绝、失败、确认与自身形成计入预算 |

### 9.2 值得学习的经历

至少包含：预测与观察冲突；重复行动却未改变候选；已有足够事实仍做昂贵实验；局部空间受排除仍反复搜索；旧策略在新条件失效；简单修复成功；正确拒绝不可行候选；正确报告信息不足。

门体事件丢失不能直接归因为“没有持久化”。可能是未捕获、掉电、队列覆盖、错误去重、覆盖不足、时间定义错误、候选生成遗漏或工具未实现。G 应保留竞争归因，并用当时可见的原始记录支持它。

### 9.3 补丁合同与执行链

补丁最小字段：`parent_program`、`target_function/site`、`source_incidents`、`applicability`、`non_trigger_conditions`、`code_or_config_change`、`predicted_behavior_change`、`side_effects`、`behavior_tests`、`full_task_test_plan`、`falsifier`。

流程：形成 → 确认代码可加载 → 局部行为筛选 → 选择集完整重新设计 → 冻结候选 → 新任务确认 → 采用/拒绝。无通过补丁时保留父 H。

“启动与运行储能的必要条件冲突时检查授权范围内的结构动作”只是一个可供开发规格说明的规则例子；正式学习中应由 G 从经历提出，并用新任务和不应触发题检验，不能作为测试答案预置给 H4。

### 9.4 G 自修改与命名

**基线编号和演化代数分开：**H0–H4、G0–G2 是实验条件名称；版本代数写作 `H^(0)→H^(1)`、`G^(0)→G^(1)`，另有实际 artifact ID。不能把“G1 通用自修改基线”误读为“所提改进器的第一代”。

F3 中 G1/G2 的后继程序必须经过实际自修改过程生成。开发者设定可编辑接口、搜索算法与归因策略是研究方法的实现；开发者直接写好一个更强后继然后称自主 G 演进则不成立。

G 可修改自身四个函数；评价器、隐藏任务、费用事实、动作权限和采用规则不可修改。固定模型权重，研究的是程序层自改进，不宣称模型权重层面的自我训练。

## 10. 40 个具体用户式研究问题

这些是任务族设计清单，**不是 40 个已运行任务，也不是 40 次足以支持统计泛化的独立试验**。每行最终实例都需 Task、初态、合法动作和独立评价。右栏为研究者规划，不直接向参与 Agent 提供故障答案或私有参考。

入口标记：全＝从用户要求设计；变＝条件变化后重新设计；修＝同一失败状态出发。开发/选择/最终实例按机制与结构划分，不按相邻随机种子拆分。

### 10.1 DOOR：16 项

| ID | 用户式问题 | 入口 / 类型 | 合法空间与必须观察的后果 |

## 11. 两篇论文的基线体系

### 11.1 论文一：四组完整 Agent 与适用子域的传统方法

| 代号 | 条件 | 作用与实现要求 |
| --- | --- | --- |
| P1-B0 | 强通用工具 Agent | 完整共同资料、工具、合法动作和预算；允许自主联合设计，不能人为禁用结构动作 |
| P1-B1 | 固定顺序设计流程 | 按事前固定流程组织设计；Task 的合法动作仍相同，固定的是策略而非工具许可 |
| P1-B2 | 同表示、普通反馈循环 | 使用相同 Task/Problem/Decision 和事实，采用普通下一步决策；分离结构化信息与新方法 |
| P1-B3 | 完整 BF 问题重构 H | 竞争解释、预测、观察选择、P 重构与 Update 均实际执行 |
| P1-OPT | 传统搜索/优化 | 仅在固定拓扑、连续/离散参数且可表达的子任务上比较；计入采样/求解成本和前提 |

P1-OPT 不能被要求解决其接口不支持的任意程序生成，再被记为败给 Agent；也不能免费获得其它组没有的可行解。对相同参数子域使用相同目标、约束、仿真器与预算。

DPTM/可信状态是已有基础的可复现性问题，不另开长期框架工程。能实际绑定才按实现范围列出；只复用恢复/状态部件时准确命名，不用未运行的“DPTM 组”补充比较。

### 11.2 论文二 H 层：五组正式条件

| 条件 | 历史 | 修改 H | 方法与要排除的解释 |
| --- | --- | --- | --- |
| H0 固定设计方法 | 只有固定基线已有能力及当前任务事实 | 否 | 保留真实原能力；不给它人为删工具/恢复功能 |
| H1 H0＋相同历史 | 与自动方法相同的允许经历和检索入口 | 否 | 检查收益是否只是额外历史 |
| H2 通用反思/程序改进 | 与 H4 相同 | 是 | 相同六类位点、形成/筛选预算，采用强通用轨迹反思和程序修订 |
| H3 固定规则库 | 同一开发历史可达；额外规则仅由开发阶段整理 | 测试时否 | 检查自动学习是否超越冻结的专家规则；计入人工形成和维护成本 |
| H4 决策归因＋条件化更新 | 与 H1/H2/H3 相同的允许历史 | 是 | 检验 Extract/Attribute/Propose/Allocate 产生的可执行 H 是否有增量 |

H0 没有本轮额外历史是明确的信息控制。有关“学习机制”的主要归因来自 H4 对 H1/H2/H3，而非仅对 H0。五组在新设计任务上的任务、资料权限、基础模型、工具、动作、评价和求解预算相同；H2/H4 的形成/选择预算相同。

**H2 的落实方式：**主比较采用能够编辑同一 H 位点的通用程序改进器。GEPA 的轨迹反思与候选筛选可作公开参照，但原方法是提示优化机制；若只复现提示部分，需单列同样只允许提示修改的匹配比较，不能用一个权限更窄的 GEPA 提示组代表强程序改进基线。[GEPA 原论文](https://arxiv.org/abs/2507.19457)

H3 的规则和 H4 的条件均不得包含测试任务 ID、私有正确参数或测试答案。开发者向某组提供的额外知识和干预必须单列，不能混入自主增益。

### 11.3 论文二 G 层：三组正式条件

| 条件 | 自修改 | 具体比较 |
| --- | --- | --- |
| G0 固定改进器 | G 程序固定，可产生 H 后代 | 当前固定改进流程的质量、成本和退化基线 |
| G1 通用自修改改进器 | 可修改自身合法提示/代码/筛选与分配规则 | 使用强通用自修改程序，不要求 BF 决策级结构归因 |
| G2 所提改进器 | 可修改相同位点 | 从 H 后代和自身改进经历归因，改变提取、归因、补丁与预算策略 |

G1 的通用自修改可参考 STOP 中“改进程序应用于自身”的公开机制，接入 BF 时明确适配范围；不能直接引用原论文结果作为 BF 实验结果。[STOP 原论文](https://arxiv.org/abs/2310.02304)

三组共享初始 H、允许历史、合法 H 编辑范围、工具和外部后代选择/评价。G1/G2 自修改权限相同；G0 的“保持自身固定”是实验条件，不是削减其设计工具。

**预算同时给出两种视角：**主结果按共同总预算比较，包含 G 自身形成、所有 H 提案、筛选和确认；G0 不支出的自修改成本可保留给合法 H 改进。另可在冻结的 G 上用相同后代预算作机制比较，同时单列前期形成成本。后一结果不能单独声称总成本更优。

固定总预算下允许不同 G 分配不同的后代数，但设共同候选数上限。更多后代仅是过程指标，主结果仍是后代完整质量、错误采用、退化、迁移和成本效率。

## 12. 实验协议：E1–E4 与 F1–F4

### 12.1 论文一 E1：环境资格与全仿真闭环

- 输入：DOOR 参数化几何、动作轨迹、器件/源模型、程序和接收条件。
- 干预：至少各一次机构/负载、储能、程序、复位/事件保持变化，选择有判别力的输入，不作笛卡尔积扫描。
- 观测：机械功和反力、受载电能、启动/掉电、事件状态、实际接收与完整判据。
- 负控制：无有效门事件、能量不足、工具错误、包重复、状态易失；至少一个声明范围内可行的装置参考。
- 出口：程序和机构变化能够反向影响供电/源端；事件、能源和服务检查给出预期关系。一个固定电源轨迹播放器不满足资格。

参考只证明装置可工作和反例可判；不要求开发者预先解出每个新设计问题。

### 12.2 论文一 E2：完整问题重构比较

比较 P1-B0/B1/B2/B3，覆盖 M1/M2/M3，以及不应重构、信息不足的控制题。三种入口分别统计，固定失败快照不能替代从用户要求出发的完整能力。

主指标是完整服务、首次可行成本、错误采用、有效任务/总预算。过程解释包括无效等价修改、满足过的约束被破坏、局部/联合/结构动作的选择和所支持的停止范围。

另作“**重构后搜索范围匹配**”：P1-B3 释放 Task 已授权的变量后，匹配基线也获得该活动范围再比较。这样区分发现范围和在扩大范围内求解的贡献。

### 12.3 论文一 E3：机制消融

| 消融 | 替换方法 | 观察什么 |
| --- | --- | --- |
| 无事前预测 | 合法动作仍可执行，选择不使用预测分支 | 实验是否还能改变判断，成本是否增加 |
| 无竞争解释 | 普通单解释反馈 | 是否过早锁定原因，是否错过可区分观察 |
| 无主动观察选择 | 预定观察顺序或成本排序 | 同信息权限下的有效信息获取效率 |
| 无 P 重构 | 固定本轮活动范围/分组策略 | M3 与简单题之间的收益/代价差异 |
| 无更新后的主动复验策略 | H 不主动安排受影响路径复验 | 错误采用与失效转移；最终外部验收始终执行 |
| 通用 Select / Update | 同候选或同状态输入下替换函数 | 哪一函数真正改变行为，是否保持完整服务 |

**“去除独立验证”只能指 Agent 内部是否主动请求某次复验，不能撤掉所有组共同的最终独立评价器。**否则比较的是评价宽松程度。

不默认把所有消融乘全部任务。事前选能区分对应机制的任务族；选择规则固定，失败任务不能事后从表中移走。

### 12.4 论文一 E4：独立仿真工程干预

将新材料的物理执行要求改为：按事前规则选代表性失败/修复候选，进行一项独立解析、数值或模型交叉核对。可选机械功—电能闭合、事件/队列重建、必要界、时间步敏感性、局部更精细模型。

保存原设计/新设计、事前预测、实际输入、运行与接收后果、独立差异、模型适用域和人工介入。额外精细模型若改变世界版本，各方法在对应比较中使用同一版本；不能只给所提方法更准确模型，再把结果视为原条件下的优势。

### 12.5 论文二 F1：H 的行为改进

从 DOOR 开发经历自动形成 H2/H4 候选；冻结 H3 规则库；对 H0–H4 在新 DOOR 任务完整求解。新任务同时包含应触发和不应触发条件。

必须报告：补丁归因是否受证据支持、是否实际加载/触发、改变哪个候选或判断、完整服务、第一次可行成本、错误修改/采用、无效实验、误触发、全部形成/求解/人工成本。

形成失败不能由开发者替写一个通过的 H。可保留父版本并按事前采用规则评价，原形成失败和成本照留；不能把父版本表现记为子方法已被成功生成。

### 12.6 论文二 F2：跨案例迁移

固定 DOOR 学到的 H，在 LC-PV 的新条件上从入口设计。与 DOOR 相比真正改变供能到达、服务时长、状态保持、温度响应和恢复语义。正式 LC-PV 输入/真值/结果不能参与 H 的形成和选择。

LEAK 资格成立后，以同样规则加入独立异机制任务。未建立资格不进入主通过率分母，明确列为未执行范围；不能事后因其结果差而改为“探索性”。资格标准和纳入规则必须在方法结果前确定。

区分三种报告：同机理新工况、同机理新结构、不同能源/信息关系的新案例。任何一层都不等于任意 BF 系统泛化。

### 12.7 论文二 F3：G 的独立比较

建议有限先导包含 **3 个独立形成块 × G0/G1/G2**。每个形成块内共享父 H、历史和总预算；G1/G2 分别进行真实独立自修改。固定的 G0 只作匹配重复，不虚称 3 次自进化。

每个条件最多产生 2 个 H 后代，合计最多 18 个新后代候选；父 H 始终可保留。形成失败、拒绝、未提交和无效后代都计入分母与成本。后代在选择集上由共同规则选出，再在未参与选择的新任务上评价。

该数字是机制先导上限，不是已确定的正式统计样本量。正式独立形成数和重复数由先导变异、主要差异和总预算在正式结果前固定。不能将同一 G 的多个后代当独立 G，也不能反复看测试后挑“最好的一代”。

主要结果：后代服务质量、有效方法改进率、单位有效补丁成本、退化率、新任务迁移、G 自身形成和筛选成本。诊断结果：哪一函数、哪一种预算分配或归因变化带来后果。

### 12.8 论文二 F4：递归深度，条件启动

只有 F3 在独立形成块上达到事前定义的服务改善或可靠性保持下的成本改善条件，才启动下一深度；简单的单次正例或后代数量上升不够。

进一步让冻结的父/后继改进器从匹配起点产生新的改进器后代，再通过这些后代生成 H、选择 H、评价新任务结果。每层都记录自身形成和淘汰成本。首个追加包最多一层，不预排无限谱系。

若 F3 无稳定收益，保留 G0 或相应父版本，完成 F3 的负结果与机制解释，F4 标为条件未满足；这不抹去已完成的 F1/F2，也不能写成更深 RSI 已证明。

### 13.4 指标定义

- **完整服务通过：**所有适用判据满足；同时给逐约束结果，不能把局部通过数当主成功率。
- **首次可行成本：**达到首个独立 PASS 的累计成本；没有 PASS 的任务作为未达事件/预算终止报告，不能只平均成功样本。
- **错误采用：**方法采用或自报成功，但独立完整判据未满足；与“提出过失败候选”分开。
- **错误修改：**实际变化破坏此前满足的约束或被独立证据否定；不把合理但失败的探索一概视为错误。
- **无效实验：**按事前规则界定：输入等价的无必要重复、已排除且条件未变的动作、不能影响当前决定的观察；未知结果不自动算无效。
- **触发准确性：**在应/不应触发的独立条件中记录实际行为；缺少参考时记未能评价。
- **成本：**模型请求/token、仿真/工具、计算时间、墙钟、形成/选择/确认、失败/截断、人工分钟分别记录。费率估算与账单区分。

缓存命中回读注明 reused 和来源；原始生成成本只记一次。计划内随机重复使用预先定义的独立随机输入/种子，不能被确定性缓存替代；不因重复运行次数多就增加任务泛化单位。

### 13.5 遇到意外如何决定下一步

| 现象 | 决策 |
| --- | --- |
| 格式或工具错误 | 只修共同接口直接路径；保留原尝试，科学结果记未执行/未知，不用事故解释方法失败 |
| 没有可行候选 | 检查生成缺口、信息、授权动作和局部界；预算内有限探索，不先要求开发者解题 |
| 局部界为空 | 标注假设及子域，合法重构或有根据地停止；不自动扩大到全任务无解 |
| 局部修复但整机失败 | 保留进展，定位失效转移；不用换指标掩盖原失败 |
| 强基线持平/更好 | 按计划解释成本和边界，收束主张；不追加无限样本追正结果 |
| H/G 改文件但没改行为 | 查加载、触发和真实输入，只补直接消费缺口；不以绑定计数代替效果 |
| LEAK 无合格模型 | 保留机制分析和具体缺口；LC-PV/F1/F3 独立继续，正式泛化范围据实限定 |
| 需要改变用户服务或重要硬边界 | 形成具体选择交用户；不依赖该选择的研究继续 |
