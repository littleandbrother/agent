## 1. 本轮只解决一个问题

为什么 E3LC 的 BF 在一个上下文中以一次评价成功，另一上下文中却先后违反装配包络和凸轮压力角，三次才成功？哪些公开工程关系可以让行为更稳定，并避免为了局部修复损害完整服务？

**假设：**把供能/启动/储能与机构适用条件落实成有条件的候选生成、选择和证据更新，比只要求模型列预测/分支更能减少可避免的无效设计尝试；局部信息足够时也能保持直接修复。

**可证伪条件：**代码只增加字段/解释，实际动作不变；动作虽改变但不能由公开事实支持；只靠新增独占事实或更弱基线改善；或在有限闭环比较中未减少无效执行/错误采用且增加成本。这些均按实际范围报告，不靠追加任务追求正结果。

本轮实现的是开发者依据公开经历改进的固定 H，不是自动学到的 H，不是 G/RSI。有限比较是机制开发证据，不是统计优势或未见迁移。

## 3. 分工、顺序与交付

### A：工程关系及独立后果

只围绕 r1 第一次决策、r2 第一次决策及紧接着的两次几何修订分析。不为本阶段重求解。

交付 `stage3-decision/a/decision-relations.md` 与紧凑可读的关系数据：

1. 同一初态下两轮分别根据哪些事实选择哪些行动，哪些是推断而不是已测事实。
2. 增大电容、改变门限、改变机械行程/凸轮几何如何分别影响启动、后续活动及模型适用域；注明依据、条件和未知量。动态源反馈存在时不能默认“采集电荷不变”。
3. 哪些几何/能量约束能由已有公开模型和数值便宜计算，哪些必须读取已保存事件细节，哪些确需新联合仿真。工具只返回关系值/条件/事实，不替 Agent 提供下一行动答案。
4. r1 的有效判断是否依赖偶然余量；r2 的错误是否能在当时信息下避免；不把“多改参数”本身当错误。
5. 一个局部修复控制，说明何时现有信息足够、不应强制观察或扩大范围。

若需纯事实计算助手，最小实现且所有条件共同可达；能复用现有函数就不新增。不得改模型、任务、服务或判据来证明方法有效。

### B：真正实现 Generate / Select / Update

从 A 已可用的公开关系开始实现，与 A 后续分析并行，不等待长报告。沿既有 H 加载/调用入口建立一个可识别版本，不重写平台，不复制整套周期。

- **Generate：**依据当前失败和仍成立的解释，构造有限可执行的局部修复、必要范围修改或判别性观察。每项的预测必须对应具体 BF 关系与适用条件，不能只用“可能PASS”或“model_valid=true”代替全部受影响关系。允许UNKNOWN；不要求每次列齐所有动作类型。
- **Select：**先利用已有证据；已有便宜事实能排除的候选不因模型文字自信而优先执行。已知信息足够就直接修复；解释会导致不同设计决定时才获取能区分它们的信息。扩大范围有明确理由；少改参数不是绝对优先规则，不能禁止合理联合修改。只有一个有效候选时可直接选择，不为形式完整增加一次LLM排序。
- **Update：**区分预测支持、预测反驳、结果不区分、执行未完成；将结论绑定当前适用范围，并让相关假设/候选/停止理由的改变被下一轮实际消费。域无效只能更新相应域判断，不能冒充物理FAIL；一个点失败不能排除整个家族；多项同时修改不能自动认定唯一原因。

输出 `stage3-decision/b/mechanism.md`、实际版本/源码、针对直接行为的测试及 `behavior-delta.json`。每个有效行为变化必须能指出：公开状态→旧选择→新选择→被消费的工程关系→受影响服务。只换解释、JSON、标签或排序分数不算行动变化；新动作、观察、范围或有证据的停止改变才算。

不得按任务ID、候选ID或事后成功参数硬编码选择。不要求一定改变原本正确的 r1 选择；应优先解释并避免 r2 可避免的错误，同时保持局部修复控制。当前开发输入最多3个状态：r1/r2共同初态、r2第一次失败后状态、一个局部修复控制。使用保存候选池调用真实实现，允许基于公开条件的生成逻辑产生新候选。

这里的离线行为回读仅证明程序怎样选择，不证明新设计会通过，不把 fixture 当自主模型或科学结果。如果使用新LLM请求才能决定行为，应计入下述共同6次求解上限，不另开付费格式/行为探针；优先用实际可调用的确定性方法部分完成离线比较。
