## 为什么固定空间无法兼顾冷启动和暗区

S0 的外部必要界检查使用独立 Decimal 计算，没有调用公开工具中的界公式或产生新的仿真。它绑定冻结合同、可执行世界和自身源码，且故意忽略启动、采样、写入、发送等额外能耗。

| 必要条件 | 乐观界 |
| --- | --- |
| 1,800 秒冷启动可积能量 | 至多 0.127800 J |
| 冷启动允许电容 | 至多 0.052809917355 F |
| 暗区睡眠能量下界 | 至少 0.215390 J，已在两端各让出完整采样间隔和步长 |
| 暗区必需电容 | 至少 0.071203305785 F |

两个电容区间不相交。固定语法没有主动关机钩子；ESR 与稳压余量排除了合法关断阈值以上靠发送压降反复复位来规避睡眠能耗的情况。零输入暗区一旦降到关断阈值以下，也无法再充到更高的启动阈值。因此这构成**当前理想计算模型及冻结设计空间内的 no-go**，不构成真实硬件的普遍不可能性证明。

若要修订产品约束，下列只是必要的乐观门槛，仍须新设计与独立验证：

| 可交给用户选择的方向 | 必要门槛或影响 |
| --- | --- |
| 保留现有合同作为失败/无解参考 | 无需修改服务或物理；后续研究沿用已资格化的独立条件 |
| 放宽冷启动期限 | 至少 2,426.93 秒，约 40.45 分钟 |
| 缩短零输入暗区服务 | 至多 32,072 秒，约 8.91 小时 |
| 修改供电或器件资源 | 例如睡眠功耗需降至至多 3.7084 µW；当前为 5 µW，实际还须覆盖其他活动能耗 |

FIFO 与“优先新记录”的选择也须明确。上述取舍没有执行，不能当作已通过的新产品要求。凭证：`external-fixed-space-bound.json`；检查源码：`independent_feasibility.py`。
